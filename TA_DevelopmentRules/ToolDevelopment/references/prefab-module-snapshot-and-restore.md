# Prefab 模块快照、映射与事务恢复参考

> 类型：REFERENCE；适用范围：Unity Editor 中需要把旧 Prefab 的人工配置迁移到重新生成结果或兼容 Prefab 的工具；使用前提：必须按目标 Unity 版本、Prefab 结构、序列化类型、第三方插件和资产生成链重新验证。
>
> 关联规则：`TOOL-CMP-01`、`TOOL-ARC-01`、`TOOL-ARC-02`、`TOOL-UI-01`、`TOOL-UI-02`、`TOOL-OPS-01`、`TOOL-OPS-02`、`TOOL-ORG-01`、`TOOL-VAL-01`、`TOOL-VAL-02`。当前模块入口见 [工具开发规则](../README_Tech_TAToolDevelopmentRules.md)。

## 1. 适用场景

本参考适用于以下问题：

- FBX、模板或生成规则更新后，需要重新生成角色、场景物件或特效 Prefab，但旧 Prefab 上已有人工配置。
- 需要迁移普通 Unity 组件、项目脚本、第三方组件、字段、Prefab 内引用和外部资源引用。
- 骨骼下存在不属于源 FBX 的空挂点、嵌套 Prefab、Added GameObject 或完整自定义 GameObject 子树。
- 旧、新 Prefab 层级大体相似，但局部路径变化，需要显式映射而不能按名称猜测。
- 第三方组件的序列化参数可以迁移，但缓存、拓扑或预构建数据必须在目标 Prefab 上重新生成。
- 正式恢复不可依赖 Unity Undo，需要 Dry Run、确认、失败不保存和版本控制回退。

本参考不等于任意 Prefab 的自动三方合并器，也不保证所有 `Component` 都能跨对象、跨项目或跨插件版本迁移。以下需求应单独设计：

- 完全不同骨架之间的语义 Retargeting。
- 跨项目且未保留 `.meta` GUID 的资源迁移。
- Player 运行时热更新、网络同步或存档反序列化。
- 对嵌套 Prefab 的全部 Added/Removed Override 做逐条重放。
- 非 Unity 序列化状态、运行时缓存、原生插件句柄和外部文件状态的迁移。

## 2. 前提与依赖

### 2.1 先区分“生成器保留”与“快照迁移”

Prefab 生成器常见两类更新策略：

| 策略 | 适合内容 | 主要风险 |
| --- | --- | --- |
| 按模板/模型全量刷新 | FBX 层级、Mesh、Renderer、模板节点等生成器拥有的内容 | 人工添加的组件、挂点和第三方配置可能被删除 |
| 保留已有、补充缺失 | 衍生 Prefab、追加模板、简单增量维护 | 旧错误配置也可能继续保留；不能保证所有源内容刷新 |

生成器中的“保留已有”通常是局部规则，不应被理解为完整保留任意组件和引用。模块快照的职责是：**在破坏性重新生成之前显式保存生成器不拥有的配置，在新结果上经过分析和映射后恢复。**

若生成器本身已有稳定的显式字段或模板配置，应优先把长期固定内容纳入生成配置；快照更适合角色特有、插件生成、人工调节或难以模板化的模块。不要用快照长期掩盖生成规则缺失。

### 2.2 用 State / Input / Transition / Effect / View 拆开流程

推荐把工具状态显式化：

| 层 | 内容 | 不应承担 |
| --- | --- | --- |
| State | 快照、模块选择、映射、分析计划、预计差异、执行状态、恢复后结果 | 直接绘制或写资产 |
| Input | 源 Prefab、目标 Prefab、模块选择、路径映射、依赖策略 | 隐式执行恢复 |
| Transition | 捕获、分析、预览、应用、第三方重建、提交、取消 | 越过前置校验 |
| Effect | `LoadPrefabContents`、创建节点/组件、写字段、重绑引用、保存、刷新 | 在 `OnGUI` 中散落执行 |
| View | 快照树、双栏映射树、模块开关、状态、错误和确认 | 成为数据事实来源 |

一个可回放的最小状态机可包含：

`Idle → Captured → Analyzing → NeedsMapping/Ready → Applying → Rebuilding → Completed/Failed`

所有按钮和自动刷新都应复用同一 Transition，不能让“高级列表选择”“树上勾选”和“重新分析”走三套逻辑。

### 2.3 冻结三类身份

快照迁移至少需要三种稳定身份：

1. **节点身份**：相对 Prefab 根的稳定路径。仅用叶节点名称会在重名骨骼、左右部位或重复挂点中产生歧义。
2. **组件身份**：节点身份 + `AssemblyQualifiedName` + 同类型组件序号。仅用类型会覆盖同一对象上的多个同类型组件。
3. **资源身份**：Asset GUID + local fileID。仅用资源名称或路径不能稳定定位 Sub-Asset。

一种可行的稳定路径格式是：

```text
Uri.EscapeDataString(nodeName)[sameNameOrdinal]/Child[0]
```

根节点用空字符串表示。路径段必须转义 `/`、`[`、`]` 等名称字符；同名序号必须按兄弟顺序计算。路径不是永久语义 ID：层级重排、重命名或模型结构变化后仍需要显式映射。

### 2.4 快照必须有 Schema 和兼容边界

持久快照是长期资产，不是临时 DTO。至少记录：

- `SchemaVersion` 与最小支持版本。
- 源 Prefab 引用、GUID、路径和层级签名。
- 节点层级、模块记录、依赖和对象引用。
- 映射方案与目标 Prefab 身份。

新增字段时优先保持旧 Schema 可读；语义不兼容时显式拒绝或迁移。**代码升级不会自动让旧快照拥有过去未捕获的数据。** 新增可迁移类型或修复捕获边界后，必须提示用户重新捕获。

## 3. 功能实现方式

### 3.1 捕获时加载 Prefab 内容，不直接依赖资产预览对象

推荐流程：

1. 通过 `AssetDatabase.GetAssetPath()` 验证源对象是 Project 中的 `.prefab`。
2. 使用 `PrefabUtility.LoadPrefabContents()` 获得可遍历的隔离内容。
3. 采集层级、组件、字段、引用和来源归属。
4. 在 `finally` 中调用 `PrefabUtility.UnloadPrefabContents()`。
5. 捕获结果先在内存中完整建立，再写入快照资产并 `SetDirty/SaveAssets`。

不要直接遍历 Project 中的 Prefab Asset 引用后假定实例状态、嵌套 Prefab Override 和组件来源都能被可靠识别。加载内容后的对象只在当前捕获会话有效，不能把 InstanceID 或场景对象引用写进快照。

### 3.2 用“来源归属”而不是类型白名单区分可迁移组件

类型白名单会持续漏掉 Animator、Renderer、约束、VFX、项目脚本或新插件组件；全量捕获又会把 FBX 原生 `MeshFilter/Renderer` 等生成器内容重复带回。更稳妥的方式是判断组件归属：

1. 保持 Model Prefab 连接时，用 `PrefabUtility.GetCorrespondingObjectFromSource()`、`IsPartOfModelPrefab()` 和 `IsAddedComponentOverride()` 区分源组件与 Added Component。
2. 模型层级已展开、来源标记丢失时，从候选源模型建立“稳定路径 + 类型 + 同类型序号”签名，再与 Prefab 组件比对。
3. 同一骨骼后来新增的组件不应因节点属于 FBX 就被整体排除。
4. 对生成器可能删除、但业务明确需要迁移的组件建立**有证据的例外**，并添加回归测试。

来源判断必须保守。无法确定时可进入候选/Warning，而不是静默归为源组件或直接覆盖目标。

### 3.3 普通字段与对象引用分两条通道保存

`EditorJsonUtility.ToJson()` / `FromJsonOverwrite()` 适合复制 Unity 可序列化普通字段，但不能把其中的对象 InstanceID 当作可移植引用。推荐：

1. JSON 保存普通序列化字段。
2. 用 `SerializedObject` 遍历 `SerializedPropertyType.ObjectReference`。
3. 跳过 `m_Script`、`m_GameObject`、Prefab Source 等引擎所有权字段。
4. 将引用分类保存：
   - `Null`：明确空引用。
   - `PrefabObject`：稳定节点路径、对象类型、组件类型和同类型序号。
   - `Asset`：GUID + local fileID。
   - `Unsupported`：无法持久化的引用，分析时提示或阻断。
5. 恢复 JSON 后，再以 `SerializedObject.FindProperty(propertyPath)` 覆盖引用。

外部资源 GUID 只在同一 AssetDatabase 或迁移时保留 `.meta` 的前提下稳定；跨项目复制必须重新映射。字段改名、插件版本变化或属性类型变化时，`FindProperty` 失败应形成可定位错误，不能静默忽略。

### 3.4 组件依赖必须显式展开

组件 A 引用组件 B 时，如果 B 也来自快照，A 的模块应记录对 B 的依赖。分析阶段可提供两种契约：

- 自动包含依赖：直接选择 A 时，将 B 加入有效恢复集合。
- 严格手动：未选 B 且目标没有 B 时形成 Blocking issue。

依赖图应按模块 ID 去重，允许跨节点和层级对象内部引用。不要依赖捕获顺序或 UI 列表顺序隐式解决依赖。

### 3.5 把完整 GameObject 子树作为原子模块

骨骼下新增的空挂点、嵌套 Prefab 和完整 GameObject 子树不适合拆成多个独立字段模块。原子层级对象模块至少保存：

- 根路径、父路径和相对稳定路径。
- 节点名称、局部 Transform、Active、Layer、Tag、Static Flags、SiblingIndex。
- `RectTransform` 专用数据。
- 所有非 Transform 组件、字段和引用。
- 嵌套 Prefab 的源 GUID、连接和实例状态。

选择父节点后应自动归一化掉被覆盖的子节点选择，防止恢复两次。目标同路径已有模块根时，必须把“整体替换该子树”作为所有权边界在 Dry Run 中显示；不能把映射到的父骨骼一起替换。

源 FBX/Prefab 固有节点应灰显不可选，但扫描仍需进入其子层级，以发现骨骼下新增内容。嵌套 Prefab 的内部固有节点不应再次作为独立模块根；以实例根作为最小选择单元更容易保持连接和引用一致性。

### 3.6 路径映射只处理“源节点对应哪个目标节点”

映射层不应同时编辑字段、组件或子树内部结构。推荐解析顺序：

1. 用户显式映射。
2. 计划中确定会创建的路径。
3. 完全相同的稳定路径。
4. 唯一同名候选只作为建议，不自动采用。

映射方案可以作为快照 Sub-Asset 按目标 Prefab 保存，便于一个快照复用到多个目标；也可以单独保存。无论存储形式如何，都应同时校验快照身份和目标身份，避免误用旧映射。

双栏树比两个独立树更适合映射：同一行共享展开、滚动和状态，显示 `Exact/Manual/Missing/WillCreate/WillReplace/TargetOnly`。搜索和“只显示差异”必须保留命中节点的父链，不能让结果失去层级上下文。

### 3.7 使用 Analyze → Preview → Apply → Commit 事务

推荐把正式恢复分为四层：

#### Analyze

- 只读取目标 Prefab，解析路径、组件、依赖、冲突和第三方约束。
- 生成不可变或可审计的恢复计划。
- 缺失路径、歧义候选、丢失资源、目标组件缺失、重叠子树等形成 Blocking/Warning。

#### Preview

- 在未保存的 `LoadPrefabContents()` 副本上执行同一恢复算法。
- 捕获恢复前后差异。
- 不启动会产生持久缓存的第三方构建，不保存 Prefab。
- 完成后卸载副本；目标资产 GUID、内容和时间戳不应变化。

#### Apply

执行顺序应支持跨模块引用：

1. 创建或替换所有层级对象。
2. 创建所有组件。
3. 覆盖全部 JSON 字段。
4. 统一重绑所有对象引用。
5. 校验并重建第三方缓存/拓扑数据。
6. 再次捕获或校验目标状态。

#### Commit

- 所有阻断校验和第三方重建成功后才 `SaveAsPrefabAsset()`。
- 保存使用原路径，不主动删除 `.prefab` 或 `.meta`。
- 保存后重新加载磁盘资产，采集实际层级和实际差异。
- 失败、取消、超时或窗口关闭时只卸载内存副本，不提交半成品。

正式 Prefab 保存通常没有可依赖的 Unity Undo。确认框、版本控制和明确的“未保存取消”边界是事务的一部分，不是 UI 装饰。

### 3.8 第三方组件迁移参数，不迁移失效缓存

布料、物理、烘焙、导航或特效插件常同时包含：

- 可移植配置：类型、参数、骨骼/Renderer/Collider 引用。
- 派生缓存：初始化数据、拓扑、预构建资产、运行时索引。

恢复时应保存前者，并在目标 Prefab 上按插件官方 Editor API 重建后者。可采用拓扑签名提前阻断明显不兼容：

- 骨骼类：根骨骼相对子树、childCount、碰撞骨骼结构。
- Mesh 类：Renderer 顺序、Mesh 顶点数、SubMesh 数。

共享 PreBuild 资产或无法安全重建的数据应在 Analyze 阶段阻断，不要自动覆盖。差异报告应忽略确定属于重建产物的字段，避免把缓存噪声当成配置差异。

### 3.9 组件详情用临时对象重建，不读取当前 Prefab

如果用户点击快照组件 Icon，需要看到的是**快照时的组件**，而不是当前已经重新生成的 Prefab 组件。可采用：

1. 解析快照中的组件类型；找不到类型时按脚本 GUID 回退。
2. 创建 inactive、`HideAndDontSave` 的临时 GameObject。
3. 添加组件并 `FromJsonOverwrite()`。
4. 外部资源引用加载真实资产；Prefab 内引用创建仅用于显示的临时占位对象/组件。
5. 使用 `Editor.CreateEditor()` 和 `InspectorTitlebar` 绘制真实 Inspector。
6. Inspector 整体只读；窗口关闭、Domain Reload 或异常时销毁 Editor 和临时对象。
7. 类型缺失、组件禁止创建或自定义 Inspector 不支持临时对象时回退显示原始序列化信息。

自定义 Inspector 可能调用 `GUIUtility.ExitGUI()`；不得把 `ExitGUIException` 当普通绘制错误吞掉。临时对象必须 inactive，避免无必要的 `OnEnable` 副作用；即便如此，带 `ExecuteAlways` 或原生资源要求的组件仍可能不适合预览，应允许安全回退。

### 3.10 让恢复模块与层级树融合，而不是维护重复页面

当模块都挂在 GameObject 上时，层级树是更自然的主工作区：

- 行内显示对象类型 Icon、组件 Icon、模块开关和映射状态。
- 点击组件 Icon 查看详情；点击模块开关控制原子模块。
- 按类型批量选择降为默认折叠的高级视图。
- 层级映射区默认展开，不应依赖先打开高级列表才生成。
- 快照/目标/模块齐备时，可排队生成首次预览；失败后不要无限自动重试。
- 自动高度和手动高度使用独立序列化状态，适应不同窗口大小。

颜色要表达行动优先级，而不是只表达数据相等：没有恢复内容的完全匹配节点可以灰显；**挂有已选恢复组件的匹配 GameObject 应保持正常亮度**，否则用户会误以为它不参与恢复。状态文字仍可显示“匹配”。

恢复成功后，同一双栏树右侧应切换到重新加载后的实际 Prefab 层级。只要用户修改目标、模块或映射，就清空“恢复后结果”缓存并回到新预览，避免把旧结果伪装成当前状态。

## 4. 常见问题、根因与解决方式

| 现象 | 常见根因 | 解决方式 |
| --- | --- | --- |
| 重新生成后脚本、Collider 或 Animator 丢失 | 全量刷新只重建生成器拥有内容，没有配置迁移层 | 生成前捕获快照；生成后 Analyze/Preview/Apply；长期固定内容回归生成配置 |
| “更新已有 Prefab”看似保留，但换骨架后引用错误 | 只保留旧对象，没有按新层级重新绑定 | 把路径与引用映射纳入恢复计划，不以对象仍存在判断成功 |
| JSON 恢复后引用为空或指向旧对象 | JSON 中的 InstanceID/fileID 不能跨 Prefab 内容会话复用 | 普通字段与对象引用分离保存，恢复第二阶段统一重绑 |
| 同名骨骼映射到错误节点 | 只按叶节点名称查找 | 使用转义稳定路径和同名兄弟序号；歧义候选必须人工映射 |
| 同一 GameObject 上第二个同类型组件被覆盖 | 组件身份只有类型 | 加入同类型序号，并在引用记录中使用同一身份 |
| Sub-Asset 引用恢复成主资源或错误子资源 | 只保存 GUID/路径，没有 local fileID | 保存 GUID + local fileID，并遍历路径下全部资产精确匹配 |
| 用户新增脚本被当作 FBX 原生组件排除 | 只依据节点属于模型，或展开后来源标记丢失 | 组件级归属判断；使用 Added Component 和源模型组件签名 |
| 应迁移的内置组件仍被排除 | 来源识别把“业务配置组件”归入模型 | 建立有证据的类型例外并加捕获/恢复测试；提示旧快照重新捕获 |
| 空挂点、嵌套 Prefab 或完整子树没有保存 | 工具只捕获组件，不捕获 GameObject 所有权 | 增加 Hierarchy Object 原子模块，保存节点、组件、引用和 Prefab GUID |
| 父子层级对象被恢复两次 | 父、子候选同时选择 | 选择归一化为最外层根；父选中后关闭被覆盖子项 |
| 恢复子树误删骨骼 | 把映射父节点或源模型固有节点当成模块所有权根 | 映射父骨骼只作为挂载点；源固有节点不可选；目标固有节点冲突时阻断 |
| 创建组件时内部引用不存在 | 边创建边立即写引用 | 先创建全部对象和组件，再统一写字段和引用 |
| 第三方布料参数恢复后仍报错 | 旧缓存绑定旧骨骼/Mesh 拓扑 | 清理派生缓存，验证拓扑，在目标内容上重建；不兼容则保存前阻断 |
| PreBuild/共享缓存被破坏 | 工具把共享预构建数据当作普通字段覆盖 | Analyze 阶段识别并阻断，要求人工或插件专用迁移 |
| Dry Run 已经修改目标 Prefab | Preview 与 Apply 复用对象或提前保存 | Preview 使用独立 `LoadPrefabContents` 副本，结束只卸载并比较目标 GUID/内容 |
| 失败后 Prefab 留下半成品 | 执行中途保存，或异常路径未取消事务 | 所有步骤成功后一次 Commit；取消/异常只 Unload，不 Save |
| 组件详情显示的是新 Prefab 当前值 | 直接打开目标组件 Inspector | 由快照数据构建 `HideAndDontSave` 临时组件，再绘制只读 Inspector |
| 自定义 Inspector 一打开窗口就报 GUI 异常 | 临时组件缺少依赖，或错误吞掉 `ExitGUIException` | 依赖占位、inactive 临时根、区分 ExitGUI、失败回退原始数据 |
| 层级区只有打开高级列表后才出现 | 分析触发绑定在高级列表，且无计划时直接不绘制 Foldout | 层级 Foldout 始终绘制；输入齐备时独立排队首次分析 |
| 有恢复组件的匹配节点仍灰色 | 颜色只依据 `Exact` 状态 | 灰显条件加入“当前节点没有已选恢复模块” |
| 恢复后修改模块仍显示旧结果 | 恢复后层级缓存未随输入失效 | 目标、模块或映射变化时清空结果缓存并重新分析 |
| 命令行编译通过但恢复仍有问题 | 交互、Prefab 连接、第三方重建和保存事务未在 Unity 中执行 | 把 CLI 编译作为补充，执行 Unity Editor 行为和真实资产矩阵 |

## 5. 风险与不适用边界

- Unity 序列化不支持的字段、普通 C# 属性、静态字段、运行时动态状态和插件原生句柄不会因 JSON 自动迁移。
- `[SerializeReference]`、自定义序列化、版本迁移回调和自定义 Inspector 可能需要类型专用适配。
- 组件可能受 `[DisallowMultipleComponent]`、`RequireComponent`、原生对象类型、Scene 依赖或 ExecuteAlways 生命周期限制，不能假定 `AddComponent(Type)` 总能成功。
- 重命名脚本类型、程序集、序列化字段或插件升级可能使快照不兼容；脚本 GUID 只能作为同一资产历史中的回退线索。
- GUID + local fileID 不解决跨项目资源复制；没有保留 `.meta` 时必须建立新的资源映射。
- 嵌套 Prefab 的 Removed GameObject/Removed Component Override 若未被快照模型显式记录，不会自动重放。
- 原子子树替换是破坏性操作。目标子树包含目标 Prefab 新增内容时，必须在 Dry Run 中显示删除影响并由用户确认。
- 正式保存没有可靠 Undo；版本控制、备份和原路径 `.meta` 保护不可省略。
- 自动分析必须有状态闸门，不能在失败状态下每帧无限重试或在 `OnGUI` 中执行长耗时工作。

## 6. 验证与回退

### 6.1 最小测试矩阵

| 场景 | 预期 |
| --- | --- |
| 重名及特殊字符节点 | 稳定路径可构建、解析并回到原节点 |
| 普通组件字段 | 数值、字符串、枚举、数组等 Unity 序列化字段一致 |
| Prefab 内 GameObject/Transform/Component 引用 | 指向目标 Prefab 对应节点和正确组件序号 |
| 外部主资源/Sub-Asset 引用 | GUID + local fileID 精确恢复 |
| 多个同类型组件 | 各自字段和引用不串位 |
| 自动依赖开启/关闭 | 开启时展开；关闭且目标缺组件时阻断 |
| Preview | 产生预计差异，但磁盘 Prefab、GUID 和 `.meta` 不变 |
| 路径缺失、唯一候选、歧义候选 | 分别阻断/建议/阻断；不静默猜测 |
| 完整普通 GameObject 子树 | 节点状态、兄弟顺序、组件和内部引用恢复 |
| 嵌套 Prefab | 恢复后仍保持 Prefab 连接，来源 GUID 丢失时阻断 |
| 父子模块同时选择 | 归一化为最外层原子模块 |
| 目标同路径已有子树 | Preview 标记整体替换，Apply 只替换模块所有权根 |
| 第三方拓扑一致/不一致 | 一致时重建并提交；不一致时保存前停止 |
| 取消、超时、窗口关闭、异常 | 目标 Prefab 未保存，无临时内容和 Editor 回调残留 |
| 恢复后查看 | 右栏来自保存后重新加载的实际 Prefab，而非计划模型 |
| 旧 Schema/旧快照 | 支持版本可读；缺失的新模块明确要求重新捕获 |

### 6.2 分层验证

1. **静态检查**：类型解析、稳定路径、引用分类、Schema、事件订阅/释放、异常与超时路径、UTF-8、`.meta` 和文档链接。
2. **程序集编译**：编译工具程序集和 Editor Tests；生成 `.csproj` 只作补充证据。
3. **EditMode 测试**：使用临时 Prefab/资产覆盖上表的数据、计划、预览和保存边界。
4. **Unity 人工交互**：打开窗口检查默认折叠、树滚动、映射、组件 Inspector、确认框、取消和恢复后结果。
5. **真实资产抽样**：选择包含重名骨骼、第三方组件、嵌套 Prefab 和外部资源引用的代表性 Prefab，保存后关闭/重开 Unity 再检查。
6. **版本控制检查**：确认目标 `.prefab` 与预期差异一致，`.meta`/GUID 未变化，无无关资产被刷新或重写。

### 6.3 回退策略

- 捕获边界不可靠时，宁可把组件标为候选并要求确认，不要全量排除或全量覆盖。
- 路径映射证据不足时保持 Blocking，不用叶节点名称自动猜测。
- 第三方重建失败时不 Commit；保留原目标 Prefab，输出模块、路径和插件错误。
- Inspector 临时预览不稳定时，只禁用该类型的可视化并回退原始数据，不影响快照和正式恢复。
- 层级对象删除影响过大时，允许用户关闭整个原子模块；不要临时拆成字段级恢复破坏内部一致性。
- Unity 行为矩阵未完成时，明确标记“静态/编译验证”，不得把可编译表述为真实 Prefab 已安全迁移。

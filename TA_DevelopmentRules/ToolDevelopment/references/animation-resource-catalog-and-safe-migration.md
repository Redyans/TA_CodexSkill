# Unity 动画资源编目、识别与安全迁移参考

> 类型：REFERENCE；适用范围：Unity 项目中由 `.anim`、预览图和可选音频组成的大批量 Humanoid 动画资源的识别、分类、改名与迁移；使用前提：必须以目标项目的 Unity 版本、资产格式、导入结果、命名约定和版本控制状态重新验证。
>
> 关联规则：`TOOL-CMP-01`、`TOOL-ARC-01`、`TOOL-OPS-01`、`TOOL-OPS-02`、`TOOL-OPS-03`、`TOOL-VAL-01`、`TOOL-VAL-02`。项目实例见 [ProjectACG 动画资源编目与双语命名 Profile](../Profiles/ProjectACG/animation-resource-catalog-and-bilingual-naming.md)。

## 1. 适用场景

本参考适用于将混放的角色动画按 `Pose`（静态姿势）与 `Motion`（动态动作）及进一步动作语义整理到稳定目录；为动作补充可审阅的多时刻、多视角预览；只保留 Humanoid 动画；并把动画、预览、对应音频和 `.meta` 作为一个资源组同步迁移和改名。

不适用于需要同时修改 Animator State、Avatar Mask、Timeline Binding、Addressables/YooAsset 地址、脚本裸路径或外部 DCC 工程的迁移。原始动作只有 FBX 导入子资源、无法确认 Importer 写回边界时，也不应直接按本流程移动或改名。

## 2. 前提与依赖

### 2.1 迁移的最小单位是动画资源组

| 成员 | 作用 | 处理要求 |
| --- | --- | --- |
| `.anim` 与 `.anim.meta` | 动画主体、Unity GUID。 | 成对移动，原 `.meta` 不能重建或覆盖。 |
| 预览图与 `.meta` | 审阅、识别和检索证据。 | 文件名前缀、目标目录与动画同步。 |
| 音频与 `.meta` | 音乐、语音或音效。 | 仅在匹配证据充分时一一配对；不确定项进入清单。 |
| 审计清单 | 复核和回退依据。 | 记录旧/新路径、GUID、分类、名称、配对依据与执行结果。 |

音频不能只因位于同一目录就视为对应动画。可使用去后缀基础名、包内相邻关系、作者命名、时长或人工试听匹配；多个候选或没有候选时记录为 `ambiguous` 或 `unmatched`，不随机归属。

### 2.2 Humanoid 判定以 Unity 导入结果为准

文件扩展名、名称中的 `humanoid`、骨骼曲线数量和截图外观都不能代替导入类型。扫描应读取 `AnimationClip.humanMotion` 或等效已导入状态，形成 `Humanoid`、`NonHumanoid`、`Unknown/Error` 清单。非 Humanoid 资源常驱动 float、BlendShape、材质或插件参数；是否删除必须再检查真实消费者和用户确认。

### 2.3 动作识别需要时间与视角证据

静态姿势使用正面、45 度和侧面三视图判断重心、坐/跪/躺、手势、道具和角色位。动态动作至少输出：

| 时间点 | 视角 | 用途 |
| --- | --- | --- |
| `15%`、`50%`、`85%` | `0°`、`45°`、`90°` | 观察起势、中段、收势、位移方向、左右肢体和身体旋转。 |

先检查截图是否完整：尺寸一致、角色完整、相机正确、没有双模型、条带图、黑图或重复帧。帧差或轮廓变化只能辅助发现异常，不能单独判定 `Idle`、`Dance`、`Emote`、`Interaction` 或 `Pose`；呼吸、持物、舞蹈定格和坐姿保持段都可能低变化。

## 3. 实现或排查步骤

### 3.1 先建立只读清单和分类词表

写入前扫描目标根目录，生成至少包含下列字段的 CSV 或 JSON：

```text
sourceAnimationPath, animationGuid, humanMotion, sourceName, previewPaths,
audioCandidates, currentCategory, proposedCategory, proposedEnglishName,
proposedChineseMeaning, targetPath, conflict, maxPathLength, decisionReason
```

分类先分一级形态，再分二级语义：

| 一级 | 二级示例 | 判定重点 |
| --- | --- | --- |
| `Pose` | `Standing`、`Seated`、`Kneeling_Crouching`、`Floor_Lying`、`Airborne_Acrobatic` | 主重心、接触面、肢体支撑和可复用静态姿势。 |
| `Motion` | `Locomotion`、`Greeting`、`Emote_Gesture`、`Interaction`、`Action_Combat`、`Dance_*`、`AFK_Idle` | 位移、节奏、社交意图、互动对象与战斗语义。 |
| 待确认 | `NeedsPreview` 或同义隔离目录 | 预览、语义或音频配对不充分。 |

`CharacterVariant`、`Pair_Role`、`Group_Role`、`Prop` 等只在确实描述使用条件时作为进一步维度；不要用来源商店名替代动作类别。

### 3.2 渲染、审阅并记录分类依据

1. Pose 输出三视图；Motion 输出 `15%/50%/85% × 0°/45°/90°`。
2. 批量检查图像完整性与命名格式，筛出渲染失败、缺时刻或重复帧。
3. 在清单写入形态、语义分类、置信度和简短判定依据。
4. 将低置信度、双人/群组角色位、带道具、镜头角度或语义不明的条目留在待确认分类。
5. 九图仍无法区分节奏、循环或交互时，在 Unity 实际播放，必要时查看曲线或试听配套音频。

### 3.3 生成可执行的改名与迁移计划

常用可读名称模型：

```text
EnglishName(中文语义)
```

英文原标识保留为搜索、插件和来源键；中文补充可读语义。文件夹可用 `EnglishCategory(中文分类)`。计划需预检目标重名、大小写冲突、截图时间/视角后缀、音频竞争、路径长度、缺失 `.meta` 和环形改名。

计划明确区分 `rename`、`move`、`move-and-rename`、`skip`、`needs-review`、`delete-candidate`。删除候选需要独立确认，不能被迁移脚本顺带处理。

### 3.4 按资源组执行，并保留 Unity 身份

推荐顺序：

1. 冻结计划，确认不存在未处理冲突、路径过长或 `Unknown/Error` 导入状态。
2. 先迁移动画与原 `.meta`，再同步迁移预览和已确认配对的音频及各自 `.meta`。
3. 同步动画名、预览图前缀和音频名。文本 YAML `.anim` 先预检格式后才可同步内部 `m_Name`；二进制或导入器子资源应使用 Unity API。
4. 按组记录旧路径、新路径、GUID、成功/失败/跳过原因和已处理成员，并以 `try/finally` 清理批处理状态。
5. 迁移后让 Unity 重新扫描；不得重新生成已存在 `.meta`。

在 Unity Editor 内优先使用 `AssetDatabase.MoveAsset`/`RenameAsset`。若因规模使用文件系统操作，要避免与正在写入的导入流程并发，并把重新导入作为必需验证。

### 3.5 报告既是审计也是回退输入

至少输出以下结构化产物：文件夹改名清单、资源组清单、预检报告、验证报告和旧/新路径回退清单。日志只有 Console 文本而没有映射清单时，无法证明某张图或音频是否随动画迁移。

## 4. 风险与不适用边界

| 风险或现象 | 常见根因 | 建议处理 |
| --- | --- | --- |
| 动画被错误归入静态姿势 | 仅看中间帧或帧差。 | 审阅九图，必要时实际播放；低置信度进入待确认。 |
| 正面相同但方向相反 | 未输出侧面或 45 度视角。 | 保留 `0°/45°/90°`，观察前后位移和左右肢体。 |
| 音频与动作拆散 | 只移动 `.anim`，或按目录猜配对。 | 以资源组清单执行，保留匹配依据与不确定状态。 |
| Unity 引用丢失 | `.meta` 未同步、覆盖或重建。 | 迁移前后比较 GUID。 |
| Inspector 名称不一致 | 只改文件名。 | 在可验证格式/API 上同步内部 `m_Name`。 |
| 非 Humanoid 参数动画混入 | 用预览或名称判断类型。 | 以 `humanMotion` 筛选，删除前检查消费者。 |
| 批处理半途失败 | 未预检冲突、路径或取消边界。 | 先完整计划、按组记账、按回退清单恢复。 |
| 外部工具失效 | DCC、表格、脚本或打包配置保存裸路径。 | 迁移前搜索消费者，无法覆盖时明确排除。 |

文件系统验证通过不等于 Unity 已完成重导入、引用、Avatar 兼容或实际播放验证。报告要明确区分“路径/GUID 已验证”和“Editor 行为已验证”。

## 5. 验证与回退

| 层级 | 检查 | 通过条件 |
| --- | --- | --- |
| 清单 | 每个动画有来源、目标、分类、Humanoid 状态和策略。 | 无未解释的重复、遗漏或 `Unknown` 执行项。 |
| 预览 | Pose 三视图；Motion 九图。 | 时间点/视角齐全，异常项可定位。 |
| 资源组 | 动画、`.meta`、预览、音频及 `.meta`。 | 已配对成员一起迁移；未匹配项明确保留。 |
| Unity 身份 | 改名前后 GUID。 | 保留资产 GUID 一致，无 `.meta` 缺失或重复。 |
| 名称 | 文件名、图片/音频前缀、可修改的内部 `m_Name`。 | 清单与实际一致，英文标识未丢失。 |
| Unity Editor | 重导入、Clip 加载、代表性播放和编译。 | 无新导入错误，抽样动作可播放且引用未丢失。 |

建议顺序：只读扫描与预览渲染 -> 人工分类和音频配对 -> 预检 -> 用户确认迁移/删除范围 -> 执行 -> 计数/GUID/配对验证 -> Unity 重导入和实际播放。

版本控制、隔离目录副本或冻结的路径映射才是大规模迁移的主要回退手段。Unity Undo 不能替代对文件移动、重导入、批量 `.meta` 关联和外部路径的回退计划；回退应限定到迁移清单涉及的路径，避免覆盖用户无关改动。

## 1. 目录级 Git 快照同步

### 适用场景

只把某个分支或提交中的指定目录带到当前工作树，同时保留其他本地改动。

### 前提与依赖

需要确定目标仓库、当前分支、源提交或远端引用、目标目录本地状态、是否允许写入 `.git` 锁文件，以及目录外是否存在用户改动。远端跟踪引用可能落后，不能只看本地缓存。

### 实现或排查步骤

1. 先刷新目标远端引用；不能刷新时明确标记结果只基于现有 refs。
2. 按目录统计各分支最后一次实际改动，再区分“目录最新”和“分支尖端最新”。
3. 读取目标目录状态，确认没有需要保留的本地改动。
4. 使用 `git restore --source=<commit> --worktree -- <path>` 同步指定目录；它不更新暂存区，但仍需要 `.git` 写权限。
5. 若补丁因父目录不存在或中途失败，先检查工作树，再用同一提交的目录快照重新统一，避免留下半应用状态。
6. 逐项核对文件清单、删除/新增文件和 blob/hash；最后用 `git diff --check` 检查格式，并报告未编译、未运行时验证的边界。

### 风险与不适用边界

目录最新不等于分支整体最新；整分支或整目录覆盖可能带入无关改动。`git restore` 不是三方合并，目标目录的未提交改动会被覆盖；先做状态和备份。仓库权限失败不能当成“没有差异”。

### 验证与回退

验证源提交、目录相对差异、文件数量、blob/hash、工作区范围和暂存区未被意外改变。回退使用原提交或备份恢复同一目录，并重新检查目录外改动。来源：`01a1be75-d3f7-7a92-994c-8af3637d957d`，消息 2～24。

## 2. 本地会话记录 Hook 的边界

### 适用场景

需要将 Codex 可见问答保存成可重新解析的 Markdown，供后续日报或检索使用。

### 前提与依赖

需要 Hook 生命周期事件、转录路径、会话 ID、目标目录写权限、JSONL 解析器和用户对读取/写入范围的授权。Hook 安装、信任、运行和自动化读取是四个独立状态。

### 实现或排查步骤

1. 按会话 ID 建立稳定文件名，另存原始 JSONL 便于重新解析；不要把聊天内容塞进 `AGENTS.md`。
2. 逐行 `json.loads()` 读取转录，提取用户和助手可见文本；处理重复事件与无转录文件。
3. 测试中文路径、重复保存、编码、文件更新和失败输出，再安装全局配置。
4. 在 Codex Hooks 界面审核并信任命令；安装完成不代表已运行。
5. 日报按每条消息时间戳换算时区筛选，不能用文件修改时间或会话开始日期代替。

### 风险与不适用边界

Hook 可能包含敏感路径、业务数据、密钥或令牌；写入前要清理敏感内容。Hook 是否每轮触发、是否覆盖子代理、是否在会话结束后运行取决于实际事件和版本。没有读到原始 JSONL 时只能报告 Markdown 中的事实。

### 验证与回退

分别检查 Hook 配置、信任开关、目标文件新鲜度、消息数量和 JSONL 可解析性。禁用 Hook 或恢复原配置即可回退；不删除既有记忆文件。来源：`01a1be89-95fb-7670-bd04-324475429c51`，消息 1～35。

## 3. 技能安装与自动匹配

### 适用场景

安装社区/官方技能并判断其是否会在每轮会话自动运行。

### 前提与依赖

先查安装器索引和准确仓库路径，读取每个 `SKILL.md`，区分技能文件、CLI 依赖、外部网络配置和后台服务。

### 实现或排查步骤

1. 记录名称、来源、目标路径和冲突状态；找不到准确来源时不要按同名猜测安装。
2. 只安装技能包，默认不安装额外 CLI、不配外部节点、不启动服务。
3. 对已有目录检查是否缺 `SKILL.md`，不要为了补齐而覆盖未知文件。
4. 将“可被任务匹配”和“每轮自动运行”分开解释；安装通常只增加可选指引，不建立常驻进程。
5. 外部联网、自我演化和自动化功能需要单独配置、授权和验证。

### 风险与不适用边界

社区技能可能包含联网、外部执行或修改本地设置的代码；审阅不等于运行安全。技能名称有多个同名来源时，来源可信度和内容审计优先于安装量。没有 CLI、API key 或节点身份时不能宣称能力已可用。

### 验证与回退

确认目标目录、`SKILL.md`、安装器结果和依赖状态；回退只移除本次新增且确认归属的技能目录，不覆盖用户已有目录。来源：`01a1be8c-05dc-7ca2-8dd2-5277cd4cf75a`，消息 1～18。

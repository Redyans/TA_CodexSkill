# Unity Mesh 贴图绘制工具参考｜2026-11-13

> 类型：REFERENCE；适用范围：Unity Editor 内对 Mesh UV 贴图进行实时通道/颜色绘制的工具；使用前提：按目标 Unity 版本、UV/Wrap、贴图导入编码、材质绑定和 GPU 能力重新验证。
> 关联既有规则：`TOOL-DOC-03`、`TOOL-CMP-01`、`TOOL-ARC-01`、`TOOL-ARC-02`、`TOOL-UI-01`、`TOOL-VAL-02`；ProjectACG 实际实现见 [Mesh 贴图绘制工具 Profile](../../Profiles/ProjectACG/CodexDaily/Development_Profile_2026-11-13.md)。

## 1. 适用场景

- 在选中模型表面编辑 FlowMap、遮罩、速度、颜色、粗糙度等材质贴图数据。
- 将原 FlowMap 专用画笔扩展为通用单通道、RGB/RGBA 贴图绘制工具。
- 高倍平铺、多 UV 区、较高分辨率造成绘制或抬笔备份停顿。
- 工具窗口功能增长，需要精简常用流程且保留高级能力和已保存工作区兼容。

## 2. 前提与依赖

- 将材质槽/Shader 属性选择与贴图内 RGBA 通道选择分开；不同 Shader 对通道的解释属于材质契约，工具不能仅凭属性名猜测。
- UV 可超出 `[0,1]`，并由贴图 Wrap 模式决定跨区写入是否周期重复；同时确认纹理 Tiling/Offset、UV 选择器和绘制坐标变换一致。
- 记录源贴图读写/编码颜色空间、Alpha、压缩、MipMap、Filter/Wrap 以及是否覆盖/另存。特殊编码贴图（如法线）需要专门解码和预览路径。
- GPU 绘制工具需确认 RT 格式、Blend 状态、GPU 同步/readback、Undo 历史内存和设备支持；CPU/GPU 测时要说明包含项。

## 3. 实现或排查步骤

### 3.1 把绘制内容语义与笔刷形状分离

1. 先选择目标 Mesh、材质槽和贴图属性，再选内容类型：单通道 R/G/B/A、RGB、RGBA 或专用向量模式。
2. 另行选择圆形/方形/笔刷纹理、强度、大小、硬度和绘制/平滑模式，使形状素材能跨内容模式复用。
3. 单通道写入时只改目标通道，其他通道原样保留；RGB 默认保留 Alpha，RGBA 才写 Alpha。擦除目标值与笔刷强度分开。
4. 让具体模式定义可用操作：颜色/数值直接绘制、平滑、填充、渐变、专用向量操作；避免 UI 暴露对当前数据语义无意义的操作。
5. 使用具名模式/预设声明通道含义时，允许用户自定义而不把某个 Shader 属性或项目通道映射写成全局固定规则。

### 3.2 保持 UV 平铺与材质绑定一致

1. 不以 UV 是否落在 `[0,1]` 作为可绘制条件；应检查所选 UV 通道是否存在、Mesh/材质是否有效及绘制坐标是否可计算。
2. 用负 UV、超过一块区域的 UV、接缝两侧和带 Tiling/Offset 的材质测试。微小浮点越界不应直接导致整 Mesh 初始化失败。
3. 若纹理 Wrap 为 Repeat，跨区绘制会映射到同一张周期纹理，重复 UV 区/重叠 UV 岛可能共享笔迹；若目标是独立岛数据，需要不同的纹理布局或遮罩策略。
4. 对修改的图另存并回绑时，明确共享材质/Renderer 的影响、Undo、失败恢复和源贴图保留方式。

### 3.3 降低 GPU 绘制和备份停顿

1. 分开量测每个笔刷落点、鼠标插值/每帧采样、GPU 同步、撤销快照、PNG 编码/写盘和整个 Scene 渲染；不要把单次落点时间换算为帧率。
2. 若每个落点都提交全 Mesh，评估按笔刷 UV/空间范围筛选三角形；小三角形可缓存索引，大三角形在落点范围内裁切。
3. 量测局部筛选 CPU 成本与 GPU 收益。全量 CPU 裁切可能使普通网格变慢，可用缓存和尺寸门槛避免小场景倒退。
4. 将连续采样合批、降低过密插值，并把 Scene/材质刷新合并为每帧或按需一次。
5. 抬笔备份使用异步 GPU readback、后台编码/写盘并合并可合并的历史；关闭窗口/域重载时等待最终写入完成。仍保留明确的“保存”完成语义。
6. 静态预览按需刷新；纹理、Undo 缓冲和材质状态按生命周期复用或缓存，并限制历史数量/内存。

### 3.4 让窗口能被重复使用

- 高频入口直接可见：模型/贴图目标、内容/UV、通道、颜色、笔刷、开始/保存。
- 用折叠区容纳填充、擦除配置、映射、预设和布局辅助等低频项；只显示当前内容模式有效的控制。
- 保留一个可识别的主要开始绘制入口，并明确“未载入画布”“目标失效”“内容已改变”和“可绘制”状态。
- 精简旧工作区时，显式迁移旧折叠状态；兼容历史设置值，避免重开工具后意外丢失配置或出现禁用的主按钮。

### 3.5 正确判断持久化后的绑定状态

保存/恢复 Editor Window 后，不要只凭可序列化内联对象是否为 `null` 判断“用户已经捕获了材质绑定”。恢复流程可能把空引用物化为字段默认值。应区分“未建立绑定”和“已建立但引用失效”：前者可进入新建/配置流程，后者应继续阻止错误绘制。将捕获、JSON 序列化、窗口关闭重开、自动 Tick 与恢复后继续绘制一起纳入回归。

## 4. 风险与不适用边界

- UV 超界合法不代表 UV 通道可以缺失；所选通道不存在时仍需给出明确诊断。
- Repeat 会让重复区域共享数据；绘制跨缝效果取决于 Wrap、纹理空间与 UV 重叠，不适合需要每个重叠岛独立像素的场景。
- 高面数几何筛选可能增加 CPU 开销；高分辨率撤销纹理占用大，异步读回仍可能受 GPU/驱动、磁盘和关窗时序影响。
- 单通道平滑/颜色绘制不适用于没有专用解码/编码的法线或压缩数据贴图。
- 性能数据必须带上 GPU/CPU、纹理尺寸、Mesh 规模、采样次数和是否包含 GPU 完成、Scene、拾取、分配及备份。
- Shader 层通道语义、工具目标贴图身份、绘制 UI 模式必须同步，但工具不能以隐式写入覆盖用户材质/源纹理。

## 5. 验证与回退

- 对目标通道逐像素验证：目标值、锁定通道不变、Alpha 保留、擦除值、半透明、平滑与 Undo/Redo。
- UV 矩阵包含 `[0,1]`、小幅负值、负区、大于一块、接缝、重叠岛、重复 Wrap、Tiling/Offset 和各可选 UV 通道。
- 同一工具目标分别覆盖新建、已有纹理、保存副本回绑、共享材质影响、异常退出和工作区恢复。
- 性能至少区分普通 UV/高倍平铺、高低面数和 512/1024/2048 纹理；报告中分列 GPU 落点与抬笔备份。
- 独立 Unity/GPU harness 可验证像素与生命周期，但生产 Editor 的 Scene 操作、手感和硬件仍需用户场景检查。
- 保留源纹理、旧菜单/旧数据状态兼容和可回滚路径；新模式出现问题时可退回已有 FlowMap 绘制路径。

# FBX 源数据编辑器开发参考

> 类型：REFERENCE；适用范围：需要直接读取、修改并重新写出 FBX 源文件的 Unity Editor 工具；使用前提：必须按目标项目的 Unity、FBX SDK、FBX 资产和导入链路重新验证。

关联 CORE：`TOOL-CMP-01`、`TOOL-ARC-02`、`TOOL-ARC-03`、`TOOL-OPS-01`、`TOOL-VAL-02`、`TOOL-VAL-03`；规范来源见 [工具开发模块](../README_Tech_TAToolDevelopmentRules.md)。

## 1. 适用场景

适用于以下需求：

- 修改 FBX 源文件中的节点、骨骼、网格、UV、顶点色、材质槽、Pivot、单位或动画相关数据。
- 需要区分“修改 Unity 导入后的对象”和“修改 FBX 原始资源”的工具设计。
- 需要保证写出后 FBX 可被 SDK 回读、Unity 重新导入，且不静默破坏蒙皮、动画或外部材质引用。
- 需要把危险的源文件覆盖操作做成可验证、可备份、可回退的 Editor 工作流。

不适用于只修改场景实例、Prefab 或 Unity 导入对象的普通 Inspector 工具；这类工具不应为了“看起来能改 FBX”而引入 FBX SDK 写回链路。

## 2. 前提与依赖

- 明确源数据的唯一事实来源：原始 `.fbx` 文件、Unity 导入对象、外部材质映射和 `.meta` 各自承担什么职责。
- 使用项目实际可用的 Autodesk FBX SDK C# 绑定；先确认 `FbxScene`、`FbxNode`、`FbxMesh`、`FbxLayerElement*`、动画栈和 Pose API 的版本差异。
- 将 SDK 读取/写出封装在独立处理器中，窗口只保存字段状态、显示校验结果并发起操作。
- 读写操作建立独立 SDK Session，完成后释放 `FbxManager`、IOSettings、Importer、Exporter 和 Scene；不要把原生包装对象跨窗口生命周期长期缓存。
- Editor-only 代码必须放在 Editor 程序集，并显式限制 `includePlatforms` 为 `Editor`；不能让 `UnityEditor`、`SceneView`、`MenuItem` 或 FBX Editor API 泄漏到 Player 程序集。

## 3. 实现或排查步骤

### 3.1 先冻结数据契约

1. 建立源文件概览：单位、节点路径、骨骼、网格、材质槽、UV、顶点色、动画栈和蒙皮。
2. 为每类操作定义“允许变化”和“必须不变”的字段。例如材质槽移动允许槽顺序和多边形材质索引改变，但网格拓扑、控制点数量、蒙皮和动画数量必须不变。
3. 使用稳定的节点索引路径或完整层级路径定位对象，不使用显示名称作为唯一键；同名节点、同名材质和重复网格是正常输入。
4. 将校验结果记录为结构签名、数值签名和索引签名；签名比较必须服务于语义，不要把 FBX 导出器可合法规范化的无意义排列误判成数据损坏。

### 3.2 采用“临时写出、回读校验、最后替换”

推荐闭环：

1. 从源 FBX 创建临时 SDK Session。
2. 应用单个明确操作，不在一次写出中隐式叠加其他编辑。
3. 写出到同目录临时文件，避免跨卷 `File.Replace` 和相对路径误判。
4. 关闭写出 Session 后，用新的 SDK Session 重新导入临时文件。
5. 比较结构签名、几何签名、变换签名、动画/蒙皮签名和本次允许变化的语义。
6. 只有验证成功才覆盖源文件或提交副本；覆盖前复制 `.fbx` 和 `.meta` 到备份目录。
7. Unity 中使用 `AssetDatabase.ImportAsset(..., ForceUpdate)` 或受控 `Refresh`，然后重新读取概览。

不要直接对二进制 FBX 做字符串替换，也不要在 SDK Session 尚未关闭时覆盖正在读取的源文件。

### 3.3 单位与整体比例

- 单位转换使用 `FbxSystemUnit.ConvertScene`，不要只改全局单位元数据；只改元数据会让几何、节点和动画的实际尺度不一致。
- 附加整体倍率可以通过临时系统单位转换实现：将当前单位的比例按倍率调整，转换场景后恢复最终单位元数据。这样可以同时覆盖节点位移、控制点、骨骼、动画、蒙皮簇矩阵和绑定姿势。
- 比例参数必须拒绝零、负数、NaN、Infinity 和过大的非预期值；在 UI 和处理器两侧都做校验。
- 回读时确认单位元数据与关键空间数据共同正确，不能只检查 `GetScaleFactor()`。

### 3.4 Pivot 与变换

- 原始 Pivot 至少区分旋转偏移、旋转枢轴、预旋转、后旋转、缩放偏移和缩放枢轴；不要把 Unity `Transform` 的一个 pivot 值伪装成 FBX Source Pivot。
- 若要求保持局部和世界变换，先保存旧局部/世界矩阵，再写 Pivot 属性，最后求解新的 TRS；验证矩阵误差超过容差时阻止写出。
- 目标节点存在变换动画时，不应只修改静态基底。除非能为所有动画栈重写新基底下的 TRS 曲线，否则必须明确阻止 Pivot 操作。
- 不保持变换应当是显式选项，并在执行前提示会改变节点及子层级的空间结果。

### 3.5 UV 与顶点色层

- 先处理 MappingMode、ReferenceMode、DirectArray 和 IndexArray，再处理数值。只改 DirectArray 但忽略索引映射会造成看似成功、实际 UV/颜色错位。
- FBX C# 绑定可能无法直接读写 UV 元素名称；需要重命名时，可创建等价新层并替换旧层，同时保持映射、引用模式、数值和索引。
- 新建 UV 或顶点色必须明确映射模式、引用模式和初始值；“新建空 UV”不应悄悄执行自动展 UV。
- 删除或交换层时校验目标层确实存在，并阻止把同一层交换给自身。
- 顶点色通道调整应在写入前后限制到合法范围，并对 RGBA 重排、反相和填充分别验证。
- 导出器可能删除完全空的数据层或重排无语义的层结构。签名比较应忽略已确认可由导出器规范化的空层，但不能忽略实际有数据的层。

### 3.6 材质槽

- 材质槽是节点连接顺序和网格多边形材质索引的联合契约；移动、删除或替换时必须同时重建节点材质连接和多边形索引映射。
- 不要只调用 `RemoveMaterial` 或直接改槽位而留下旧的 `eIndex/eIndexToDirect` DirectArray；重建材质层可避免旧材质指针在导出后重新出现。
- 用材质对象身份或场景材质索引判断重复，不要只比较材质显示名称；同名材质可能不是同一个对象。
- 仍被多边形使用的槽位不能直接删除；添加已连接材质、替换为其他槽已有材质应在 UI 和处理器两侧阻止。
- 某些 FBX 使用 `eDirect` 直接材质引用，C# 绑定不一定能安全写入 DirectArray。无法证明安全时应阻止该替换并提示原因，不要静默降级。

### 3.7 骨架层级

- 重设父级前保存所有节点的默认姿势世界矩阵，改变父级后重新求解目标骨骼的本地 TRS，并验证全节点世界矩阵误差。
- 必须阻止把节点移动到自身或子层级，避免生成循环父级。
- 保持蒙皮 Cluster、连接关系和 BindPose/Pose；父级变更不是简单的 `SetParent` 文本操作。
- 含节点 Transform 动画时，改变父级会改变曲线所在空间。没有完整的所有动画栈曲线重写方案时，必须阻止操作。
- UI 应在目标骨骼切换时同步当前父级，并过滤非法父级；处理器仍需重复做循环和动画校验。

### 3.8 Editor UI、覆盖和构建边界

- 破坏性写入必须有“另存副本”和“覆盖源文件”两个明确入口；覆盖前确认、备份和可定位结果缺一不可。
- UI 只负责收集参数、显示当前选择、阻断明显非法输入和报告结果；SDK 副作用集中在处理器/资产 IO 边界。
- 中文工具参数和状态文本保持术语一致；技术限制、未支持的 FBX 变体和回退方式必须写在界面提示与技术文档中。
- Editor 程序集显式 `includePlatforms: ["Editor"]`，并在目标平台编译检查中确认没有把 Editor API 带入 Player。
- 不修改 `Library`、`Temp`、自动生成 csproj 或 SDK 生成文件作为永久修复；生成文件只用于诊断和临时编译验证。

## 4. 风险与不适用边界

- SDK 能读写一个 FBX，不代表它能无损保留该 FBX 的所有私有扩展、导出器元数据或第三方工具属性；必须以目标资产的回读和 Unity 重导入为准。
- 动画、Pivot、骨架重父级和单位倍率会相互影响；一次操作只修改一个职责域，避免难以归因的组合变换。
- 同名对象、重复材质、多个 Layer、空 Layer、不同 MappingMode/ReferenceMode 和非标准轴向是必须覆盖的边界输入。
- 独立 .NET Probe 反复创建/销毁原生 FBX Manager 可能触发 Native SDK 生命周期异常；测试应减少 Session 数量，必要时每个模式独立进程，不能把此类 Probe 崩溃误判成 Unity 编辑器程序集错误。
- Unity Editor 编译通过不能证明 FBX 语义正确；反之，单次 FBX 回读通过也不能证明 Player 构建边界正确。

## 5. 验证与回退

最小验证矩阵：

| 范围 | 至少覆盖 | 通过条件 |
| --- | --- | --- |
| 编译 | Unity Editor 重编译、受影响程序集、目标 Player 编译 | Editor API 不进入 Player；无新增编译错误 |
| 静态 FBX | 单位、比例、Pivot、UV、顶点色、材质槽 | 临时文件可回读，结构签名和允许变化符合预期 |
| 蒙皮 FBX | 单位、Pivot、材质槽、骨架层级 | 蒙皮连接、BindPose、默认姿势和网格拓扑保持 |
| 动画 FBX | 单位/倍率、Pivot 阻断、骨架重父级阻断 | 动画数据不被静默改坏，非法操作明确阻止 |
| 导入链 | Unity 重导入、材质映射、动画播放 | Console 无新增错误，引用和显示结果可复核 |
| 失败回退 | 只读源文件、SDK 导出失败、回读不一致、用户取消 | 源文件未替换，临时文件清理，备份可定位 |

回退优先使用覆盖前备份或版本控制恢复；不要用 Unity 重新导入来“修复”已经被错误写出的源 FBX。

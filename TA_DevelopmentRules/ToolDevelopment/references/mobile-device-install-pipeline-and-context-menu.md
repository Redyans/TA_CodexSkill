# 移动设备一键安装工具链与资源管理器右键集成参考

> 类型：REFERENCE；适用范围：Windows 上把 Android `APK` 与 iOS `IPA` 一键安装到真机的脚本工具链、资源管理器右键菜单集成、长任务进度反馈与相关排查；使用前提：必须按目标 `adb`、`go-ios`、系统版本、设备签名描述文件和实际命令输出重新验证。
>
> 关联规则：`TOOL-CLS-01`、`TOOL-ARC-01`、`TOOL-OPS-01`、`TOOL-OPS-03`、`TOOL-VAL-01`、`TOOL-VAL-02`。本文记录可迁移的实现模式、排查路径和检查清单，不替代目标工程的脚本、设备工具官方文档或实际安装结果。

## 1. 适用场景

本参考适用于以下问题：

- 打包机产出体量大（GB 级），需要绕开 Unity Build And Run 或 IDE 部署流程，直接对已有 `.apk` / `.ipa` 重复安装。
- 需要在资源管理器里对任意一个包体文件右键安装，并看到目标设备、传输进度和明确的成功/失败结论。
- 需要把「选设备 → 传输 → 安装 → 结果」这条链路做成可复用脚本，而不是每次手敲命令。
- 需要排查已经能跑通的安装链路为什么会静默失败、卡死、中途断开或报出与真实原因无关的错误。

以下需求不属于本参考范围：

- 用脚本绕过目标应用本身的签名、授权或设备管理策略。
- 把工具链做成常驻服务、构建流水线的一部分或对外分发的安装器。
- 通过改名、隐藏窗口或伪造日志掩盖失败，而不是如实报告设备返回的错误。

## 2. 前提与依赖

### 2.1 冻结 source of truth

开始实现或排查前先记录以下信息：

| 维度 | 要确认的内容 |
| --- | --- |
| 宿主 | Windows 版本与构建号、默认右键菜单是经典菜单还是精简菜单、是否可重启资源管理器 |
| 设备 | 平台、系统版本、机型标识、序列号/`UDID`、当前连接方式（USB/Wi-Fi） |
| 工具链 | `adb` 或 `go-ios` 的版本、来源路径、是否已在 `PATH` 中、是否为自带副本 |
| 包体 | 文件大小、签名类型、描述文件含哪些设备、`MinimumOSVersion`、是否 `testOnly` |
| 脚本宿主 | 执行脚本的是 5.1 还是 7.x，二者默认编码和部分行为不同 |
| 验证 | 无设备、单设备、多设备、大包、失败包各自的预期结论 |

### 2.2 签名与授权边界

- Android：开发包通常需要 `-r`（覆盖）、`-d`（允许降级）、`-t`（允许 `testOnly`）三个开关同时成立，否则会被设备直接拒绝。
- iOS：`App Store` 下载的加密 `ipa` 无法安装；开发 / `AdHoc` / 企业签名的包，其描述文件必须已包含目标设备 `UDID`。
- 描述文件、证书和账号信息不得写入脚本正文或随工具分发；脚本只消费本地已有产物。
- 安装工具只面向自有或明确获授权的测试设备，不提供规避设备管理或签名的实现。

### 2.3 权限与验证上下文

同一个 Windows 账号在不同提权路径下可能是**不同的用户配置单元**：受限沙箱、服务账户与登录桌面用户各自拥有独立的 `HKCU`。因此：

- 用 `whoami` 确认当前进程身份，用 `query user` 和资源管理器进程的 owner 确认交互桌面身份。
- 注册表写入、菜单枚举和「菜单到底出没出现」的验证必须在**同一个目标用户上下文**完成，跨上下文验证会得到假阴性。
- 涉及 `HKCU` 的下述实现都不需要管理员权限；把不需要提权的步骤升级，反而会引入用户不一致问题。

## 3. 实现或排查步骤

### 3.1 资源管理器右键菜单集成

#### 3.1.1 选择注册位置

| 注册位置 | 生效对象 | 适用判断 |
| --- | --- | --- |
| `HKCU\Software\Classes\SystemFileAssociations\.<ext>\shell\<Verb>` | 指定扩展名 | 首选。与文件当前关联程序无关，换关联不失效 |
| `HKCU\Software\Classes\<ProgID>\shell\<Verb>` | 某个关联程序 | 仅当必须并入该程序的菜单组时使用，绑定具体 `ProgID` |
| `HKCU\Software\Classes\*\shell\<Verb>` | 所有文件 | 必须同时写 `AppliesTo`（AQS 过滤）限定扩展名，否则污染全部文件的菜单 |
| `HKCU\Software\Classes\Directory\shell\<Verb>` | 文件夹 | 用于「安装目录里最新的包」这类入口 |
| `%APPDATA%\Microsoft\Windows\SendTo\<名称>.lnk` | 「发送到」子菜单 | 作为补充入口，快捷方式 `TargetPath` 指向 `wscript.exe` |

动词键的默认值即菜单显示名，`Icon` 指向可作为图标的可执行文件；`command` 子键默认值给出命令行，`%1` 会被替换为被选中的文件路径。

#### 3.1.2 用 `wscript` 静默启动，避免黑框闪现

菜单命令直接调用 `powershell.exe` 会短暂弹出控制台窗口。做法是注册一个 `wscript.exe "<launcher>.vbs" "%1"`，由 `.vbs` 用 `WScript.Shell.Run(cmd, 0, False)` 以隐藏窗口启动脚本。`.vbs` 本身保持纯 ASCII 内容，避免被 `wscript` 按 ANSI 解释时出现乱码或截断。

#### 3.1.3 注册后必须刷新外壳

静态动词写入注册表后**不会**立即出现在右键菜单里。最低要求是通知外壳关联变更：

```powershell
# SHCNE_ASSOCCHANGED = 0x08000000, SHCNF_IDLIST = 0x0000
[Win32.ShellRefresh]::SHChangeNotify(0x08000000, 0x0000, [IntPtr]::Zero, [IntPtr]::Zero)
```

实测该通知有时仍不足，需要重启 `explorer.exe`（`Stop-Process -Name explorer -Force` 后重新启动）。注册脚本应当把「通知失败时提示重启资源管理器」写进输出，而不是默认成功。

Windows 11 的精简右键菜单默认不展开静态动词，必须点「显示更多选项」或按 `Shift+F10`。写使用说明时要写清这一点，否则会被判定为「菜单没生效」。

#### 3.1.4 用 Shell API 验证，而不是靠肉眼

判断某个动词是否真的生效，应枚举外壳自己会展示的动词列表，该结果与右键菜单使用同一套逻辑：

```powershell
$item = (New-Object -ComObject Shell.Application).NameSpace($dir).ParseName($file)
$item.Verbs() | ForEach-Object { $_.Name }
```

若目标动词出现在该列表而菜单里没有，问题是资源管理器缓存而不是注册内容；若该列表里也没有，先回到注册位置和验证上下文排查。

注意该 COM 调用在非交互上下文可能长期阻塞，脚本化验证时应带超时保护，不要让它卡死整条命令。

### 3.2 Android：会话式安装与真实进度

`adb install` 只输出最终结果，无法给出传输百分比。需要真实进度时用 `pm` 会话接口，把包体从标准输入流式送进去：

1. `adb shell pm install-create -r -d -t -S <字节数>`，从 `Success: created install session [<数字>]` 中取出会话号。
2. `adb shell pm install-write -S <字节数> <会话> base -`，把包体按固定块大小写入子进程标准输入，每写一块即可算出真实百分比。
3. `adb shell pm install-commit <会话>`，返回 `Success` 才算安装完成。
4. 会话任一步失败时先 `pm install-abandon <会话>`，再回退到 `adb install -r -d -t <路径>`。

`.apks` 这类拆分产物先解压，再用 `adb install-multiple -r -d -t <多个 apk>` 安装。设备解析用 `adb devices -l`，除 `device` 之外还要识别 `unauthorized`、`offline`、`no permissions` 等状态并给出可操作提示，不能只挑 `device` 行、让用户在「未检测到设备」里猜原因。

### 3.3 iOS：开发者隧道与新安装服务

iOS 17 起苹果把安装服务搬到开发者隧道之后，传统的 `installation_proxy` 路径会静默失效。两类典型症状：

- 直接传宿主路径调用安装接口，返回 `MissingPackagePath`——该接口需要的是**设备上的绝对路径**。
- 用 `libimobiledevice` 系列工具调用时立即返回、回调不触发，看起来「成功」但设备上没有任何变化。

可行路径是先用 `go-ios` 一类工具建立隧道，再走新的安装服务（`com.apple.remote.installcoordination_proxy` / `zipconduit`）：

1. `ios tunnel start --userspace`，等待隧道就绪。
2. 就绪判定必须用 `ios rsd ls --udid=<UDID>` 能列出 `shim.remote` / `remoteserver` 一类服务，**不能**用 `ios tunnel ls`——它会返回上一次已经死掉的隧道记录，导致误判就绪。
3. `ios install --path=<ipa> --udid=<UDID>`；该命令在多数版本中会自行拉起隧道，显式管理隧道时要避免重复启动。

安装阶段会输出带 `percentComplete` 的阶段日志（5 → 100）。需要注意真正的安装阶段只有十秒量级，而之前数分钟的传输阶段**设备侧不回报进程**；进度界面在传输阶段应使用不定态进度条配合已用时计时，否则界面会长时间停在 0% 被误判为卡死。

### 3.4 长任务的流处理：进度反馈与死锁规避

两个必须同时满足的要求：既能实时拿到子进程输出，又不能用标准输入喂大流量数据时被管道写满卡住。

```csharp
// 先异步排空，再写标准输入，最后取回结果
var outTask = proc.StandardOutput.ReadToEndAsync();
var errTask = proc.StandardError.ReadToEndAsync();
// ... 分块写入 proc.StandardInput.BaseStream ...
var stdout = outTask.Result;
var stderr = errTask.Result;
```

反例是「先写完标准输入，再调用 `ReadToEnd()`」。当子进程先向标准输出写了超过管道缓冲区的内容，它会阻塞在写操作上，不再读取标准输入，双方互等形成死锁。该缺陷可以用合成子进程稳定复现：让子进程先写约 2 MB 到标准输出、再完整读取标准输入，用两种顺序各跑一次即可对比。

需要边读边刷新界面时，用 `ReadLineAsync()` 配合 `Wait(<毫秒>)` 轮询：等待期间执行计时刷新或界面重绘，读到的每一行再驱动进度解析。同理，进度回调要在后台线程与界面之间做好节流，否则 200 ms 一次的刷新会把日志窗口刷满。

### 3.5 并发与资源互斥

同一台机器上同时发起两次安装会互相抢占设备连接，症状是传输中途断开、子进程无提示退出（例如 `wsasend: An existing connection was forcibly closed`），或两次都以无关错误码失败。这类失败最难排查，因为单独重跑往往成功。

做法：安装入口用独占文件句柄建立互斥，重复进入时直接给出「已有一次安装正在进行」的明确提示，而不是排队或并行执行。同时脚本要能清理上一轮遗留的隧道/代理进程——它们会占住固定端口，导致新一轮隧道无法启动。

### 3.6 脚本宿主与 PowerShell 兼容性

以下问题与设备无关，但会直接让工具「看起来完全没反应」，属于高频排查项。

#### 3.6.1 编码

Windows PowerShell 5.1 在没有 BOM 时按系统 ANSI 代码页读取 `.ps1`，含有中文的 UTF-8 无 BOM 脚本会被截断，报出 `Unexpected token`、字符串未终止、括号不匹配等一串位置错乱且与真实行号不符的语法错误。7.x 默认按 UTF-8 读取，因此**用 7.x 验证 5.1 宿主脚本会漏报**。

处理方式二选一，优先第一种：

- 脚本保存为 **UTF-8 with BOM**；文档、配置与其他文本资源仍保持 UTF-8 无 BOM，不要为了统一而批量改写。
- 脚本内容全部使用 ASCII（界面文案改英文），彻底规避宿主差异。

写 BOM 需要显式指定编码，普通文本写入不会自动加：

```powershell
[IO.File]::WriteAllText($path, $text, (New-Object Text.UTF8Encoding($true)))
```

语法自检必须在目标宿主里执行，否则结论无效：

```powershell
powershell.exe -NoProfile -Command "[System.Management.Automation.Language.Parser]::ParseFile('<脚本>', [ref]`$null, [ref]`$errs) | Out-Null; `$errs.Count"
```

#### 3.6.2 常见语言陷阱

| 陷阱 | 现象 | 修正 |
| --- | --- | --- |
| `@('a','b','--udid=' + $udid)` | 逗号优先级高于 `+`，实际展开为 4 个元素，参数被拆成 `--udid=` 与值两段，命令返回用法帮助 | 统一用字符串插值：`"--udid=$udid"` |
| 给 `$args` 赋值 | `$args` 是自动变量，覆盖后行为不可预期 | 改用其他参数名 |
| `Test-Path 'HKCU:\...\Classes\*\shell\x'` | `*` 被当作通配符展开，遍历大量子键导致长时间无响应 | 使用 `-LiteralPath` |
| 对 `-Include` 只给目录 | 不递归时不生效，返回空集 | 与 `-Recurse`（或通配路径）配合使用 |
| 用 7.x 校验 5.1 脚本 | 编码类语法错误被漏报 | 用目标宿主的可执行文件校验 |

## 4. 风险与不适用边界

| 风险 | 典型原因 | 处理建议 |
| --- | --- | --- |
| 菜单项不出现 | 只写了注册表、未刷新外壳；或验证发生在错误的用户配置单元 | 发送关联变更通知并重启资源管理器；用 Shell API 在当前用户上下文枚举动词 |
| 菜单项重复出现 | 同一动词注册在 `SystemFileAssociations` 与 `ProgID` 两处 | 只保留一处；需要改绑程序仍生效时保留扩展名级注册 |
| 安装中途断开、无明确报错 | 并发安装、设备息屏、遗留隧道进程占端口 | 加互斥；要求设备保持亮屏解锁；安装前清理遗留进程 |
| 长任务看起来卡死 | 传输阶段无进度回调，界面长时间停在 0% | 传输阶段用不定态进度条配合计时，安装阶段再切百分比 |
| 大流量传输死锁 | 先写完标准输入再读标准输出，管道写满 | 先异步排空输出流，再写输入流 |
| 报出的错误与真实原因无关 | 直接展示设备返回的原始路径错误（如 `MissingPackagePath`） | 先核对路径语义与接口要求，再把根源写进结论 |
| 脚本在 5.1 上语法报错、7.x 正常 | 无 BOM 的 UTF-8 中文脚本 | 保存为 UTF-8 with BOM，或用目标宿主重新做语法自检 |
| 卸载/清理不彻底 | 端口与进程残留，重启后仍占用 | 提供成对的注册/注销、启动/清理脚本，并在失败路径上也执行清理 |

本参考不覆盖签名申请、描述文件生成、企业分发、设备管理策略和跨平台（macOS 宿主）流程；这些必须在目标平台和官方工具链上单独验证。

## 5. 验证与回退

### 5.1 最小验证矩阵

| 层级 | 检查 | 通过条件 |
| --- | --- | --- |
| 静态 | 用目标宿主做语法解析与自检 | 语法错误为 0，命令行参数展开数量与预期一致 |
| 环境 | 枚举设备状态；无设备时执行一次 | 给出可操作提示并非零退出，不出现未处理异常 |
| 命令行 | 对真实大包执行一次完整安装 | 传输百分比连续推进，最终返回成功并给出耗时 |
| 结果核对 | 在设备侧查询已安装应用列表 | 目标包标识与版本号确实存在，不以脚本退出码单独作为结论 |
| 菜单 | 用 Shell API 枚举动词；再人工右键确认 | 动词在列表中，且菜单中可见可点 |
| 界面 | 启动安装窗口，确认标题与设备下拉内容后关闭 | 窗口存活、设备列表正确、无异常弹窗 |
| 并发 | 在上一次未结束时再次发起 | 明确提示「已有安装进行中」，不产生第二个设备连接 |
| 失败路径 | 用不满足签名前提或已损坏的包执行一次 | 失败结论指向真实原因，且临时文件与隧道进程被清理 |

### 5.2 回退方式

1. 通过成对的注销脚本删除菜单动词与「发送到」快捷方式，并重启资源管理器恢复原菜单。
2. 脚本入口保留命令行开关（命令行模式、跳过界面、指定设备），菜单失效时可继续用命令行完成安装。
3. 工具链自带设备工具副本时，保留「先查副本、再查 `PATH`、最后查已知安装路径」的解析顺序，替换副本即可回退版本，不改脚本。
4. 出现无法复现的失败时，保留完整命令输出与设备状态记录并标记为未验证，不扩大默认行为，也不把单次成功写成通用结论。

# Unity 模型导入规则与编译快照参考

> 类型：REFERENCE；适用范围：Unity Editor 中按目录、文件名和导入器页面批量控制通用模型资源；使用前提：必须按目标项目的 Unity 版本、`ModelImporter` API、资源目录、已有导入处理器和版本控制状态重新验证。

关联 CORE：`TOOL-CMP-01`、`TOOL-ARC-01`、`TOOL-ARC-02`、`TOOL-ARC-03`、`TOOL-OPS-01`、`TOOL-OPS-02`、`TOOL-OPS-03`、`TOOL-VAL-01`、`TOOL-VAL-02`、`TOOL-VAL-03`；规范来源见 [工具开发模块](../README_Tech_TAToolDevelopmentRules.md)。

## 1. 适用场景

适用于需要让新导入模型自动遵循团队导入约定，同时允许美术按资源目录或命名覆盖部分设置的工具，例如：

- 按角色、场景、特效或外包目录设置 `Model`、`Rig`、`Animation`、`Materials` 页面。
- 按 `SK_`、`_LOD1`、`_anim` 等文件名模式选择性覆盖整页导入参数。
- 为现有模型提供“应用规则并重新导入”或单目录重新导入入口。
- 需要多人协作编辑规则，但不希望 `AssetPostprocessor` 在导入期间读写预设资产。

不适用于直接修改 FBX 源文件、重写骨架/动画数据或替代 DCC 导出器；这些需求应使用 [FBX 源数据编辑器开发参考](fbx-source-asset-editor-development.md) 的源文件回读和备份流程。

## 2. 前提与依赖

### 2.1 先确定事实来源

将三类数据职责分开：

| 数据 | 职责 | 导入回调是否读取 |
| --- | --- | --- |
| 规则预设 `ScriptableObject` | 人工编辑源、可审查的规则集合 | 否 |
| `ProjectSettings` 编译快照 | 当前工程实际生效的规范化规则 | 是，只读 |
| `ModelImporter` | Unity 对单个源模型的导入状态 | 由 `OnPreprocessModel()` 修改 |

规则系统还必须确认：目标 Unity 版本支持哪些 `ModelImporter` 属性；项目中是否已有同类 `AssetPostprocessor`；哪些目录是手动导入或第三方工具管理；哪些模型由运行时、Prefab、Animator 或构建流程消费。

### 2.2 规则对象保持可序列化且可复制

- 目录规则和文件名规则使用可序列化的纯数据类；页面设置按职责分成 `Model`、`Rig`、`Animation`、`Materials`。
- `UnityEngine.Object` 引用（例如外部 `Avatar`）不能假定会被 `JsonUtility` 深拷贝正确保留；复制后必须显式恢复引用，或改用可验证的 GUID/对象引用策略。
- 默认规则应为空或保持旧行为。不要因为安装工具就对全工程现有模型执行隐式重导入。

## 3. 实现或排查步骤

### 3.1 先冻结解析契约

建议把解析流程固定为：

```text
手动导入目录排除
    ↓
whitelist Label 排除
    ↓
启用的最深目录规则
    ↓
该目录规则中最具体的文件名规则
    ↓
按页面合并：文件名覆盖页，否则继承目录页
    ↓
只修改选中的 Model / Rig / Animation / Materials 页面
```

具体约定：

1. 资产路径统一为 `Assets/...` 正斜杠，并在比较时按项目约定处理大小写；目录匹配必须区分目录边界，不能让 `Assets/Models2` 错命中 `Assets/Models`。
2. 目录规则按路径长度选择最深匹配，不按数组顺序猜测优先级。
3. 文件名只检查文件名，不把父目录当作名称；扩展名是否参与匹配必须是显式选项。
4. 多条文件名规则同时命中时，使用可解释的特异度排序（例如排除 `*`、`?` 后有效字符更多者优先），同分保持列表顺序。
5. 文件名规则覆盖的是整页设置，而不是若干字段的隐式叠加；未勾选覆盖页时继承目录页。
6. 目录规则可以只启用文件名规则，不启用任何目录页面，以便把某个页面选择留给命名模式。

### 3.2 采用“预设源 → 编译快照”两阶段

推荐闭环：

1. 在 `ProjectSettings` UI 中只维护预设引用和只读快照展示。
2. 预设保存后执行规范化：清理空路径、统一斜杠、限制数值范围、补齐空设置对象。
3. 编译时按预设列表顺序合并规则；同一目录 Root 的后一个预设覆盖前一个预设，并记录 Warning。
4. 对合并结果做深拷贝，避免后续编辑预设时通过共享引用改变快照。
5. 计算稳定哈希并写入快照；UI 显示“已同步/预设已修改或快照不一致”。
6. 预设缺失或全部未分配时应阻止覆盖旧快照，而不是把工程规则静默清空。

导入回调只消费快照。不要在 `OnPreprocessModel()` 中加载预设、保存预设、重新生成快照或调用 `SaveAndReimport()`；这些操作会增加递归导入、顺序不确定和多人协作冲突风险。

### 3.3 将自动导入 Hook 限定在模型和有效规则

`OnPreprocessModel()` 的最小职责是：

1. 获取当前 `ModelImporter`，为空则返回。
2. 检查扩展名、手动排除目录和白名单 Label。
3. 解析最优目录/文件名规则。
4. 只写入被启用页面的 `ModelImporter` 属性。

不要因为“模型导入规则”而扫描全工程、触碰贴图或材质导入器，也不要把该 Hook 与旧的 FBX 批处理窗口耦合。若项目已有其他模型导入处理器，必须先确认调用顺序、同字段覆盖关系和禁用方式。

### 3.4 把现有资源重导入做成显式操作

- “应用预设到快照”只更新编译快照，不应默认重导入全工程。
- “应用并重新导入”应先确认影响范围，再按有效目录去重；父目录已覆盖子目录时只重导入父目录。
- 单条规则提供“重新导入此目录下的模型”入口，使用 `AssetDatabase.FindAssets("t:Model", new[] { root })` 或目标版本等效 API 收集模型，并按稳定路径排序。
- `AssetDatabase.StartAssetEditing()` 必须与 `StopAssetEditing()` 放在 `try/finally` 中；进度条、刷新和异常清理也必须成对。
- 没有有效目录或没有模型时要输出明确的跳过结果，不把空结果报告成成功。

### 3.5 用问题证据驱动修正

常见问题和处理方式：

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 规则编辑后新模型不生效 | 只改了预设，未更新快照 | 显式执行“应用预设到快照”，检查哈希和快照内容 |
| 快照与预设共享对象，编辑预设后旧快照被连带改变 | `JsonUtility`/数组引用未深拷贝 | 编译时复制规则图；对 Unity 对象引用单独恢复或按 GUID 绑定 |
| 导入时反复触发或导入顺序不稳定 | Hook 内加载/保存预设或 `SaveAndReimport()` | 回调只读快照，只改当前 `ModelImporter`，重导入放到显式菜单 |
| 目录规则误命中相似目录 | 使用简单 `StartsWith`，没有目录边界 | 统一路径后使用“等于 Root 或以 `Root/` 开始”判断 |
| 多条文件名规则结果不可解释 | 依赖数组最后一条或未定义优先级 | 固定特异度排序，同分取靠前规则，并在 UI 说明 |
| 编译错误提示 `EditorScriptableSingleton<>` 找不到 | 项目提供的基类命名空间未导入 | 读取真实程序集/API，补齐正确 `using`；不要在临时 harness 中伪造类型掩盖项目依赖 |
| 命令退出码为 0 但 Unity 测试没有结果 | 项目被另一 Unity 实例占用，进程在启动阶段退出 | 必须检查测试 XML、日志中的测试摘要和项目锁；退出码不能单独作为通过证据 |
| 全工程 `dotnet build` 出现随机 `CS2012` | 多个构建并行写同一中间文件，通常与本改动无关 | 使用隔离的最小编译 harness；不要结束用户进程或把文件占用归因于规则代码 |

## 4. 风险与不适用边界

- `AssetPostprocessor` 是项目级公开接口。即使规则只处理模型，也可能与其他处理器、插件、导入设置模板或 CI 导入顺序冲突；必须定义字段所有权和禁用/回退路径。
- `ModelImporter` 的字段和枚举会随 Unity 版本变化。静态编译通过不等于目标版本导入行为、材质生成或动画结果正确。
- `Apply and Reimport` 可能耗时很长且会改变大量导入产物；它不是逐对象可撤销操作，必须依赖版本控制、备份或限定目录回退。
- `Rig.SourceAvatar`、嵌套对象引用和导入器内部状态不能仅靠 JSON 文本验证；需要 Unity 序列化和实际导入复核。
- 不要把目录/文件名规则当成 DCC 源数据命名修复工具；命名不一致应先修源资产或提供单独的安全迁移流程。
- 默认空预设只保证“不主动改变现有模型”，不保证项目里其他历史导入器没有既有行为。

## 5. 验证与回退

最小验证矩阵：

| 范围 | 至少覆盖 | 通过条件 |
| --- | --- | --- |
| 规则解析 | 空规则、无效 Root、父子目录、大小写、文件名同分/不同分 | 结果符合固定优先级，路径边界无误命中 |
| 快照 | 预设合并、同 Root 覆盖、深拷贝、哈希、缺失预设 | 快照可重复生成；预设引用未被反向修改；缺失源不清空旧快照 |
| 导入器 | 四个页面各至少一项字段、未启用页面、白名单和手动目录 | 只改声明页面；排除项保持原导入器状态 |
| 增量流程 | 新模型导入、修改预设后只更新快照、单目录重导入、全量重导入 | 新导入自动命中；既有模型只有显式重导入才变化 |
| 工程边界 | 无关贴图/材质、其他导入器、Player 编译、BatchMode/CI、Domain Reload | 无关资源不被修改；Editor API 不进入 Player；禁用/异常可回退 |
| 资产安全 | `.meta`/GUID、材质映射、Rig/Animation 结果、空结果和异常 | 引用未丢失；日志区分成功、跳过、失败；临时状态清理 |

回退优先使用版本控制或导入前备份恢复快照和受影响资源；不要依赖再次导入来“还原”已经错误写入的导入设置。测试报告必须区分：独立编译通过、Unity Editor 编译通过、Unity EditMode 实际执行、代表性模型实际重导入，这四者不能互相替代。

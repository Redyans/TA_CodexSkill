# 按需显示的 Inspector 与可搜索属性选择器参考

> 类型：REFERENCE；适用范围：参数较多的 Unity IMGUI Inspector、材质控制器和配置工具；使用前提：以目标项目的序列化格式、Shader 接口、Unity API 和实际工作流程重新验证。
>
> 关联规则：工具模块 `TOOL-CMP-01`、`TOOL-ARC-01`、`TOOL-UI-01`、`TOOL-UI-02`、`TOOL-VAL-02`。本文给出实现选择，不新增 CORE 强制规则。具体实现与验证边界见 [ProjectACG 后处理 Timeline Profile](../../TimelineDevelopment/Profiles/ProjectACG/custom-post-processing-timeline.md)。

## 1. 适用场景

面板复杂通常有三种来源：选项难找、当前无效的参数占空间、长说明反复出现。三者分别适合搜索、条件显示、帮助折叠；仅把整块面板折起来，会让用户少看到内容，却仍然不知道去哪里找。

| 用户诉求 | 可迁移的设计方式 | 保留的诊断能力 |
| --- | --- | --- |
| 属性很多，展开菜单铺满屏幕 | 搜索框 + 限高列表 + 滚动条 | 当前选择、无结果、失效项仍可识别 |
| 只想改常用值 | 高频字段前置，次要字段分组折叠 | 收起标题显示当前值、数量或修改标记 |
| 某个模式用不到很多参数 | 根据能力、模式和前置开关显示 | 已保存的非默认配置有摘要与完整设置入口 |
| 提示占满整个面板 | 短提示放 Tooltip，长说明按需展开 | Warning/Error 独立显示 |
| 多个功能区容易混淆 | 整块浅色底 + 稳定标题 | 保持文字、禁用态和选择态的可读性 |

本文适合改造已有 Inspector。改用 UI Toolkit、虚拟列表或统一编辑器框架是另一项架构选择，不需要为了一个搜索下拉先重写整个工具。

## 2. 前提与依赖

先确定字段的消费者与作用域，再画界面。建议把参数记录成以下表格：

| 需要确认的内容 | 示例问题 | 对显示策略的影响 |
| --- | --- | --- |
| 作用域 | 这是整个片段共用，还是某个效果独有？ | 共用参数放公共区，避免误认为每个效果可独立设置 |
| 能力 | 当前材质是否声明了对应属性和所需 Pass？ | 没有能力时折叠或隐藏，并提供未知实现的回退入口 |
| 运行时条件 | 开关由材质、片段还是 Renderer 控制？ | 说明外部条件，避免“控件可见 = 已生效”的误导 |
| 模式依赖 | 自动中心开启后，手动中心是否参与计算？ | 仅在手动模式显示可编辑中心 |
| 非默认配置 | 不适用模式下是否仍有旧配置？ | 保留数据，显示“已配置/暂不生效”摘要 |
| 兼容性 | 字段是否已被旧资产序列化？ | 不为显示优化改字段名、枚举或默认输出 |
| 多选 | 多个对象的材质、模式、值是否不同？ | 混合状态不能套用第一个对象的类型和能力 |

复用附近工具的实现前，检查其程序集、Undo、搜索规模、对象引用和生命周期是否一致。相似的界面只证明可以参考交互，不证明可以整类复制。

## 3. 实现或排查步骤

### 3.1 用依赖关系建立默认视图

一种适合材质工具的顺序是：输入资源 → 常用参数 → 作用目标 → 共用配置 → 画质与性能 → 高级项 → 可选列表 → 使用说明。具体顺序随用户的操作频率调整。

建议把“是否显示”看成多个条件的组合：

`显示字段 = 完整模式 || 混合值需人工处理 || 当前能力与模式需要 || 旧配置需要被发现`

这只是设计判断式，并非所有字段共用一个布尔表达式。手动中心、失效引用、空列表等各自有不同例外。

| 依赖情况 | 默认显示建议 | 保留方式 |
| --- | --- | --- |
| 尚未选择输入资源 | 输入框与错误 | 显示已保留配置数量，先避免展示一大块无效控件 |
| 自动模式开启 | 自动开关 | 手动值保存在资产中，关闭自动后重新出现 |
| 模糊级数为零 | 模糊级数 | 隐藏采样间距，保留数值 |
| 可选列表为空 | 添加按钮 | 不先画空白大框和长说明 |
| 有内容的可选列表 | 名称、数量、折叠入口 | 条目错误可主动展开或在标题外显示 |
| 高级参数不等于默认 | “当前设置 + 已调整”摘要 | 完整模式允许检查所有保留值 |

界面隐藏不等于逻辑关闭。显示函数只管理控件；是否执行由消费者原本的逻辑决定。

### 3.2 通过能力合同显示参数

优先查公开属性、属性类型和成组 Pass，避免依赖 Shader 显示名称或文件名。显示名称可能更改，另一个 Shader 也可能实现同一合同。

能力可以是局部的位标记或小型描述对象：是否支持形状输入、是否需要中间纹理、是否支持一对模糊 Pass。多个效果共享设置时，使用能力并集；任意一个效果需要的公共参数都可访问。若同一 GUI 事件改变了模式，后续画质区重新计算能力，避免等下一次事件才更新。

能力推断的边界：

- 属性存在不代表当前渲染分支使用它；还要考虑模式、数值与外部开关。
- 一组功能要求多个 Pass 时，单个 Pass 存在不能证明完整支持。
- 自定义 Shader 可能使用工具未知的合同。提供“显示全部设置”，必要时再增加显式 Adapter。
- 能力探测本身只服务于界面，不代替 Renderer、Shader 变体和最终画面的检查。

### 3.3 用折叠摘要保留信息

好摘要回答“现在配置成什么样”。例如：`作用目标 · 跟随绑定 + 额外对象 2 个`、`画质 · 对象 0.5 / 模糊 2 级（已调整）`、`亮度 · 曲线 × 3`。单写“高级设置”不能帮助定位隐藏的非默认值。

名称作为折叠标题展示，需要时通过“改名”显示输入框。属性类型可由 Shader 推导时，默认省去重复选择；类型不匹配、混合值和完整模式下再显示修正控件。

折叠和帮助状态可放在 Editor 实例字段、集合或 `SerializedProperty.isExpanded` 中。仅为“展开/收起”新增运行时字段会扩大资产格式和维护成本。基于数组路径保存状态时，删除或重排会改变路径，应接受状态重置或另用稳定身份；它不适合作为业务身份。

### 3.4 分开处理帮助与诊断

| 信息类别 | 默认呈现 | 展开后的内容 |
| --- | --- | --- |
| 字段含义、单位、简单公式 | Tooltip | 通常不需要额外大框 |
| 连贯的使用说明 | “说明/使用帮助”入口 | 详细步骤、前置条件、限制 |
| 当前不可执行的错误 | 直接显示 | 具体对象、原因和修正入口 |
| 可能影响结果的告警 | 紧邻相关组显示 | 风险与可选处理 |

诊断代码与字段绘制分开，使组或控制器收起后仍能发现缺材质、缺属性、类型不匹配和失效筛选。默认收起普通说明不意味着把全部 `HelpBox` 一次性关闭。

点击某组“说明”时，可同时打开解释所对应的目标区；否则用户看到了说明，却找不到它说的控件。

### 3.5 搜索选择器保留显示名和真实标识

在 `EditorGUI.DropdownButton` 上打开 `PopupWindowContent`，把一次选择组织成以下流程：

1. 打开时收集受支持属性，过滤系统独占字段，建立内置属性名和描述文本的对应关系。
2. 行文本用“描述（内部名）”；持久化只写内部名，避免文案改名破坏绑定。
3. 搜索同时覆盖描述和内部名；对查询去空白、忽略大小写。
4. 窗口高度限制为少量可见行；列表可滚动，必要时固定显示竖向滚动条。
5. 显示当前选中项高亮、无结果信息和清除入口。清除时重置滚动位置并恢复搜索焦点。
6. 选择后写回属性并关闭；Escape 关闭且不改数据。

选项数量非常大时，再考虑索引缓存、延迟过滤或虚拟化。普通 Shader 属性列表通常不值得引入全局搜索系统。

当前绑定失效时保留原名称并提示。绘制下拉时自动选第一项，容易把“资产暂时不能解析”转成真正的错误写入。

### 3.6 异步弹窗回调重新定位序列化对象

弹窗选择通常发生在之后的 GUI 事件中。不要长期保存数组元素的 `SerializedProperty` 迭代器；可以保存属性路径，回调中按以下顺序处理：

`检查 Editor 与目标仍有效 → serializedObject.Update → FindProperty → 验证元素/当前资源 → 写入 → ApplyModifiedProperties → 请求必要刷新 → Repaint`

路径重新查找解决的是迭代器失效，不保证元素身份稳定。弹窗打开后如果允许列表重排、删除或切换材质，需要增加身份/资源一致性校验，或关闭弹窗后再进行结构操作。

弹窗已写回后，下一次 Inspector 的 `ApplyModifiedProperties()` 可能返回 false。跨事件记录变更时采用累积语义，例如 `changed |= ApplyModifiedProperties()`，避免覆盖尚未消费的变更。派发刷新后清零；单纯帮助折叠不应触发业务刷新。

### 3.7 防止 Repaint 修改资产

自绘 Toggle、枚举和筛选器采用 `BeginChangeCheck/EndChangeCheck`，仅用户明确修改时赋值。否则用 `旧 float > 阈值` 绘制勾选框后，每次回写 0/1，会在用户没点击时抹掉历史小数。

多选值采用 `hasMultipleDifferentValues` 与 `EditorGUI.showMixedValue`，并恢复原 GUI 状态。不同 Shader 的属性类型或属性集合不一致时，可以使用保守的数值编辑或完整视图；不要根据第一个材质强制统一全部对象。

数组还涉及两个常见边界：

- `arraySize++`/插入元素可能复制上一项的序列化内容。新元素的曲线、类型、数值和引用按明确默认值初始化。
- 对象引用数组的删除可能先置空、再次调用才真正移除。删除前后比较 `arraySize`，必要时再删；不要无条件调用两次。

### 3.8 整块分组着色与窄面板布局

在容器的 Repaint 阶段、绘制子控件之前，用 `EditorGUI.DrawRect` 为组绘制浅底色。保留边框，分别检查明暗主题。直接改全局 `GUI.color` 或 `GUI.backgroundColor` 可能连文字、按钮、禁用状态一起染色。

纯色背景通常无需每次创建 `Texture2D`。IMGUI 的容器 rect 取值和绘制时机依赖实际布局，编译成功不能证明背景完整覆盖；真实 Inspector 内检查折叠、窄宽度和长标题。

曲线与数值在宽面板并排，窄面板换行。临时修改 `EditorGUIUtility.labelWidth`、缩进或混合值状态后，通过作用域或 `try/finally` 恢复，避免后续控件串位。

## 4. 风险与不适用边界

| 风险 | 原因 | 应对与回退 |
| --- | --- | --- |
| 隐藏了用户需要的参数 | 能力合同不完整、未知 Shader、外部渲染开关 | 完整设置入口、保留摘要、逐步完善 Adapter |
| 收起后看不到错误 | 校验放在被提前 return 的绘制分支内 | 诊断单独调用，检查每个提前返回位置 |
| 编辑后跳到别的条目 | 用数组路径代替稳定身份 | 校验身份/资源，或限制弹窗期间的结构编辑 |
| 面板一打开资产就变了 | 每次重绘回写枚举、0/1 或自动类型 | 变更检查；对照打开前后序列化与 Dirty 状态 |
| 多选覆盖各自配置 | 以第一个对象推断类型或默认值 | 混合状态、完整视图、仅显式操作写入 |
| OnGUI 成本不断增长 | 每次探测、扫描、分配或加载资源 | 先测量；缓存按 Shader/资源变更失效，不先建立全局框架 |
| UI 状态串到其他条目 | 路径型 HashSet 随删除重排变化 | 允许状态重置，业务数据不依赖其身份 |

## 5. 验证与回退

| 类别 | 代表性操作 | 预期 |
| --- | --- | --- |
| 搜索 | 中文描述、内部名、大小写、空查询、无结果、长列表 | 搜索可定位、滚动可用、选择写入真实标识 |
| 依赖显示 | 各模式、前置开关、未知材质、多个效果能力并集 | 只呈现相关字段，完整模式可恢复访问 |
| 帮助诊断 | 开关说明、收起错误组、缺属性、失效引用 | 帮助默认不占空间，错误仍可发现 |
| 序列化 | 打开、折叠、Repaint、Undo/Redo、新增、删除、重排 | 无无意写入，默认值正确，已有值不丢失 |
| 多选 | 不同资源、模式和值的混合选择 | 不把首对象值覆盖给其他对象 |
| 视觉 | 明暗主题、窄宽度、长标题、大列表 | 背景和控件可读，无横向溢出和布局报错 |
| 生命周期 | 切换选择、关闭 Inspector、重载脚本、弹窗未关闭时改列表 | 不持有无效对象，不误改其他条目 |
| 渲染关联 | 修改字段后检查运行时消费者 | UI 简化前后结果与参数语义一致 |

下一次实现可先写一页参数依赖表，再做一个效果和一个控制器的最小闭环。只有发现多个工具共享稳定行为时，再抽取搜索 Popup 或能力 Adapter；不按相似外观提前建大框架。

回退时先禁用条件隐藏、启用完整视图，检查数据是否仍在，再定位显示条件。数据语义修改与面板折叠分开回退，避免为了恢复可见性撤销资产格式。

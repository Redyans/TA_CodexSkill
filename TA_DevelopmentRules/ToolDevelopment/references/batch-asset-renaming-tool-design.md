# Unity 批量资源重命名工具设计参考

> 类型：REFERENCE；适用范围：Unity Editor 中对 Asset、Prefab、Scene GameObject 和可重命名子资源执行批量命名转换的工具；使用前提：必须以目标项目的 Unity 版本、资产类型、序列化方式、Undo 能力和构建流程重新验证。
>
> 关联规则：`TOOL-CMP-01`、`TOOL-ARC-01`、`TOOL-UI-01`、`TOOL-OPS-01`、`TOOL-OPS-02`、`TOOL-ORG-01`、`TOOL-VAL-01`、`TOOL-VAL-02`。

## 1. 适用场景

本参考适用于以下批量重命名需求：

- 从当前选择、指定目录或已有列表收集资源，并按类型筛选、排序、去重。
- 组合多个字符串操作，例如删除、替换、截取、插入、编号、规范化和名称片段重排。
- 在真正写入前预览每一步结果、非法名称、重复名称和已有资产冲突。
- 对 Asset、GameObject、Sprite 等不同对象走各自的写入与 Undo 路径。
- 保存操作预设，并在新增功能后继续读取旧预设。
- 为内部 TA 工具提供中文 UI，同时保留其他语言回退。

以下需求不应混入普通手动重命名窗口：

- 无条件监听全工程导入并自动改名。
- 修改 Addressables/YooAsset 地址、资源 GUID、脚本类型名或序列化引用。
- 重命名 Shader Property、Keyword、Animator 参数、Timeline 绑定键或代码符号。
- 需要跨仓库、跨版本控制分支或外部 DCC 同步的迁移任务。
- 无法预览、无法确认且失败后难以恢复的大规模文件系统移动。

资源“显示名称”、资产文件名、扩展名、子资源名、Hierarchy 节点名和外部路径是不同契约。工具开始实现前必须明确本次修改的是哪一层，不能因为它们在 Inspector 中都显示为 `name` 就共用同一写入方式。

## 2. 前提与依赖

### 2.1 冻结重命名契约

实现前先确认以下决策：

| 维度 | 必须明确的问题 |
| --- | --- |
| 输入来源 | 当前 Selection、拖拽列表、指定目录、递归子目录分别是否支持？ |
| 对象类型 | Asset 主资源、Sprite 子资源、Prefab、Scene GameObject、文件夹是否允许？ |
| 名称边界 | 是否保留扩展名？是否只改 `Object.name`？子资源名如何写回？ |
| 操作顺序 | 多个操作是否严格按列表顺序组合？编号使用原始顺序还是排序后顺序？ |
| 冲突作用域 | Asset 同目录、GameObject 同父节点、批次内部重复分别如何判断？ |
| 冲突策略 | 跳过冲突、发现任一冲突停止全部、自动追加编号，默认采用哪一种？ |
| 非法结果 | 空名称、非法字符、首尾空白、Windows 保留名、未变化名称如何展示？ |
| 兼容性 | 旧预设、序列化类型名、默认值和操作顺序是否保持？ |
| 回滚 | GameObject Undo、Asset Rename Undo、Sprite 导入写回分别由谁负责？ |
| 验证 | 纯字符串、预览、真实资产、Undo、Domain Reload 和窄窗口分别如何测？ |

只要上述任一项尚不明确，就不应直接进入批量写入。先让预览模型表达清楚，再决定按钮是否可执行。

### 2.2 建立分层而非堆叠条件分支

推荐职责如下：

| 层 | 职责 |
| --- | --- |
| Collection | 从 Selection、目录和拖拽列表收集对象，过滤、去重、排序，不修改资源。 |
| Operation Model | 保存一个字符串转换的配置、校验、纯逻辑执行和克隆语义。 |
| Operation Drawer | 只绘制并编辑对应 Operation，不直接重命名对象。 |
| Sequence | 按顺序组合 Operation，生成每一步结果，并负责预设序列化。 |
| Preview | 把对象、原名、每步结果、最终路径、警告和冲突组成可观察计划。 |
| Conflict Resolver | 在写入前统一处理批次内、已有资产和同级 GameObject 冲突。 |
| Executor | 只消费已确认的无冲突计划，分类执行 Asset、GameObject 和子资源写入。 |
| Undo/Report | 记录撤销边界、进度、成功、失败、跳过和可定位原因。 |

UI 窗口只协调这些状态。不要让 `OnGUI` 直接扫描全工程、改资源、猜冲突或拼接持久化格式。

### 2.3 先确认目标项目的 Unity 边界

- 工具必须位于 `Editor` 目录或 Editor-only asmdef。
- 使用 `AssetDatabase.RenameAsset` 前确认对象是可写主资产，而不是只读 Package 或不支持直接改名的导入子资源。
- Sprite、模型子资源和自定义 Importer 的名称可能由导入设置生成，不能等同普通 Asset。
- GameObject 冲突通常按同一父节点判断；如果团队允许同级同名，也应把策略写清。
- 文件系统非法字符、平台保留名和大小写行为应按团队目标平台验证，不能只以当前 Windows 机器为唯一事实。
- `.csproj` 属于 Unity 生成产物。新增脚本后应让 Unity 刷新工程；不要手工把 Compile Item 写入并提交。

## 3. 实现或排查步骤

### 3.1 把一次批量改名建模为状态转换

推荐模型：

- State：对象列表、收集规则、排序、操作序列、编号分组、冲突策略、预览和执行结果。
- Input：Selection/目录快照、Drawer 参数变化、拖拽、排序命令和用户确认。
- Transition：收集 → 规范化顺序 → 应用操作序列 → 校验 → 解决冲突 → 确认 → 写入 → 汇总。
- Effect：Asset 重命名、GameObject `name` 修改、Sprite 导入设置写回、Undo 记录和资源刷新。
- View：操作列表、逐步 Diff、最终名称、警告、冲突、按钮可用状态和执行汇总。

预览与执行必须共享同一份 Operation Sequence、编号输入和冲突解析结果。若执行阶段重新计算另一套名称，用户看到的预览就不再是写入契约。

### 3.2 设计可扩展的字符串 Operation

一个可进入序列和预设的 Operation 至少应提供：

1. 配置校验：非法正则、空查找串、越界长度、无效索引和非法规则格式在执行前暴露。
2. 纯转换：输入名称与相对计数决定输出，不访问 Selection、AssetDatabase 或窗口状态。
3. 结构化结果：除了最终字符串，还能表达相等、插入和删除片段，供逐步预览使用。
4. 克隆：Drawer 原型、添加操作和预设加载不能共享同一个可变实例。
5. 默认值：新增字段必须有旧预设反序列化时安全的默认行为。
6. 等价语义：若窗口用 `Equals`/`GetHashCode` 判断配置变化，新字段必须同步参与。
7. 稳定持久化：不要把本地化后的菜单文字作为新预设的主身份；优先使用稳定 ID 或稳定类型标识。

新增一个操作时，通常需要同步以下位置：

- Operation 模型。
- 对应 Drawer。
- 窗口的 Operation/Drawer 原型注册。
- Operation Sequence 的反序列化类型映射或稳定 ID 映射。
- 中英文显示文本、字段标签、选项、错误提示和帮助文本。
- 纯逻辑测试、非法输入测试、预设保存/加载和克隆测试。
- 新脚本 `.meta` 与目标 asmdef/csproj 的实际编译覆盖。

只完成模型和 Drawer 会出现“界面能选但预设无法恢复”；只完成序列映射则可能出现“旧预设能读但菜单里无法添加”。接入清单必须作为一个整体验证。

### 3.3 按语义拆分常用字符串操作

不要用一个拥有大量互斥 Toggle 的“万能字符串操作”覆盖所有需求。更易理解的分类如下：

| 类别 | 典型操作 | 关键边界 |
| --- | --- | --- |
| 边界删除 | 从开头/末尾删固定字符数；删除指定前缀/后缀；从两端 Trim 字符集合。 | 字符数越界、空字符串、大小写、只匹配一次。 |
| 指定字符串删除 | 删除第一处、最后一处或全部匹配；限定任意位置/开头/末尾。 | 查找串为空、重叠匹配、大小写和正则转义。 |
| 替换 | 普通替换、正则替换、多行 `旧=>新` 映射。 | 非法正则、非法映射行、规则顺序、只替换第一处。 |
| 插入与截取 | 按正向/倒序索引插入；保留前 N、后 N、区间或分隔符之间内容。 | 索引定义、负索引、连接符、越界回退。 |
| 编号 | 前缀、后缀、指定位置插入；十进制/字母；按全局、文件夹、类型重置。 | 排序决定计数；从末尾索引要有独立选项；旧默认不变。 |
| 结构规范化 | 统一 `_`、`-`、空格等分隔符；合并连续分隔符；清理首尾。 | 不要误改扩展名、负号或业务缩写。 |
| 命名风格 | PascalCase、camelCase、snake_case、kebab-case 等。 | 单词拆分规则、连续大写缩写、数字边界。 |
| 后缀清理 | 删除 Copy、Instance、Clone、数字副本等常见尾缀。 | 只在边界匹配；避免删除名称中间的合法词。 |
| 括号处理 | 删除括号及内容，或只删除括号；支持多种括号。 | 嵌套、不配对括号、全角符号和合法 Mask 位。 |
| 资源名清洗 | 全角规范化、非法字符替换、空白与重复替换符合并、保留名修正。 | 目标平台差异、替换字符自身是否合法、结果为空。 |
| 长度限制 | 保留开头、末尾或首尾，中间使用连接符。 | 最大长度小于连接符、代理对/组合字符、结果冲突。 |
| 片段重排 | 按分隔符拆分，使用索引或负索引重排。 | 重复索引、缺失片段、非法整数、空片段策略。 |

操作顺序本身属于业务语义。例如“先清洗非法字符再按分隔符重排”和反向执行可能产生不同结果。UI 应让顺序可见、可调整，并在预览中展示每一步，而不是把所有规则并行应用到原名。

### 3.4 处理字符串边界时优先显式语义

实践要点：

- “删除前 3 个字符”和“删除前缀 `Tex_`”不是同一操作；前者按长度，后者应先确认实际匹配。
- “指定字符串删除”应让用户选择匹配位置、出现次数和大小写，而不是隐式采用 `string.Replace` 的全部替换语义。
- 多规则替换按输入顺序执行，并在 UI 中明确每行格式。非法行应让 Operation `HasErrors()`，阻止批量执行。
- 正则只是可选高级模式。普通字符串必须先 `Regex.Escape`，避免 `.`、`[` 等字符被误当表达式。
- 倒序索引必须有清晰定义。例如 `-1` 表示最后一个词段，或“插入位置从末尾计算”；不要在不同操作中复用不同含义。
- 长度限制若按 C# `char` 计数，会拆分 Emoji、代理对或组合字符。需要支持多语言名称时，应改用文本元素/字素簇并增加专项测试。

### 3.5 收集、筛选与排序保持确定性

目录收集推荐步骤：

1. 用 `DefaultAsset`/ObjectField 选择文件夹，由 `AssetDatabase.GetAssetPath` 取得路径。
2. 验证 `AssetDatabase.IsValidFolder`。
3. 使用 `AssetDatabase.FindAssets` 获取 GUID，再转路径。
4. 排除文件夹、空路径和重复路径。
5. 非递归模式比较规范化后的父目录路径。
6. 加载主资产并按显式类型 Mask 过滤。
7. 将结果加入唯一列表，再按当前排序策略统一排序。

排序和编号必须绑定同一个对象顺序。支持“按名称自然排序、资产路径、资产类型、降序”时，预览和执行都应消费排序后的同一列表；不要在添加、预览和写入阶段分别排序。

类型筛选应有 `Other` 兜底，但 `All` 必须由所有合法标志位按位组合，不能使用 `~0` 把未来或非法位带入序列化。MaskField 写回后也应与合法位掩码相与。

### 3.6 冲突检查必须覆盖三个作用域

批量重命名至少检查：

1. 批次内多个对象得到同一最终名称。
2. Asset 最终路径与同目录已有资产冲突，比较时保留原扩展名和规范化路径。
3. GameObject 最终名称与相同父节点/场景根作用域中的现有同级对象冲突。

计算时先把本批次原路径从“已有路径集合”中移除，再按最终结果重新预留。未变化对象应先预留原名，避免把警告错误地标到保留原名的一方。

常见冲突策略：

| 策略 | 行为 | 适用场景 |
| --- | --- | --- |
| 跳过冲突 | 预览保留警告；执行时跳过冲突项，其余继续。 | 批次大、允许部分成功。 |
| 停止全部 | 任一阻断问题存在时禁用或中止整个执行。 | 要求批次原子性或命名完整性。 |
| 追加编号 | 按确定顺序尝试 `_1`、`_2`，每确定一个名称立即加入预留集合。 | 用户接受自动消歧，且命名规范允许数字后缀。 |

自动编号解析必须先处理未变化对象，并使用稳定的输入顺序。否则相同对象集因 Selection 顺序不同会获得不同名称，预设和日志难以复现。

### 3.7 使用临时名称解决交换与环形改名

以下操作不能直接依次写最终名：

```text
A -> B
B -> A
```

第一个写入会先撞上仍存在的 `B`。安全流程是：

1. 预览阶段确认最终路径集合无外部冲突。
2. 对会占用彼此名称的 Asset 先改为批次内唯一临时名。
3. 所有占位完成后再改为最终名。
4. 临时名不得与已有资产、目标名或其他临时名冲突。
5. 任一步失败时记录已完成边界，并按 Undo/版本控制策略回退。

实例 ID 可以作为编辑器会话内的临时占位组成部分，但不要把它作为持久名称或跨会话身份。

### 3.8 预览警告要区分“提示”和“阻断”

建议至少区分：

- 空名称。
- 首尾空白。
- 非法字符或平台保留名。
- 与已有 Asset 或批次结果冲突。
- GameObject 同级冲突。
- 结果未变化。
- Operation 配置错误。

“未变化”通常是可跳过提示，不应与空名或冲突一样阻断整个批次；但统计中应单独计数。执行按钮的禁用条件应读取统一的 `HasBlockingIssues`，不要在窗口、预览和执行器中各写一份不同判断。

预览应显示每一步 Diff 与最终名称。复杂操作若只返回最终字符串，用户难以定位是哪一步删除或插入了错误内容。

### 3.9 Asset、GameObject 与子资源分别执行和撤销

执行前先分类：

- GameObject：使用 Unity Undo 记录对象后写 `name`。
- Asset 主资源：使用 `AssetDatabase.RenameAsset`，并保留可恢复的旧路径/新路径记录。
- Sprite 或导入子资源：通过对应 Importer/元数据写回；不能假设普通 Undo 会覆盖。

批量执行应显示进度并在 `finally` 清理进度条。若引入 `StartAssetEditing`，必须 `try/finally` 配对；只有实际能减少导入次数时才使用。

不要把“调用了 Undo API”等同“所有副作用可撤销”。真实验证需要执行：改名 → 检查路径/GUID/引用 → Undo → Redo → 重开窗口或重新导入。

### 3.10 IMGUI 绝对坐标必须保持同一坐标系

在非 GUILayout 的 `Rect` 布局中，子控件位置必须包含父矩形原点。例如：

```csharp
labelRect.y = previewRect.y + previewRect.height * 0.5f - labelRect.height;
```

如果只写 `previewRect.height * 0.5f`，当预览区上方新增工具栏、筛选面板或 Foldout 后，提示仍按窗口顶部坐标绘制，会覆盖上方 UI。

新增面板时同步检查：

1. 面板实际高度。
2. 后续区域的 `y` 起点。
3. 后续区域的可用高度。
4. 空状态、滚动内容、Footer 和按钮是否都使用传入 Rect 的 `x/y`。
5. Dock 后小于 `minSize` 的窗口是否出现负高度。

只把横幅文字设为空或把条件设为 `false`，仍可能保留空白高度。移除一个 UI 区域时应同时删除状态、绘制调用、布局预留和失效按钮回调。

本地化文本长度不同，固定四等分按钮很容易在窄窗口重叠。至少验证中文、英文、最小浮动宽度和 Dock 窄宽；必要时使用两列/单列响应式布局、短命令文本或带 Tooltip 的图标按钮。

### 3.11 本地化修改要验证数据结构而不是根节点数

若语言 JSON 结构是：

```json
{
  "name": "...",
  "key": "...",
  "version": 1,
  "elements": [
    { "key": "...", "value": "..." }
  ]
}
```

验证时应统计 `elements[].key`，而不是根对象只有几个字段。建议检查：

- 每份 JSON 能以 UTF-8 解析。
- 同一语言内没有重复 key。
- 基准语言与主要目标语言 key 集合完全一致。
- 次要语言缺失键时存在可验证的英文回退。
- 新 Drawer 引用的每个 key 都能在基准语言找到。
- 若语言系统依赖版本更新，修改内容后同步提升版本。

代码中不要内置中文 fallback 替代语言表。缺失键回退到稳定基准语言，再回退到 key 本身，便于发现遗漏。

### 3.12 预设兼容优先保持类型和字段稳定

使用 `JsonUtility` 按类型序列化 Operation 时：

- 重命名或移动类型可能使历史类型字符串无法解析。
- 删除字段会丢失旧配置；新增字段使用 C# 默认值，必须确认默认值符合旧行为。
- 枚举值不要重排；追加新值放在末尾或显式赋值。
- 新增布尔开关默认 `false` 往往更能保持旧行为，但需逐项判断。
- Operation 的 `Clone`、`Equals`、`GetHashCode`、`Reset` 和序列化字段必须同步。

旧格式若用本地化菜单路径作为键，只能作为兼容读取层保留；新格式应迁移到稳定 ID。切换语言后仍要验证旧预设是否能读。

### 3.13 编译验证要覆盖 Unity 尚未写入 csproj 的新文件

新增脚本后常见情况是 Unity 生成的 `.csproj` 尚未刷新。此时直接 `dotnet build` 可能完全漏编新文件，或因窗口已引用新类型而产生误导错误。

推荐顺序：

1. 优先让 Unity Editor 导入并由 Bee 编译目标程序集。
2. 确认 `Library/ScriptAssemblies/<Assembly>.dll` 在最后一条相关 C# 错误之后重新生成。
3. 若必须用 dotnet 补验，可通过临时 MSBuild targets 注入尚未列入的源文件。
4. 构建结束立即删除临时 targets，不修改、不提交 Unity 生成的 `.csproj`。
5. Unity 刷新 `.csproj` 后再运行普通 `dotnet build`，目标是 `0 warning / 0 error`。

仅看到历史 `Editor.log` 中有错误或成功都不够。需要比较日志顺序和文件修改时间，确认最终成功发生在本轮源码修改之后。

## 4. 风险与不适用边界

| 现象或风险 | 常见根因 | 推荐解决方式 |
| --- | --- | --- |
| 空状态文字覆盖筛选区 | 子 Rect 只使用高度，没有叠加父 Rect 的 `x/y`。 | 全部绝对坐标以传入区域原点计算；新增上方面板后重点复测空状态。 |
| 删除横幅后仍有空白 | 只取消绘制，Footer 高度和按钮定位仍引用横幅 Rect。 | 同时删除状态、绘制、预留高度和回调，让后续控件直接依赖预览区边界。 |
| 预览无冲突，执行却失败 | 预览和执行使用不同顺序、路径规则或冲突集合。 | 执行只消费最终预览计划；冲突解析结果不可二次猜测。 |
| A/B 交换名称失败 | 直接按最终名顺序写入。 | 先改唯一临时名，再统一写最终名。 |
| 自动编号每次不同 | Selection 顺序不稳定或未变化对象后处理。 | 执行前稳定排序；未变化结果先预留；逐个确定并预留候选名。 |
| 删除指定字符串误删过多 | 隐式使用全部替换，未定义出现次数和位置。 | 把位置、次数和大小写做成显式配置并预览。 |
| 正则字符导致异常 | 普通文本直接传给 Regex。 | 普通模式转义；正则模式提前编译校验并阻止执行。 |
| 名称清洗后为空或再次冲突 | 多步规范化没有最终校验。 | 所有操作完成后统一做空名、非法字符、保留名和冲突检查。 |
| 旧预设丢字段或无法加载 | 类型名、枚举顺序、字段名或默认值变化。 | 保持序列化身份稳定；追加字段；建立旧预设回归样本。 |
| dotnet 编译通过但 Unity 报错 | csproj 漏掉新文件，或 Unity/Editor 条件编译不同。 | 以 Unity 实际程序集编译为主，dotnet 仅补充；检查 Compile Item 覆盖。 |
| 语言键数量检查错误 | 只数 JSON 根字段，没有读取 `elements`。 | 解析结构后统计叶子 key、重复 key 和基准语言差异。 |
| Undo 后资产状态不一致 | Asset/Sprite 写入不在普通对象 Undo 覆盖范围。 | 对不同对象分类记录 Undo；真实执行 Undo/Redo 和重新导入验证。 |
| 拖入父子 GameObject 后重复计数 | 只按路径或名称去重，没有按对象身份。 | 用对象引用/稳定 ID 去重，排序与显示来源另存。 |
| 改动混入大量脏工作区内容 | 使用仓库级 stage、回退或格式化。 | 修改、验证和提交都限定到工具路径；不得重置无关改动。 |

本参考不承诺跨平台文件名规则完全一致。目标项目若发布到区分大小写的文件系统、移动设备、主机或外部内容管线，需要增加对应名称、编码、长度和保留字测试。

## 5. 验证与回退

### 5.1 最小验证矩阵

| 层级 | 代表性用例 | 通过条件 |
| --- | --- | --- |
| 纯 Operation | 空串、短串、越界、大小写、非法正则、负索引、多条映射、括号不配对。 | 不抛未处理异常；错误配置可阻止执行；输出符合显式语义。 |
| Operation 组合 | 删除 → 规范化 → 重排 → 编号；调换操作顺序。 | 每一步 Diff 和最终名一致；顺序变化可观察。 |
| 克隆/等价 | 添加 Operation 原型、复制、修改新字段、Reset。 | 实例不共享状态；新字段参与等价与默认行为。 |
| 预设 | 保存/加载所有新操作；读取旧预设；切换语言后读取旧格式。 | 类型、字段、顺序和默认值保持；未知/损坏项有明确失败。 |
| 收集 | 空目录、非递归、混合类型、重复对象、父子 GameObject、只读资源。 | 数量、筛选、去重和排序正确；不在收集阶段写资源。 |
| 编号 | 全局、按目录、按类型；升序/降序；从末尾插入。 | 编号顺序与预览列表一致；旧预设默认行为不变。 |
| 冲突 | 批次内同名、已有 Asset、同级 GameObject、未变化名称、自动编号链。 | 跳过/停止/编号三策略可预测，按钮状态和执行一致。 |
| 环形改名 | A↔B、A→B→C→A。 | 临时名阶段无外部冲突，最终名称全部正确。 |
| Asset 写入 | Prefab、Material、Texture、普通文本资产。 | 文件名、扩展名、GUID、引用和导入状态符合契约。 |
| 子资源 | Sprite/自定义导入子资源。 | 使用正确写入路径；主资产和其他子资源不被误改。 |
| Undo/Redo | GameObject、Asset、Sprite 分别改名后 Undo/Redo。 | 可恢复项完整恢复；不可完整撤销项已明确并可用版本控制回退。 |
| IMGUI | 空列表、有列表、展开/折叠、窄 Dock、中文/英文、Domain Reload。 | 无重叠、负高度、截断到不可操作或隐形占位。 |
| 编译 | Unity Bee、普通 dotnet、临时注入缺失文件的 dotnet。 | 最终目标程序集在本轮修改后生成；临时文件清理；不提交 csproj。 |
| 本地化 | 所有 JSON UTF-8 解析、key 去重、基准语言对齐、回退。 | 主要语言 key 集一致；缺失键回退可控；无硬编码显示 fallback。 |

### 5.2 建议的验证顺序

1. `git diff --check` 与目标路径状态检查。
2. 纯字符串行为测试和非法输入测试。
3. 本地化结构、重复键和主要语言键集合检查。
4. Unity/目标程序集编译，确认新脚本进入编译输入。
5. Unity 中打开真实窗口，检查空状态、窄窗口、操作 Drawer、预设和冲突提示。
6. 在隔离目录复制代表性资产，执行真实批量改名。
7. 检查扩展名、GUID、引用、Sprite/Importer、Undo/Redo 和重新导入。
8. 用接近真实规模的目录验证扫描、预览和执行耗时。

### 5.3 回退与未验证项

正式资源批量改名前应确保版本控制工作区可回退，或先在资产副本/隔离目录执行。对 Asset 文件移动、Importer 子资源、外部文件和大批量操作，不应只依赖 Unity Undo。

迁移本参考到其他项目时，需要重新确认：

- Unity 版本、目标平台文件名限制和大小写行为。
- 资源包、只读目录、自定义 Importer 和 Sprite 写回方式。
- 预设格式、类型解析和本地化回退策略。
- 项目对同级 GameObject 重名、自动编号格式和扩展名的规范。
- 实际 Unity 编译、窗口布局、资源引用和 Undo 验证入口。

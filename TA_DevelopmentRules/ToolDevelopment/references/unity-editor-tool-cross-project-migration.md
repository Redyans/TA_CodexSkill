# Unity Editor 工具集跨工程迁移与旧件下线参考

> 类型：REFERENCE；适用范围：把以 Editor 窗口为主、可整体拷贝的 TA 工具目录从源工程迁移到目标工程，并处理目标工程的同名工具、旧版运行时组件与冗余示例资产；使用前提：必须以目标工程的 Unity 版本、程序集、`.meta`/GUID、菜单、序列化状态和版本控制状态重新验证。
>
> 关联规则：`TOOL-CMP-01`、`TOOL-ARC-02`、`TOOL-DOC-03`、`TOOL-OPS-01`、`TOOL-OPS-02`、`TOOL-VAL-01`、`TOOL-VAL-03`。项目实例见 [ProjectACG 网格地形与地表工具集 Profile](../Profiles/ProjectACG/mesh-surface-terrain-toolset.md)；无 Unity 宿主时的编译校验见 [Unity Editor 脚本离线编译校验参考](unity-editor-script-offline-compile-verification.md)。

## 1. 适用场景

本参考适用于：工具本体由 Editor 窗口、编辑器数据类、Shader/贴图/文档组成，没有 Player 消费者；可以按目录整体拷贝；不需要改 asmdef、包名或寻址地址；目标工程里可能有同类工具的旧版本或旧版运行时组件。

不适用于：工具含必须在 Player 运行的组件；旧组件序列化数据必须先由工具读回再删除；需要改 asmdef/包依赖方向；需要 Unity 内序列化迁移（`FormerlySerializedAs`/`ScriptUpdater`）；需要迁移 Addressables/YooAsset 地址或脚本裸路径。

## 2. 前提与依赖

### 2.1 迁移单位是「目录 + 该目录下全部 `.meta`」

| 成员 | 作用 | 处理要求 |
| --- | --- | --- |
| `.cs` + `.cs.meta` | MonoScript、菜单、程序集成员、GUID。 | 成对复制，禁止让 Unity 目标端重新生成 `.meta`。 |
| `.shader` / `.mat` / `.png` / `.asset` | 预览、笔刷、默认数据。 | 同上；引用靠 GUID 保持。 |
| `.unity` / `.prefab` 示例 | 演示与回归。 | 只有确认属于工具本体时才随代码迁移，见 3.6。 |
| `README` / `Usage` / `.md` | 说明与路径示例。 | 复制后必须改写其中的旧路径（见 3.2）。 |
| 目录自身的 `.meta` | 目录 GUID。 | 可复制也可由目标工程生成；只要该目录 GUID 未被目标资产引用即可。 |

### 2.2 复制前的四项冲突预检

| 检查项 | 方法 | 通过条件 |
| --- | --- | --- |
| GUID 冲突 | 取源侧全部 `.meta` 的 `guid:` 与目标工程全部 `.meta` 的 `guid:` 求交集。 | 交集为空才允许原样复制 `.meta`。 |
| 类型全名冲突 | 比较两侧声明的 `class`/`struct`/`enum`/`interface`；同名时继续比命名空间与所在程序集。 | 同名同命名空间必须去重，见 3.3；不同命名空间的同名只是提醒。 |
| 菜单冲突 | 比较 `MenuItem("...")` 字符串与由常量拼出的菜单路径。 | 路径唯一，否则会出现两个入口或一个入口失效。 |
| 硬编码路径 | 在源侧 `.cs` 与文档中搜索 `Assets/` 字面量。 | 全部在目标工程重新定位，见 3.2。 |

### 2.3 目标目录的 Editor 语义会改变程序集归属

源工程 `Assets/Plugins/...` 迁到目标工程 `Assets/Editor/...` 时，整棵目录进入 Editor-only 程序集（`Assembly-CSharp-Editor`）。这通常正是「不需要挂脚本、打开即用」的目标形态，但要明确两点：

- `Editor` 目录内的 `MonoBehaviour`/`ScriptableObject` 仍能编译，但只存在于编辑器：需要在 Player 中存在的组件不能放这里。
- 组件脚本一旦被删除或移出，挂在场景/Prefab 上的组件就会变成 `Missing (Mono Script)`，原有序列化字段不再读取。

若目标工程已有「`Assets/Editor/TA_Tools/**/Runtime/` 放 MonoBehaviour」的既有约定，可以沿用；这是项目事实，不是跨项目结论。

### 2.4 数据要跟着工具走，不要跟着场景走

把「挂在对象上的组件」改造为「Editor-only 数据资产」时：数据目录由常量给出（例如工程级 `Assets/Tools/<ToolName>/`），工具代码只负责解析路径。这样复制代码目录不会把旧工程的业务数据带过去，也不会把新数据写回旧工程。

目录解析优先「按脚本自身位置反查」，最后回落到显式常量：

1. `AssetDatabase.FindAssets("<PathsTypeName> t:MonoScript")` 找到路径脚本本身；
2. `GUIDToAssetPath` 后取其上两级目录作为工具根；
3. 失败时使用 `FallbackRoot` 常量（该常量必须按目标工程改写）。

## 3. 实现或排查步骤

### 3.1 保字节复制

```powershell
robocopy <src> <dst> /E /NFL /NDL /NJH /NJS /NP /R:1 /W:1
```

逐字节复制（含 `.meta`），不重排换行、不加 BOM。复制后用「文件数 + 总字节数」双向对账；唯一允许的差异来自后续路径改写引入的字节变化。

### 3.2 硬编码路径改写清单

| 位置 | 典型内容 | 处理 |
| --- | --- | --- |
| 路径常量 | `FallbackRoot`、`UsageDocumentPath`、`DocumentationAssetPath` | 改为目标工程相对路径。 |
| `EditorPrefs` 默认值 | 输出目录默认值 | 改为目标路径，保留旧 key 兼容。 |
| 目录扫描常量 | 笔刷/模板目录 | 指向新位置。 |
| `README` / `Usage` | `Assets/Plugins/...` 示例 | 同步改写，避免误导后续维护。 |

改写完成后在工具目录内再搜一次源前缀，要求 0 命中；同时搜索目标工程其余位置对旧路径的引用（可能有别的工具依赖旧目录），并逐一判断是改写还是保留。

### 3.3 同名类型与重复助手去重：禁用优于删除

目标工程已存在同名同命名空间的 helper（例如只实现少量成员的旧版工具类）时：

1. 优先把旧的那份改名禁用：`X.cs` → `X.cs.disabled-old-copy`，`.meta` 一起改名；
2. 不直接删除：禁用是单文件、可逆、不会让 Unity 因缺 `.meta` 生成新身份；
3. 必须验证旧调用方（自定义窗口等）在新实现下仍能编译，且成员签名一致；
4. 确认全部调用方收敛后再清理，并在 Profile 记录回滚方式。

### 3.4 旧版组件的下线顺序：先迁移，再删除

1. 保留旧组件脚本，先让工具或迁移入口读取旧组件数据并写入新的数据资产；
2. 确认引用旧组件的场景/Prefab 已完成数据迁移，或已明确接受数据丢失；
3. 最后删除旧脚本；删除后这些资源显示 `Missing (Mono Script)`；
4. 目标工程没有版本控制时，删除前必须留下可回退副本。

顺序反了就无法再用工具读回旧数据，也无法用旧字段名定位历史资产。

### 3.5 破坏性清理的操作约束

- 删除前先做可回退副本：复制到工程外备份目录（例如 `%TEMP%/<tool>_backup_<date>`）。
- 若执行环境禁止对工程外路径直接删除，可用 `Move-Item` 把目标移到备份目录：效果等同移除，且天然可回退。
- 逐个显式路径操作，并核对绝对路径仍位于预期的工具/工程根之下；不要用循环拼路径或跨 shell 组合删除命令。
- 删除后立即复查：目录是否仍在、文件数、以及目标工程内是否还有引用该路径的 `.cs`/`.unity`/`.prefab`/`.mat`/`.asset`。

### 3.6 示例资产与文档单独统计，再决定是否随代码迁移

先分开计量，再决策：

- 工具本体：`Scripts/`、`Editor/`、`Shaders/`；
- 非本体：`Demo/`、`Generated Meshes/`、引导 `PDF`、示例场景。

实测一个工具的示例与文档可占其目录体积的 95% 以上。把非本体内容并入代码工程会显著放大仓库体积，并让「工具是否可用」与「示例是否完整」混为一谈。裁剪时先确认这些资产没有被其他工具或文档引用。

### 3.7 迁移后的静态校验

1. 离线编译全部迁移脚本，引用目标工程 `Library/ScriptAssemblies` 与第三方 DLL；
2. 菜单路径唯一性、类型全名唯一性、旧路径前缀 0 命中；
3. 列出目标工程内仍引用已删除旧路径的消费者。

## 4. 风险与不适用边界

| 现象 | 常见根因 | 建议处理 |
| --- | --- | --- |
| 场景/Prefab 出现 `Missing (Mono Script)` | 删除了仍被引用的组件脚本。 | 先迁移数据再删除；或保留组件并由用户在 Unity 内移除。 |
| 同一类型出现两份实现（重名警告/序列化歧义） | 同名同命名空间未去重。 | 按 3.3 禁用其中一份。 |
| 迁移后出现 `CS0012`/程序集错误 | 只改了目录，未确认程序集依赖方向。 | 检查 asmdef 与引用方向；离线编译可复现但不等价于 Unity。 |
| 菜单没出现或出现两次 | 菜单路径重复，或脚本未编译。 | 执行菜单唯一性预检。 |
| 工具找不到笔刷/模板/文档 | 目录常量未改写。 | 按 3.2 清单逐条改写并复搜。 |
| 仓库体积异常增大 | 示例资产随代码迁移。 | 按 3.6 单独统计并裁剪。 |
| 无法回退 | 无版本控制 + 直接删除。 | 按 3.5 先备份，或改用 `Move-Item`。 |

## 5. 验证与回退

| 层级 | 检查 | 通过条件 |
| --- | --- | --- |
| 文件对账 | 源/目标文件数与总字节。 | 差异只能来自已声明的路径改写。 |
| GUID | 复制前后资产 GUID，源/目标 GUID 交集。 | 复制后与源一致；交集为空。 |
| 编译 | 目标工程程序集 + 第三方 DLL 的离线编译。 | 0 error；剩余 warning 均有来源说明。 |
| 入口 | 菜单路径、窗口类名、常量。 | 唯一、可解析、与文档一致。 |
| 路径 | 旧前缀搜索、旧路径消费者清单。 | 前缀 0 命中；消费者已逐条判断。 |
| 宿主 | Unity 重导入、窗口打开、代表性流程。 | 无新导入/编译错误；离线编译不能替代本项。 |
| 回退 | 备份目录、源工程副本、版本控制。 | 可按工具目录整体恢复。 |

Unity Undo 不覆盖文件移动、目录改名与 `.meta` 关联变化，不能用它作为迁移回退手段。

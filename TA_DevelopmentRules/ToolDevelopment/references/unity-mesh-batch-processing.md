# Unity Mesh 属性批处理开发参考

> 类型：REFERENCE；适用范围：Unity Editor 中对文件夹、选中资产或场景引用执行 Mesh 读写设置与顶点通道清理；使用前提：按目标工程的 Unity 版本、资产来源、导入处理器和实际消费者重新验证。这里提供实现模式，不新增 CORE 强制规则。

关联规范：工具开发模块的 `TOOL-DOC-03`、`TOOL-CMP-01`、`TOOL-ARC-01`、`TOOL-ARC-03`、`TOOL-OPS-01`、`TOOL-OPS-02`、`TOOL-VAL-01`、`TOOL-VAL-02`、`TOOL-VAL-03`。规范来源见 [工具开发模块](../README_Tech_TAToolDevelopmentRules.md)。

项目 API、原交付路径、已复现问题和实际验证范围见 [ProjectACG Mesh 批处理开发案例](../Profiles/ProjectACG/mesh-batch-processing.md)。该案例保留了“源码副本存在，但当前工作区原交付文件缺失”的状态，不能视为工具已在当前工程安装。

阅读路径：立项与选型看 1、2、3.1；实现看 3.2～3.10；排障看 4；验收与后续复用看 5。

## 1. 适用场景

适用于以下同类需求：

- 对美术选中的模型、独立 Mesh 或目录统一设置 CPU 读写权限。
- 删除指定顶点属性，例如高编号 UV、颜色、法线或切线，同时保持未选数据。
- 从 Prefab 或 Hierarchy 引用反向找到持久化 Mesh 资产，再执行同一批处理。
- 让源模型重新导入后仍然遵循显式的资源清理策略。
- 将旧的“单项开关窗口”扩展为可预览、可解释、可回退的资源处理能力。

它不等同于减面、焊点、网格优化、骨架重建、动画压缩或 FBX 源文件修改。只删除属性时，引入完整重建算法容易扩大兼容性和验证成本；需要改变源文件时，另读 [FBX 源数据编辑器开发参考](fbx-source-asset-editor-development.md)。

## 2. 前提与依赖

### 2.1 先查工具与自动处理链，再决定补全范围

调查可分成四条并行的只读线索，最终由一个修改方案收敛：

| 线索 | 查什么 | 需要回答的问题 |
| --- | --- | --- |
| 菜单与窗口 | 读写开关、模型批处理、右键入口、资源检查修复器 | 是缺能力，还是缺统一入口？ |
| 资产写入 | 导入器写入、独立资产编辑、文本替换、复制导出 | 当前操作能否保存，能否兼容二进制资产？ |
| 自动链路 | 模型预处理/后处理、目录规则、预设、构建剥离 | 手动结果会不会在下一次导入时被覆盖？ |
| 消费者 | Shader、光照 UV、描边、动画变形、运行时 CPU 访问 | 所谓“无用数据”是否实际上被读取？ |

可复用的检索顺序是：先用 `rg --files` 找文件名与工具目录，再用 `rg -n` 找菜单、读写字段、UV 操作与导入回调，最后沿调用链读取实现。搜索命中只证明存在相关代码，不能证明具备完整功能。

如果旧工具已经承担纹理和模型读写设置，通常保留其入口与旧能力，把新的 Mesh 操作收敛到同一执行服务。若另一窗口按整页应用导入设置，不能把它直接当作“只改一个 Mesh 参数”的替代品。

### 2.2 把用户术语变成可验证契约

在写 UI 之前明确六项：

| 契约 | 需要冻结的语义 |
| --- | --- |
| UV 编号 | Inspector 零起点编号、脚本属性编号和“第几个通道”的对应关系 |
| 删除 | 顶点布局中不再有该属性；填零不等于删除 |
| 读写设置 | 改 CPU 数据访问能力；不代表删除 GPU 顶点属性 |
| 选中对象 | Mesh 资产、模型根、子 Mesh、Prefab、场景对象、文件夹分别如何解释 |
| 保存范围 | 修改共享原资产，还是生成副本并重绑当前对象 |
| 恢复 | 恢复项目规则、取消删除策略、从源重导入、Undo 或版本回滚分别恢复什么 |

默认保持读写状态，默认不勾选任何删除通道，能降低误操作。需要改变行为的每一项参数都有明确执行含义；“没勾选”只表示本次不新增删除操作，不能暗示已恢复历史数据。

### 2.3 资产来源决定写入方式

| 资产来源 | 修改对象与生存期 | 可选保存方案 | 恢复边界 |
| --- | --- | --- | --- |
| 外部源模型导入结果 | 子 Mesh 随导入重建 | 保存清理策略并在导入期重放；或导出独立资产 | 清除策略后从源重导入，前提是源仍含数据 |
| Unity 原生 Mesh 资产 | 持久化对象本身 | 编辑对象并只保存相关资产 | Undo、备份、版本控制；通常没有可自动再生的外部源 |
| Prefab/场景上的共享引用 | 引用指向的资产 | 按来源分派到上述两种方式 | 修改资产会影响全部引用者 |
| 非持久化运行时 Mesh | 当前进程内对象 | 本工具可明确排除；需要时另设保存副本流程 | 不应假装已保存到项目 |
| 包或只读目录资源 | 不在允许写入范围 | 跳过，或另行授权复制后处理 | 路径可见不等于可写 |

## 3. 实现或排查步骤

### 3.1 选最小结构，先分离职责

复杂度来自两种持久化方式、混合选集和导入回调，而不只是面板按钮数量。一个可复用闭环是：

```text
选择/文件夹/层级引用
    ↓ 解析、归一化、过滤、合并
当前执行计划
    ↓ 预览、校验、工具内确认
按资产来源分派
    ├─ 源模型：合并策略 → 重导入 → 重新加载 → 校验
    └─ 原生资产：备份 → 最小修改 → 校验 → 保存
    ↓
逐项结果、取消边界、失败原因与恢复信息
```

窗口只处理交互、预览和执行协调；服务处理选集、规则、写入与验证；导入回调只读取持久化策略并作用于当前导入对象。纯通道处理可以独立测试，不依赖窗口是否打开。

这种拆分不要求固定文件数，也不要求抽象出插件框架。先实现同一工具确实存在的两条写入路径，再考虑跨工具复用。

### 3.2 将“选了什么”和“改到哪里”分别建模

推荐先以资产路径建立目标集合，再记录该路径下是“所有 Mesh”还是“某些 Mesh”。这样可避免文件夹、模型根和子 Mesh 同时选中时重复重导入。

合并示例：

```text
选中某模型的 Body、同一个 Body、模型根
→ 一个模型资产目标，范围升级为整模型

选中某目录和该目录中的模型
→ 路径去重，每个模型只执行一次

选中多个场景对象，它们都引用同一 Mesh
→ 一个持久化 Mesh 目标
```

解析中可采用以下技巧：

- 文件夹用资产数据库查找模型与 Mesh，不只依赖文件扩展名，也不递归解析每个 Prefab 的依赖。
- 模型内资源用“加载该路径下全部子资产”收集，避免只加载主对象而漏掉 Mesh。
- 场景或 Prefab 通过静态和蒙皮渲染组件的共享 Mesh 引用收集，并显式决定是否包含 inactive 子对象。
- 路径集合稳定排序，让预览、日志和重复运行结果更容易比对。
- 执行按钮重新解析当前输入并重新校验，避免把旧预览当作当前事实；更复杂工具可进一步冻结计划与输入指纹。

模型读写设置通常属于整个源文件的导入器，而通道规则可以属于单个 Mesh。二者不能共用一个“选中范围”文案掩盖粒度差异。

### 3.3 为跨导入对象选择稳定标识

内存对象引用和实例 ID 不适合直接持久化为导入规则：重新导入会重建对象。名称方案易实现，但只在资产内唯一、命名足够稳定时可靠。

使用名称时，可在执行前检查目标名称存在且唯一；后续导入发现名称丢失或重复时，警告并跳过歧义条目，不任意挑一个。整模型策略不依赖单 Mesh 名称。

若项目需要处理大量同名 Mesh，可评估来源节点标识、层级路径或导入标识表；这些方案也要验证对重命名、重排、DCC 导出和 Unity 版本的稳定性。仅改用文件 ID 并不自动解决所有跨导入身份问题。

### 3.4 将删除理解为最小数据变换

处理前后分别检查属性存在性。目标是让选择的属性从顶点布局中消失，而不是把数值全部写零。Position、顶点数量、索引与 SubMesh、未选属性是保真基线。

优先清空指定属性，不为删除一个 UV 重建整个 Mesh。完整重建会要求同时正确处理：

- UV 的二维、三维和四维数据，以及顶点属性格式与精度；
- 颜色的压缩格式、各顶点流与步长；
- 索引格式、拓扑、SubMesh 描述和边界；
- 骨权重、绑定姿态、BlendShape 帧及其增量。

“代码没有主动修改这些数据”只能支持设计意图，不能替代保留测试。高层 Mesh API 也可能触发内部布局重排；是否能保持字节级数据与内存收益，要靠实际版本和资源验证。

UV 命名映射与本次 API 示例集中在 [项目案例第 5 节](../Profiles/ProjectACG/mesh-batch-processing.md#5-通道操作与-uv-编号)，避免本参考把某套实现的位掩码和字段变成接口要求。

### 3.5 对源模型保存策略，在导入时重放

只修改当前导入出来的 Mesh 并标脏，不能保证下次导入仍保持结果。可选择“修改源文件”“生成独立资产”或“持久化导入策略”；用户只要求导入结果清理时，策略方案通常对源内容影响较小。

策略可表达：是否覆盖读写状态、全模型删除掩码、按名称删除掩码、版本。设计时分别考虑：

1. 没有策略时快速返回，不修改无关模型。
2. 读写覆盖在合适的导入预处理阶段应用，通道删除在模型数据生成后执行。
3. 与已有导入规则存在同字段写入时，显式定义优先级与解除覆盖入口。
4. 使用共享元数据容器时，仅合并自有命名空间的数据，保留其他工具内容。
5. 规则损坏、旧版本、未知位、名称失效时，有明确告警、忽略或迁移策略。
6. 回调内部不保存规则、不再次重导入、不扫描全工程，以免递归或扩大影响。

显式追加删除规则可以使用集合并集；撤销则走独立的清除流程。若要支持按通道、按子 Mesh 精细恢复，需要扩展策略编辑语义，不能靠取消本次复选框实现。

项目级规则与编译快照另见 [模型导入规则参考](unity-model-import-rules-and-snapshot.md)。一次性的 Mesh 清理工具不必复制整套预设系统。

### 3.6 区分导入期可编辑数据与运行时读写标志

导入回调中的模型数据和运行时 CPU 访问权限处于不同阶段。在某些版本的导入处理中，最终读写标志已经关闭，但当前数据仍允许处理；用该标志直接跳过会使“关闭读写并清理通道”失效。

可用最小三角形验证这个交叉条件：先确认法线和 UV 存在，再同时关闭读写并删除通道，重导入后检查标志、属性存在性、Position 和顶点数。不要把这个结论推广为“所有不可读 Mesh 在任何时候都可编辑”。本次的实证范围记录在项目案例。

### 3.7 原生 Mesh 走对象序列化与局部保存

字符串替换序列化文件不适合通用资产编辑：文本格式、二进制资源、同文件多个对象和内部字段变化都会破坏假设。更合适的方向是使用目标版本可验证的对象/序列化 API，并把内部字段依赖集中封装。

一种编辑事务是：

```text
记录原读写状态和目标状态
→ 准备临时备份、登记 Undo
→ 必要时临时允许编辑
→ 删除指定属性并验证
→ 恢复预期读写状态
→ 只保存当前处理资产
→ 释放临时备份
```

异常时尝试把备份恢复到原对象，避免替换资产对象导致引用丢失。恢复动作本身失败时另报错误。关闭 CPU 数据访问与主动释放 CPU 数据是不同操作，批处理需要支持往返时不能把二者混为一谈。

只保存本工具修改的资产，可减少顺带保存用户其他 dirty 内容的风险。对于同一文件内多个子对象，保存与回滚边界仍可能是文件级，需单独验证。

### 3.8 明确恢复、Undo 与批量取消的边界

| 动作 | 可以承诺什么 | 不能推断什么 |
| --- | --- | --- |
| 对象 Undo | 恢复已登记、引擎可撤销的对象编辑 | 跨重导入、跨会话、源文件变化均能恢复 |
| 单资产备份回滚 | 当前项失败后尝试恢复原内容 | 整批操作具备原子性 |
| 清除导入清理策略 | 下次从源重新生成，不再施加这项删除 | 源已丢失的数据会凭空恢复 |
| 解除读写覆盖 | 让项目规则重新决定该属性 | 必然开启或关闭读写 |
| 批量取消 | 在一致性检查点停止后续项，保留已完成项 | 自动撤回所有先前成功项 |

不要因为一种写入路径有回滚，就宣称所有按钮都具备同级事务保证。尤其是“清除规则并重导入”这种辅助入口，也要单独审视失败恢复。

### 3.9 预览优先展示决定行为的信息

预览最有用的信息是资产路径、资产来源、Mesh 数量、局部/全模型范围、读写作用粒度、现有策略、将删属性和不处理原因。大集合可限量展示，但总数与截断提示要准确。

参数变更和选择变更让预览失效；昂贵扫描不放在每次绘制里。选择事件有对应解绑，关闭窗口和 Domain Reload 不留下订阅。执行时重新确认范围，结果区可定位资源并保留错误摘要。

统计最好分别报告资产文件、Mesh 对象和规则条目。它们的数量不同；直接把“改了几个模型”和“跳过几个 Mesh”相加，可能得到没有明确单位的总数。

### 3.10 性能优化以保存与导入依赖为前提

先做好路径去重、属性无变化跳过、无策略快速返回和局部保存，再考虑批量编辑保护。若写入后必须立即取得重导入结果做验证，不能机械套用“延迟所有导入”的优化。

预览抽样、进度显示、逐项取消和错误隔离通常比追求一个大事务更实用。确实需要整批原子提交时，另行设计完整备份、提交清单、恢复失败处理和磁盘预算。

## 4. 风险与不适用边界

### 4.1 常见问题的定位表

| 现象 | 优先检查 | 解决方向 |
| --- | --- | --- |
| 本次有效，重导入后恢复 | 修改的是导入产物还是持久化策略 | 选定源修改、独立资产或导入重放方案 |
| 读写设置被改回 | 项目自动规则是否写同一字段 | 显式优先级、读回验证、解除覆盖入口 |
| 关闭读写后通道清理失效 | 是否用运行时访问标志跳过导入期处理 | 用最小模型验证阶段行为，按证据调整条件 |
| 删除“UV3”却删错通道 | 零起点和脚本属性编号是否混用 | UI 同时显示实际编号与通道序号 |
| 颜色/UV/变形异常 | 是否完整重建或统一转换数据类型 | 缩小写入范围，检查未选数据与格式 |
| 多个模型意外一起变化 | 是否修改共享资产，是否扩大为整模型 | 展示引用与操作粒度；需要局部结果时另做复制 |
| 子 Mesh 规则命中错误 | 名称重复、改名、跨导入引用失效 | 校验唯一性，拒绝歧义或重建标识策略 |
| 删除后仍占顶点通道 | 是否只是把数值置零 | 检查属性布局而非仅看数组数值 |
| 编译能过但行为失败 | 是否只做了外部类型检查 | 补真实导入、保存重载、渲染与变形验证 |
| 日志显示通过，但新测试没跑 | 当前脚本是否已晚于该日志修改 | 将日志与代码版本配对，禁止沿用旧通过状态 |

### 4.2 通道不使用的结论来自消费者

高编号 UV 也可能存描边法线、遮罩、AO 或自定义变形数据；颜色可用于混合权重；UV 可用于 Lightmap；切线和法线影响光照。资源 Inspector 中“看起来没用”不能构成删除依据。

读写关闭还可能影响运行时顶点访问、碰撞处理或项目特定 CPU 运算。仅证明画面暂时正常不足以覆盖这些消费者。

### 4.3 属性减少不等于收益已量化

属性删除可以改变布局，但实际 CPU/GPU 内存、对齐、顶点流、构建压缩和加载行为依赖目标版本与平台。用顶点数乘属性字节数只能估算，不能作为最终节省量。需要性能结论时，在相同资源和构建配置下测量前后内存、包体与加载/渲染数据。

### 4.4 故障经验与规则分开维护

本参考的方案是可选择的实现模式。具体字段、回调优先级、第三方窗口框架、某个测试的结果和当前代码缺口留在 Profile；只有已有 CORE 尚不能表达且跨项目证据充分时，才修订规范来源。

## 5. 验证与回退

### 5.1 分层验证矩阵

| 层级 | 最小样本/动作 | 可证明的结论 |
| --- | --- | --- |
| 静态 | 路径、程序集、菜单、事件解绑、编码、API 与序列化字段检查 | 结构和明显调用问题可定位 |
| 外部编译 | 引用实际 Unity 与插件程序集编译受影响文件 | 语法、签名和引用匹配；不等同于 Unity 宿主通过 |
| 纯 Mesh | 小三角形包含多种属性，仅删除一部分 | 指定属性删除、未选属性和拓扑保持 |
| 模型导入 | 带法线/UV 的临时源模型，关闭读写后清理，再重导入 | 策略生效及持久化范围 |
| 原生资产 | 保存、关闭读写、选择性清理、重载、再开启 | 读写往返、资产保存和引用稳定 |
| 复杂数据 | 实际骨权重、绑定姿态、多帧 BlendShape、各格式 UV/颜色 | 对代表性变形与格式的兼容性 |
| 集成边界 | 混选、目录、重名、空输入、取消、异常、Undo、规则清除 | 工具行为与恢复边界 |
| 消费者 | 实际 Shader、光照、蒙皮动画、运行时代码与目标设备 | 业务与视觉结果；不能由上一层代替 |

### 5.2 回归用例按不变量设计

有价值的断言包括：

- 删除后属性确实不存在，未选属性仍存在且数据值/维度/格式保持。
- 顶点数、索引值、SubMesh 与拓扑保持；复杂资产再检查边界和变形。
- 重复导入两次仍符合策略；同样参数再次执行不会破坏结果。
- 其他工具元数据原样保留；解除自身策略不删除别人的数据。
- 名称歧义不会错误命中；取消后已完成项和未执行项可解释。
- 失败回滚后，数据和引用恢复；回滚失败能单独定位。

测试应验证结果和不变量，避免只是把实现步骤再抄成断言。测试创建的临时资源与生产资源隔离，清理范围固定。

### 5.3 记录证据的最小格式

```text
对象与版本：Unity/插件/代码版本，样本资产来源
输入：选择范围、读写操作、删除通道、现有策略
动作：导入/处理/保存/重载/再次导入
输出：属性存在性、数据保留、错误与结果计数
证据：日志路径、断言、必要的样本哈希
限制：尚未执行的场景、资产和设备
回退：解除策略/Undo/备份/版本控制，及失败边界
```

“测试源文件已编译”“测试计划已补齐”和“测试运行通过”使用不同状态。环境启动失败仅证明该次执行受阻；先前的小样本通过也不能替代后续新增回归。

### 5.4 用于其他工具的复用清单

| 可迁移经验 | 应用到其他功能时先替换什么 |
| --- | --- |
| 来源决定保存方式 | 纹理/音频的导入器、材质/动画资产的序列化方式 |
| 选择粒度和实际写入粒度分离 | 贴图子资源、材质槽、动画片段与源文件整体设置 |
| 元数据只写自有区域 | 对应工具的命名空间、版本和迁移策略 |

| 最小修改保护未选数据 | 目标资产的数据格式、引用、子对象与隐藏信息 |
| 单项回滚与批量取消分别定义 | 文件级、对象级或外部系统级事务边界 |
| 每次执行重新校验输入 | 输入资产、预设版本、当前选择和输出冲突 |
| 编译与宿主行为证据分层 | 目标应用的真实执行链和代表性消费者 |

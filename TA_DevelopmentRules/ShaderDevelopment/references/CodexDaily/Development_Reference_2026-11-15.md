# Shader 云海与可选效果验证参考｜2026-11-15

> 类型：REFERENCE；适用范围：移动端背景云海、Shader 功能扩展与既有材质兼容验证；使用前提：按目标管线、场景、相机、材质和设备重新核实。
> 关联既有规则：`DOC-03`、`CMP-01`、`CTL-02`、`VAL-03`；ProjectACG 当日状态见 [Shader 与环境渲染 Profile](../../Profiles/ProjectACG/CodexDaily/Development_Profile_2026-11-15.md)。

## 1. 适用场景

- 高处镜头需要云层铺满山谷并延伸到地平线，且相机有一定移动。
- Android/iOS 需要控制云层 Shader 的采样数、透明过绘和覆盖面积。
- 在既有 Shader 增加可选发光、PBR 或坐标功能，同时保留旧材质效果。
- 文档描述、资源存在与目标场景实际 Renderer 配置不一致，需要选择可复用路径。

## 2. 前提与依赖

- 先确定云海是固定镜头背景、可活动镜头下的空间云层，还是近景云团；目标不同会改变几何、视差与透明方案。
- 核对游戏实际加载的质量档、Renderer Data、Renderer Feature、雾效、云 Shader、材质和贴图。资源存在或 README 说明都不能单独证明其参与当前场景绘制。
- 记录目标手机、图形 API、屏幕覆盖率、透明层数量、纹理采样器预算和允许的阴影/法线需求；会话建议没有替代设备 Profiler 数据。
- 新 Shader 功能应有独立默认关闭路径，条件编译字段、顶点赋值和片元读取保持相同开关边界；复用现有贴图通道前先确认其项目语义。

## 3. 实现或排查步骤

### 3.1 按镜头选择云海承载方式

| 方案 | 适合情况 | 主要成本或限制 |
| --- | --- | --- |
| 天空盒全景贴图 | 镜头固定、只需远景 | 成本低但缺少视差，镜头移动时容易显得像背景图。 |
| 弯曲云面网格/穹顶 + 云纹理 | 高空云海、镜头可移动；通常是移动端优先候选 | 云层形状和视差可控；透明面覆盖大时仍可能受填充率和过绘限制。 |
| 少量 Billboard/粒子 | 云海上零散近景点缀 | 避免大量重叠透明粒子和排序压力。 |
| 高度雾 | 淡化云层与地平线交界 | 用作远景过渡，不能替代云层形状。 |
| 体积云光线步进 | 高端设备、近景特写或离线演出 | 大量屏幕像素重复采样，移动端成本和调参风险较高。 |
| 预烘焙视频/序列帧 | 镜头受控的演出 | 视差和交互有限，并增加解码或资源体积成本。 |

对于背景型云海，可先用大尺度弯曲网格、一张压缩云纹理和缓慢 UV 滚动；低档维持单次主纹理采样，高档再选择性增加细节层。关闭实时阴影和不必要法线，避免叠放多层透明云面；用高度雾处理远处交界。随后按目标场景覆盖率与镜头路径检查形状和遮挡。

### 3.2 先验证现有管线是否真的可复用

1. 从目标场景与质量档定位活动 Renderer，再检查 Feature 是否挂载、所需资源是否被赋值、Feature 是否在当前相机和 Pass 执行。
2. 对照 README、Renderer Data、材质与实际 draw 路径；发现说明过期时以当前目标场景配置和捕获证据为准，并把漂移作为项目 Profile 事实记录。
3. 若现有天空 Shader 会先采样其他天空层，即使其可见开关关闭也要计入采样预算；纯云海需求可比较专用普通 URP 网格路径，避免不必要的 Feature 依赖。

### 3.3 扩展 Shader 时保护旧路径

1. 对新增发光或坐标模式使用独立属性/开关；默认状态保持旧材质行为。
2. 明确功能插入合成的位置：表面自发光、内部程序效果、MatCap、PBR 和透明度是否相加或调制，不能让一层覆盖另一层。
3. 使用目标 Shader 中真实参与渲染的属性；GUI 范围/显示辅助属性不能代替效果参数。确认顶点色、Alpha、遮罩和 Meta 等消费者是否应包含该功能。
4. 按目标断言构建隔离验证：编译矩阵检查分支组合；像素断言检查开关、坐标、范围、遮罩和合成端点；验证报告需在本轮执行后生成，不能沿用较早的成功报告。

## 4. 风险与不适用边界

- 云面透明覆盖很大时，少 Draw Call 仍可能因填充率和过绘而慢；必须在目标设备分析 GPU 与 Overdraw，不能仅根据网格数推断性能。
- Screen UV 能稳定屏幕尺寸但会随相机/物体运动产生表面滑动；模型 UV 则会随透视距离改变屏幕尺寸。
- 多采样、噪声与 Shader Keyword 会增加变体或采样器压力；默认关闭只说明目标默认分支不执行新路径，不代表所有构建组合都没有成本。
- 独立像素夹具通过不能证明真实角色、整场景透明排序、移动端带宽或发热达标。
- “已有资源可用”必须同时满足实际 Renderer 接入、材质输入和场景目标；项目文档陈述过期时不能据此宣布不可用或已接入。

## 5. 验证与回退

- 云海在目标设备覆盖固定镜头和代表性移动镜头，检查地平线、云层视差、透明边缘、Overdraw、GPU 时间与温升；与目标质量档基线比较。
- 记录各档纹理采样数量、开启的 Keyword、Feature/Pass 路径与质量差异；绘制范围或采样预算超限时回退到单层云面/天空贴图。
- 新 Shader 功能先测默认关闭画面与旧基线一致，再测开关端点、HDR 范围、遮罩、Alpha=0、PBR/MatCap 组合和实际 Meta/深度等相关 Pass。
- 失败时关闭独立功能开关并回到旧材质路径；保留失败断言和新运行报告，修正测试输入后再重跑，不把失败阈值当成实现成功或失败的充分证明。

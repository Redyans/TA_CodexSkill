## 1. 平面 MatCap 与独立法线控制

### 适用场景

用视图空间法线 XY 直接采样 MatCap 时，同法线平面内部颜色恒定；或希望 MatCap 凹凸与表面光照、折射的凹凸强度分别调整。

### 前提与依赖

明确透视/正交投影、逐像素位置、模型法线、法线贴图解码、TBN、UV 与旋转约定。相关职责见 [ORG-03、WRK-04](../../README_Tech_URPShaderDevelopmentRules.md)。

### 实现或排查步骤

1. 将逐像素视线与法线统一到视图空间，计算反射方向。
2. 按来源给出的球面映射思路：`r = normalize(reflect(posVS, norVS))`，再以 `normalize(r + float3(0,0,1)).xy * 0.5 + 0.5` 生成采样坐标。这里是来源示意公式；矩阵方向、视线符号与极点处理需要适配目标实现，不能直接视为完备代码。
3. 在透视相机下，同法线平面的逐像素视线不同，因此可以产生面内变化；正交相机应使用平行视线，同法线平面保持均匀并不表示映射失效。
4. 若要分开调节法线效果，共享原始法线贴图和 UV，分别构造表面与 MatCap 所需法线；避免先乘表面强度再交给 MatCap，使表面强度为零时细节被提前消除。
5. 区分 Fresnel 掠射角增强与几何边框。固定四周亮边需要遮罩或倒角，不能仅靠观察角度曲线获得。

### 风险与不适用边界

平面较小或相机较远时，透视视线差异也可能很小。一个采样分支正确处理正交相机，不表示 Fresnel、折射等其他分支也已适配。分离法线强度后，旧材质 MatCap 可能更强，需要重新调节；映射极点的具体保护步骤在可采用的当日消息中缺失。

### 验证与回退

对比平面左右像素、球面、相机旋转、透视/正交、法线强度为零及中间值、MatCap 关闭时的输出。保留旧映射作为对照；原材质参数和采样路径可恢复。依据来源：S1 消息 97–111。

## 2. 毛玻璃的采样成本、噪声衰减与前景保护

### 适用场景

在低采样成本、柔和模糊和随机磨砂之间选择方案，或排查“近处有颗粒、远处消失”“背景仍清晰”“整体朝一侧偏移”。

### 前提与依赖

屏幕背景与深度纹理由实际相机提供；透明材质能够读取它们。确认纹理尺寸、颜色域、噪声导入类型及过滤方式。资源职责和性能验证引用 [ARC-01、ARC-04、CTL-01、VAL-02](../../README_Tech_URPShaderDevelopmentRules.md)。

### 实现或排查步骤

| 方案 | 实现与成本取舍 | 不解决的内容 |
| --- | --- | --- |
| 邻域平均加噪声 | 多个背景采样点加权，逐点深度保护；能形成柔和模糊 | 大覆盖率时读写成本较高 |
| 单次噪声偏移 | 先采噪声与偏移位置深度；若命中前景，退回原 UV，再读取一次背景颜色 | 随机移位不等于宽半径平均，关闭噪声后可恢复清晰背景 |
| 降采样共享背景 | 先降低背景分辨率，透明材质仍单次采样 | 不修复噪声 Mip 导致的幅度衰减，也不保证足够柔和 |
| 共享模糊纹理 | 先集中模糊，再供多个材质读取 | 需要额外 Pass、RT 和生命周期；当天仅为建议 |

排查噪声时可按下列顺序：

1. 分开查看模型方向折射与随机偏移，暂时将其中一路归零，定位整体偏移来自哪一路。
2. 以 `noiseRG * 2 - 1` 作为扰动时，检查 RG 是否围绕中性值 0.5；灰度噪声两通道相关，会更容易沿对角线偏移。
3. 数据噪声按数据纹理读取。若在线性项目将 0.5 经 sRGB 解码，约变为 0.214，映射后约为 -0.572，会引入方向偏置。法线类型导入的贴图也不能不解码就当普通 RG 噪声使用。
4. 检查 Mip：噪声被平均后趋向 0.5，使扰动趋近零。负 Mip Bias 只能延缓；屏幕空间噪声或专门 Mip 策略属于待验证选择。
5. 检查最终透明混合：`result = processed * alpha + clearBackground * (1-alpha)`。Alpha 过低时，清晰背景会重新混入。
6. 深度保护与“背景离玻璃越远越模糊”是两个功能；后者需要额外定义深度到模糊强度的关系，不能由前者推断已实现。

宽高各减半的纹理像素数为原来的四分之一；各减为四分之一时为十六分之一。共享背景降采样会影响同相机其他消费者；局部专用背景需要独立资源。更多成本比较见[屏幕空间特效参考](../screen-space-effect-production-and-validation.md)。

### 风险与不适用边界

Opaque 背景不代表完整透明场景。场景颜色已包含光照，再作为普通 Albedo 重算光照可能产生不可控亮度；来源采用发光贡献承载背景，但不等同于开启额外自发光功能。减少采样不自动减少 Draw Call 或已存在的背景/深度纹理内存，也不能代替设备性能测量。

### 验证与回退

覆盖前景遮挡、无噪声、零扰动、远近距离、高对比背景、低 Alpha、正交/透视与其他背景消费者。比较近似可见模糊半径下的采样数、带宽、额外 Pass 与画质。保留清晰背景路径及原降采样设置。依据来源：S1 消息 114–147；项目当天最终已移除该毛玻璃功能。

## 3. 将背景、最终 Alpha、染色和凹凸折射分开诊断

### 适用场景

透明材质中多个“透明、淡出、颜色”控件视觉上重叠，或平面玻璃背景整体平移而不是局部凹凸扰动。

### 前提与依赖

列出各控件真正作用的中间量与计算顺序，并冻结现有材质数值。依据 [CMP-01、ORG-02](../../README_Tech_URPShaderDevelopmentRules.md) 区分算法变化与面板整理。

### 实现或排查步骤

1. 将采样背景贡献、最终 Alpha、表面 PBR 输入分别追踪。背景强度变化不一定改变最终 Alpha；最终 Alpha 会影响整个玻璃结果。
2. 对角度公式代入边界值计算，不只看控件名称。指数为零等情况可能让号称“随视角”的项变成常量。
3. 追踪“贴图乘染色 → 饱和度 → 亮度 → 光照”。颜色选择器只改变乘数，不能等价替代对整张染色结果的饱和度操作；已乘成黑色后调饱和度也不会恢复细节。
4. 原地凹凸折射可将模型朝向造成的统一偏移与法线贴图局部扰动分离。来源采用去掉统一方向项、保留局部凹凸的方式；迁移时以平坦法线输出无整体偏移为目标验证，精确通用实现代码在当天消息中不完整。

### 风险与不适用边界

两组控件都改变观感，不表示可无损删除其中一组。单纯增强法线不能消除统一方向偏移；低 Alpha 也可能掩盖折射变化。特殊相机矩阵写法不能仅按习惯改成“常规写法”。

### 验证与回退

检查角度端点、法线强度为零、平坦法线、相机旋转、基色黑/白、染色与饱和度分别变化。用原材质与原公式作为回退基线。依据来源：S1 消息 137–153、169–177、202–204；角度淡出结论采用消息 153 对消息 150 的明确纠正。

## 4. 生成式 Shader 精简、依赖迁移与光照复用

### 适用场景

将节点生成代码整理为可维护实现、移动 Shader 后 Include 失效，或尝试共享既有 PBR 光照。

### 前提与依赖

冻结 Properties、GUI、材质引用、坐标变换、Pass、实际渲染队列和输入输出。规范来源为 [CMP-01、ARC-02、ARC-03、ORG-01、WRK-03](../../README_Tech_URPShaderDevelopmentRules.md)；资产移动检查见[工具集成检查](../../../ToolDevelopment/references/tool-integration-checklist.md)。

### 实现或排查步骤

1. 分开清理未启用模板与删除有效能力：未执行的细分/透射分支清理主要改善维护；删除阴影、深度法线或烘焙 Pass 会改变支持能力。
2. 根据真实调用选择 Pass，保留编辑器选中/拾取等实际消费者。Pass 数不是每帧 Draw 数；Forward 深度写入也不由是否存在 DepthOnly 单独决定。
3. 保持矩阵乘法顺序、精度与合成顺序，先逐职责 A/B，再整体对比；“代数看似相近”不代表相机旋转下相同。
4. 移动时检查主 Shader、相对 Include 依赖与各自 `.meta` 的闭包，并在目标目录结构下重新编译。需要单文件交付时，可整理共享声明及各 Pass 实现，但确认参数只声明一次、宏与 Include 顺序正确。
5. 复用已有光照时先比较 Surface/InputData 与核心 BRDF，再分开评估 AO、阴影染色、假光和高光抗锯齿。屏幕空间遮蔽可能对应透明物体背后的不透明深度；不能直接当作透明表面的遮蔽。
6. 核对 GI 接口所需屏幕 UV、反射探针选择和接收阴影控制，不仅替换函数名。高光抗锯齿作用于高光，不等于折射背景模糊。

### 风险与不适用边界

共享光照只保证统一维护的可能性，不保证自动变快或外观一致。源码缩短不能折算为 GPU 收益；项目有意删功能与行为保真重构需分别评价。

### 验证与回退

固定输入比较基色、法线、遮罩、折射、发光、Alpha、深度遮挡、相机旋转与选取；核对测试副本和交付版本一致。保留完整依赖及材质快照，回退时恢复成套文件。依据来源：S1 消息 154–191；共享光照在来源中仅分析，未实现。

## 5. 变体裁剪的计数与恢复

### 适用场景

选择精简材质/管线功能，或确认一次已验证裁剪是否被误回退。

### 前提与依赖

明确材质开关、运行时数值分支、渲染状态、固定宏、逐 Pass 重复声明和构建剥离的区别。引用 [CTL-02、VAL-03](../../README_Tech_URPShaderDevelopmentRules.md)，不另定义计数规则。

### 实现或排查步骤

1. 分别统计独立开关组与各 Pass 的声明次数；最终构建变体数另从构建结果确认。
2. 为每个删除项记录对应能力、依赖代码、材质控制和全局 Keyword 来源，避免只删除 pragma 留下行为不明的代码。
3. 比较“旧版关闭待删功能”与“裁剪版保留功能”，再测试全局开启已删 Keyword 时功能不会意外回归。
4. 怀疑回退时，结合结构清单、规范化换行后的内容比较和备份验证身份；行数仅作定位线索。
5. 恢复历史已测版本时，区分本次静态一致性检查与历史 Unity 测试，不把旧报告写成新的实测。

### 风险与不适用边界

Inspector Toggle 不必然创建变体；关闭管线能力会影响依赖它的场景。材质开关含“OFF”时还需检查关闭的具体反射或光照路径，不能扩大解释。

### 验证与回退

按目标设备、实际材质与运行时关键词复验；记录未测场景。恢复经过识别的备份并保留 GUID；当天实际数量和测试证据只见 Profile。依据来源：S1 消息 191–211。

## 6. 将 RGB 混合与 RT 覆盖率分开

### 适用场景

透明贴花、表情或叠色层绘到已有不透明内容时，RGB 正常但 RT Alpha 被压低，后续 UI 合成漏背景。

### 前提与依赖

确认 RT 后续消费者确实使用 Alpha，明确源 Alpha 表示覆盖率，以及当前 RGB 是直通、预乘或加法模式。相关 Render State 契约见 [ARC-03、CMP-01](../../README_Tech_URPShaderDevelopmentRules.md)。

### 实现或排查步骤

颜色和 Alpha 共用 `SrcAlpha / OneMinusSrcAlpha` 时：

```text
Aout = As * As + Ad * (1-As)
As=0.5，Ad=1 → Aout=0.75
```

若 Alpha 表示普通覆盖率，可保留现有 RGB 系数，只把 Alpha 改为独立混合：

```shaderlab
Blend [_SrcBlend] [_DstBlend], One OneMinusSrcAlpha
```

```text
Aout = As + Ad * (1-As)
As=0.5，Ad=1 → Aout=1
As=0.5，Ad=0 → Aout=0.5
```

该方法没有强制所有 Alpha 为 1，也没有把颜色变成不透明叠色。

### 风险与不适用边界

读取 Alpha 的后处理会观察到变化；加法发光、特殊数据 RT 或非覆盖率 Alpha 需单独确认契约。RGB 表达式不变不能直接证明整条合成链视觉不变。

### 验证与回退

检查透明空背景、不透明底面、多次叠加、RGB 普通混合/加法混合和最终 RT 消费者；逐材质视觉检查与编译分开记录。回退限定在 Blend 状态，避免无关材质重调。依据来源：S3 消息 1–14。

## 7. 图标与场景 RT 共用模糊处理

### 适用场景

同一 UI 需要对 Sprite/图集图标或外部场景 RT 使用 Dual Blur、Kawase Blur、Grainy Blur。

### 前提与依赖

区分输入提取、滤波调度与最终 UI 显示。明确图集 UV、打包形状、Alpha、Gamma/Linear 显示链、Mask 裁剪以及静态/动态更新方式。成本选择可引用[屏幕空间特效参考](../screen-space-effect-production-and-validation.md)。

### 实现或排查步骤

1. 将 Sprite 的独立 UV 区域提取到处理输入，避免邻接图标进入模糊核；不假设任意紧密打包形式都兼容矩形提取。
2. 在滤波中采用一致的预乘 Alpha 语义，减少透明边缘黑边；具体显示混合方式仍与目标 UI 链对齐。
3. Dual Blur 采用多级降采样/升采样并由组件调度；Kawase 的采样间距与迭代数需观察高对比细线；Grainy 保留颗粒特征。当天会话没有披露全部核权重、采样数和调优后的参数，不能补写成标准实现。
4. 静态输入在参数或图片变化时重算并缓存；外部场景 RT 根据生成相机与更新节奏持续刷新，避免把静态快照策略误用到动态画面。
5. 制作原图与各算法的同输入对比入口，覆盖图标和 RT 两类来源。

### 风险与不适用边界

三种算法的同名半径不代表相同模糊程度；清晰原图、透明边缘、图集隔离与高对比纹理都要比较。零半径、Mask 变体通过不代表移动端性能或所有图集布局通过。

### 验证与回退

检查零半径还原、图集串色、边缘黑边、裁剪、RT 输入和多次启停后的资源释放；视觉不满足时恢复原图或关闭处理。依据来源：S4 消息 2–12；当天 Kawase 重影只有调优进度及最终交付陈述，没有专项消除数据。

## 8. 静态截屏模糊的时机与预算

### 适用场景

弹窗背景需要包含已经完成的后处理，但不包含新弹窗自身；或排查“参数写了降采样，实际仍全尺寸”。

### 前提与依赖

沿截屏入口、RT 创建、横纵滤波、显示材质、遮色层追踪实际链路。区分捕获画面、模糊结果与 Inspector 预览；颜色诊断方法见[工具参考](../../../ToolDevelopment/references/CodexDaily/Development_Reference_2026-11-10.md)。

### 实现或排查步骤

1. 核对帧末捕获与新 UI 加载先后。最终屏幕截图会包含当时已合成的后处理和已有 UI，不能等同于只截场景。
2. 检查 RT 实际宽高与 descriptor，不以 Game View 的预览缩放或未接入尺寸计算的参数判断分辨率。
3. 可分离高斯先横向再纵向、以临时 RT 中转；按实际轮数统计 Blit，核权重总和与均匀色块一起检查。
4. 静态快照可复用已处理结果。UV 翻转用于方向校正，与模糊强度分开排查。
5. 将截图、备份、临时滤波 RT 的格式统一考虑。四通道每通道 16 位浮点的基础像素存储为 8 字节，是四通道 8 位格式的两倍；实际总量还取决于同时存活的纹理、附件等。

### 风险与不适用边界

增加精度不等于修复发灰，也不恢复已经色调映射前的 HDR 画面。模糊降低局部对比度与整幅均匀颜色被提亮是不同现象。

### 验证与回退

使用同帧原图/滤波结果，检查尺寸、均匀灰阶、颜色读数、UV 方向及显存；更改运行中 RT 格式后旧内容可能丢失，需要重建并重拍。回退格式时同步回退全部中间 RT。依据来源：S2 消息 1–15、32–40。

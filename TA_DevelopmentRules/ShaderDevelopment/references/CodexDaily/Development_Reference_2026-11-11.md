# UI 模糊实现与验证参考｜2026-11-11

> 类型：REFERENCE；适用范围：Unity UI 图像自身模糊、场景 RT 显示到 UI，以及 Gamma UI/遮罩合成；使用前提：必须按目标 Unity/URP、Canvas、纹理图集和目标设备重新验证。
> 关联既有规则：`ARC-03`、`ARC-04`、`VAL-02`；项目案例见 [ProjectACG UI 模糊 Profile](../../Profiles/ProjectACG/CodexDaily/Development_Profile_2026-11-11.md)。

## 1. 适用场景

按输入和画面覆盖面积选算法，而非只按算法名称判断快慢：

| 用途 | 可先评估的实现 | 主要取舍 |
| --- | --- | --- |
| 少量小图标、清晰渐变到轻度模糊 | 单轮 Kawase Shader | 约 4 次采样的会话估算；大半径会有重影，且持续绘制仍逐帧采样。 |
| 大面积或强模糊的场景 RT | 多级 Dual Blur | 逐级缩小 RT 后模糊并上采样，适合大范围；需要多次 Pass 与中间 RT 调度。 |
| 刻意的颗粒模糊质感 | Grainy Blur | 会话所述实现每像素为 8/16/32 次采样，采样量高，低档颗粒更明显。 |

以上是会话报告的算法特征与初选建议，不是目标设备上的 GPU 基准。若严格限定一个 Shader 且不允许脚本/RendererFeature 调度，完整 Dual Blur 无法由单次 Image 绘制替代；需接受近似效果，或缩小功能要求。

## 2. 前提与依赖

- 区分 Image 自身的 Sprite 纹理与相机产生的场景 RT；后者还涉及源相机先于 UI 相机的时序。
- 图集模糊必须限制到当前 Sprite 的 UV 区域，避免采样邻图。普通 Image 未必提供足够信息供 Shader 稳定恢复打包矩形；可由组件传递 UV 矩形。会话方案建议避免 Tight Packing，不代表所有 Atlas 配置均已验证。
- Gamma UI 项目中，模糊 Shader 必须遵守现有材质颜色域、Alpha/预乘约定、Stencil 和 Mask 协议。只看单个 Pass 输出不足以证明最终相机合成正确。
- RT 算法需要确认目标纹理尺寸/格式、临时资源生命周期、Pass 顺序与释放时机；HDR RT 与半透明 UI 应纳入测试。

## 3. 实现或排查步骤

1. 先定输入类型、像素覆盖面积、强度、静态/动画状态和目标设备，再建立接近的视觉质量基线。
2. 小图标先试单轮 Kawase，小半径从清晰值逐渐增加；模糊仍保持时，纯 Shader 仍会持续执行采样。动画结束并不会自动产生缓存。
3. 若静态图标数量或成本足以抵销额外显存，可一次渲染到缓存 RT，仅在图标或参数变化时更新；渐变期间仍需重算。缓存使用额外显存，也增加脚本生命周期和失效管理。
4. 大面积场景模糊先比较半分辨率、多级 Dual Blur 与视觉质量；记录每级尺寸、Pass、采样和中间 RT，而不只比较帧率数字。
5. 图标显示灰块或纹理缺失时，检查目标材质属性复制是否丢掉纹理绑定；Gamma UI 跨 Shader 复制材质时仅按目标 Shader 的匹配属性转移，避免意外清空纹理属性。
6. 检查 URP 相机纹理是否在允许的 RendererPass 阶段访问，并确认临时 RT 不会在最后消费者之前释放。将错误栈归属到具体 Feature；同屏其他已有 Feature 报错不应自动归因于新模糊 Shader。
7. 依次验证颜色/Alpha、HDR、Stencil、RectMask2D、普通 Mask、SoftMask 的组件顺序、场景 RT 与多相机合成；用真实 UI 排序覆盖简单材质预览。

## 4. 风险与不适用边界

- 大半径单轮 Kawase 可能重影；Dual Blur 的金字塔半径若累计放大过度，小图标会糊成灰块。需要从实图轮廓和透明区确认，不以“无报错”代替。
- 对已模糊的像素再逐帧重算只适合动态强度；静态保持阶段可评估缓存，但额外 RT 内存未必适合小图标。
- 颜色正确不等于遮罩、排序和相机堆叠正确；SceneView/单 Pass 检查不能证明正式 GameView 的完整路径。
- 本参考没有目标手机的 GPU 测量，也未给出适用于任意分辨率/格式的性能阈值。

## 5. 验证与回退

固定相机、Canvas、颜色空间、RT 格式、材质和 UI 层级，对比锐利输入和模糊结果；用 Frame Debugger 或等价工具核对纹理生产、采样与释放时序。记录采样/Pass 数、RT 尺寸与格式、透明覆盖面积及目标设备 GPU 时间。若颜色、Alpha 或遮罩回归，回退到项目已验证的 UI 材质/Feature 路径，并逐项恢复组件顺序和纹理绑定。

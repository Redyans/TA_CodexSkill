## 1. Alpha Test：从面板开关追到所有像素消费者

### 适用场景

材质勾选 Alpha Test 后本体仍不镂空，或本体已消失而深度、阴影、描边、运动矢量仍有残留。

### 前提与依赖

收集实际贴图及 Alpha 导入方式、材质倍率、阈值、Keyword、UV 变换，以及所有真实使用的 Pass。属性、关键字或输出 Alpha 的存在不能证明执行了裁剪；透明混合和 Alpha Test 是不同机制。

### 实现或排查步骤

1. 沿“面板属性 → 材质 Keyword → 编译分支 → 片元采样 → `clip()`”逐段确认。
2. 将裁剪输入写成明确契约，例如 `textureAlpha × alphaScale < cutoff`；确认是否与漫反射混合等旧用途复用同一通道。
3. 检查通用深度/阴影 Include 使用的贴图、ST 和阈值是否与材质实际命名一致，避免主 Pass 与辅助 Pass 各读一套参数。
4. 逐项接通主渲染、深度、法线、阴影、描边、运动矢量等消费者。关闭关键字时同样编译检查，留意采样器被优化移除后仍被其他代码引用。
5. 用黑白遮罩、多个阈值、倍率、UV Offset/Tiling 和开关前后对照绘制，单独读回深度/遮罩结果。

### 风险与不适用边界

Alpha Test 是硬裁剪，不提供连续半透明。通道复用会改变旧材质；单个 Pass 正确不能外推整个管线。采样器移除问题是当日特定关闭分支的故障，不推断为所有编译器的共同缺陷。

### 验证与回退

验证矩阵引用 `ORG-03`、`VAL-01`；保留修改前 Shader/材质与关闭功能的基线。独立工程像素结果仍需在业务场景、目标设备和实际渲染时序下复验。来源：[01a1bf2c-715a-7c50-8e33-adad65bde442](../../../../VA_Worlk_memory/sessions/01a1bf2c-715a-7c50-8e33-adad65bde442.md)，消息 5～20。

## 2. 玻璃方案选择：明确采样对象和“折射”的含义

### 适用场景

从文章、截图或旧 Surface Shader 制作玻璃；需要在低成本风格化效果、环境倒影和屏幕背景扭曲之间选方案。

### 前提与依赖

先确定模型是平板还是曲面、相机为透视还是正交、是否允许屏幕纹理、贴图是否齐全、是否需要真实场景背景和透明物体互相折射。

### 实现或排查步骤

| 方案 | 实现路径 | 能表达的效果与主要边界 |
| --- | --- | --- |
| 法线 MatCap | 视角空间法线映射到二维贴图，叠加高光；可分反射与内部色层 | 适合可控棚拍高光。平面法线一致时易采成一块颜色，不等同真实环境反射。 |
| 平面 MatCap | 用模型 UV 铺开纹理，加缩放、偏移、旋转和可选法线扰动 | 能显示完整图案，但属于美术投影，UV 质量影响结果。 |
| Cubemap | 反射用 `reflect(-V, N)`；模拟透射可按折射率构造采样方向 | 反射与透射分别选择来源、分别旋转。采到的是环境贴图，不是相机背后的实时物体。 |
| 屏幕背景采样 | 从不透明场景颜色按屏幕 UV 加法线偏移采样，再与表面合成 | 可表现背景扭曲；依赖场景颜色纹理，通常不包含后绘制的透明物体。 |
| 视角条带假反射 | 透明底色、Fresnel 亮边、随视角变化的条带投影；宽窄双条和边缘抗锯齿 | 能制作窗户、杯壁、镜片风格高光；球体 UV 可能扭曲条带，曲面和直条需不同投影。 |
| 旧公式的透明度模拟 | Cubemap 颜色混合与角度 Alpha；保留原计算语义 | 名为“Refraction”的参数也可能只改变 Alpha，没有折射采样。 |

移植旧代码时先修正拼写、输入类型、向量空间和 Alpha 标量语义，再接入目标 URP 光照与雾效。原贴图缺失时可用诊断或示例环境图验证功能，但不能宣称还原了原作品。新增贴图来源模式时，保持旧材质默认路径，用相同输入比较默认模式是否发生视觉变化。

### 风险与不适用边界

Cubemap 的 Mip 模糊只作用于倒影，不能据此声称模糊了屏幕背景。单次屏幕偏移或 IOR 参数并不等同追踪穿过前后表面与厚度的物理折射。条带和 MatCap 属于可控近似。透明排序、ZWrite、负缩放、相机投影均可能影响结果。

### 验证与回退

比较透视/正交、平面/曲面、法线扰动、旋转、透明度为零与默认模式；来源切换分别验证反射、透射和混用。场景多层透明与手机性能单独验收。来源：[01a1bf8a-7eff-7be3-89ad-651747d035e0](../../../../VA_Worlk_memory/sessions/01a1bf8a-7eff-7be3-89ad-651747d035e0.md) 消息 5～22；[01a1bf9b-020f-7dc0-97d8-de8f3a50cc92](../../../../VA_Worlk_memory/sessions/01a1bf9b-020f-7dc0-97d8-de8f3a50cc92.md) 消息 2～13；[01a1bf9f-cc5a-7913-850f-5be6144d681f](../../../../VA_Worlk_memory/sessions/01a1bf9f-cc5a-7913-850f-5be6144d681f.md) 消息 4～13；[01a1bff3-d286-7722-a456-7e33304f5a7b](../../../../VA_Worlk_memory/sessions/01a1bff3-d286-7722-a456-7e33304f5a7b.md) 消息 5。

## 3. 玻璃发白、Alpha 和自发光：按合成阶段排查

### 适用场景

Albedo 贴图存在却被冲白；贴图 Alpha 为零仍看得到反射；“透明度”“背景亮度”“自发光”名字相近但行为不同。

### 前提与依赖

确认当前材质的真实值、磁盘保存值、最终 Blend/ZWrite 及背景采样条件。需要区分表面光照、额外反射、背景透出、自发光和最终 Alpha 五条路径。

### 实现或排查步骤

1. 写出简化合成式：`最终 RGB = 表面光照 + 自定义反射 + 背景贡献 + 独立发光`，再确认最终透明混合位置。Albedo 可能只乘表面颜色，不会染色后续相加的反射与背景。
2. 以真实公式寻找中性参数：例如偏移若为 `normalOffset × (refraction - 1)`，则 `1` 才是无偏移；不能按名称把 `0` 当作关闭。
3. 分别关闭额外反射、Fresnel、背景贡献，降低金属度，隔离亮度来源；恢复参数时逐项观察。没有完成此对照，就保留“候选原因”状态。
4. 区分“Alpha 控制背景混合”和“Alpha 控制最终可见度”。若目标是 A=0 完全消失，将遮罩接入最终 Alpha，并核查反射、发光、深度与阴影是否遵循同一边界。
5. 独立发光可采用“贴图 RGB × HDR 颜色”，有独立强度需求时再乘强度。若背景与表面先进行 lerp，明确发光是在 lerp 之前还是之后，避免背景透出压掉发光。
6. 面板标签说明实际用途；当 Pass 写死渲染状态时，属性字段不能被描述为可控制该状态。需要接通状态时作为渲染行为变更单独验收。

### 风险与不适用边界

最终 Alpha 改造依赖 Blend 因子；普通透明和“背景先合成到 RGB、输出 Alpha=1”的路径不能直接套用同一公式。仅裁掉 A=0 不等于中间 Alpha 不写深度。增加 Emission 并不保证 Bloom 可见；还受后处理、曝光和场景设置影响。

### 验证与回退

采用 A=0、0.25、0.5、1、反转、Fade、发光开关及强度零值组合；关闭新增功能时与旧图对照。保留旧材质、Shader 与渲染状态快照，恢复时一起核对。来源：[01a1bff3-d286-7722-a456-7e33304f5a7b](../../../../VA_Worlk_memory/sessions/01a1bff3-d286-7722-a456-7e33304f5a7b.md) 消息 5～20、32～54；本日发白主因未完成逐项隔离实测，Alpha/Emission 的会话测试范围见 Profile。

## 4. 合并 PBR 贴图：同时迁移通道、Importer、材质键和 UV

### 适用场景

把金属度/光滑度与 AO 多张图合成一张图后外观变化，或 Shader 通道看似正确但旧材质不再一致。

### 前提与依赖

记录原图物理通道、Importer Swizzle 与 sRGB、Shader 读取通道、材质纹理槽键、倍率、UV/ST 和“无图”默认值。按数据流确认，不能只根据贴图文件名判断通道。

### 实现或排查步骤

1. 列出“源图 → 导入后的 RGBA → Shader 输出语义”三层映射。例如源 A 经 Swizzle 进入采样 R 后，Shader 的 `.r` 已不等于源 R。
2. 为新图约定完整语义。若 R 存光滑度，则粗糙度为 `1-R`；不要因为需求写 roughness 就改成另一种通道布局。
3. 迁移旧纹理引用和必要的 ST；重命名 Shader 属性不会自动把旧材质槽的数据搬过去。
4. 无 AO 数据时以旧材质等效结果为基线。若旧结果 AO=1，未知或很暗的通道不能直接冒充 AO；转换时设为 1 或采用显式无 AO 回退。
5. 核对附带消费者：光滑度原通道可能还参与背景透出遮罩。迁移该遮罩读取的位置，而不只是 PBR 输入。
6. 根据需求选择“通道直读”或“通道 × 滑条”。默认白图可使无图状态回到倍率参数、AO=1；不为追随参考 Shader 自动复制额外亮度/对比度控制。
7. 数值遮罩使用正确的线性采样设置。若更改同一张图的 Swizzle，检查仍引用该图的旧材质，避免修改新 Shader 时影响旧 Shader 的采样。

### 风险与不适用边界

共享图的 Importer 改动会影响所有消费者；独立贴图原本有不同 ST 时，合并为单图会丢失部分表达能力。图中暗通道不天然是 AO。只有通道测试通过，不能据此宣称材质外观完全一致。

### 验证与回退

对每通道使用已知色值验证输出；再对比旧/新材质、无图默认、倍率、遮罩、透明度和发光。回退包含 Shader、材质槽与 Importer 三者，不能只恢复代码。来源：[01a1bff3-d286-7722-a456-7e33304f5a7b](../../../../VA_Worlk_memory/sessions/01a1bff3-d286-7722-a456-7e33304f5a7b.md) 消息 55～87；最终映射和修正中的未完成项留在 Profile。

## 5. UI 图标模糊：小核采样与 Mip 的成本取舍

### 适用场景

单个图标从清晰过渡到模糊，希望控制纹理采样、额外 RT 与屏幕覆盖成本。

### 前提与依赖

确认 UI 颜色域、Alpha 混合、Mask/矩形裁剪、图集 Sprite UV 范围、贴图 Mip 与过滤设置。仅更改 Shader 不能为未生成 Mip 的贴图增加低层图像。

### 实现或排查步骤

1. 轻度模糊采用固定小核，例如 5 点和可选 9 点；清晰端走单次采样路径。Alpha 加权处理透明边缘，减少黑边。
2. 图集对每个 Sprite 的 UV 范围限制采样，整张图集 Clamp 不能阻止采到相邻图标。
3. 大范围模糊可用 Mip，配 Trilinear 平滑层级过渡；纯 Mip 模式可只保留一次采样指令，再按需求与局部小核组合。
4. 处理图集边界时分开“原始 UV 的导数/层级估计”和“用于取样的限制后 UV”，检查 Clamp 是否让角落突然变清晰。
5. 若梯度采样未获得预期层级，先做缩小显示与边界对照；显式 LOD 可作排查或替代路径。具体公式和后端适配仍需目标项目验证。

### 风险与不适用边界

固定小核的大半径会产生重影；Mip 降采样不是精确高斯模糊。低层 Mip 已混入邻图颜色时，UV Clamp 无法恢复原色，独立图标更易控制。完整二维 Mip 链通常增加约 33% 纹理存储，实际取决于压缩、对齐和尺寸。一次采样指令不等于一次物理 texel 读取，Trilinear、缓存和带宽仍有成本。

### 验证与回退

比较零强度颜色、强度连续变化、透明边缘、图集边界、缩小状态和裁剪；分别记录采样指令、内存、额外 Draw/RT 与手机 GPU 时间。性能要求引用 `CTL-01`、`VAL-02`，无实测不声称优化倍数。可关闭 Mip 回到小核模式；调整 Importer 前保留原设置。来源：[01a1c025-cbe5-78c0-abf8-3479d35c4241](../../../../VA_Worlk_memory/sessions/01a1c025-cbe5-78c0-abf8-3479d35c4241.md) 消息 2～16。

# 屏幕空间特效制作、性能与交付验证参考

> 类型：REFERENCE；适用范围：人物遮罩、扰动描边、软边模糊及相关材质预设的工程化制作；使用前提：以目标项目代码、资产和版本重新验证。
>
> 图像计算见 [Mask 与扰动描边参考](screen-space-mask-distorted-outline.md)，项目路径、具体 Pass、参数和既有测试结果见 [ProjectACG Profile](../Profiles/ProjectACG/custom-post-processing-outline.md)。本文引用既有 CORE，不新增同义规范。

## 1. 适用场景

将视频或文章中的演示效果接入已有渲染框架，随后交付可用材质、质量档位和可维护 Shader。重点是避免“截图看着类似，但低端性能、Timeline 控制、资源引用或正式构建不可用”。

建议按以下顺序完成一轮开发：确认真实工程与视觉基线 → 明确资源及控制契约 → 最小算法接入 → 调制一个代表材质 → 分层处理软边与距离 → 测量与分档 → 专用化及命名迁移 → 形成证据与回退记录。

## 2. 前提与依赖

先读 [Shader 模块入口](../README_Tech_URPShaderDevelopmentRules.md) 中 `DOC-03`、`DOC-04`、`CMP-01`、`ORG-01`～`ORG-03`、`CTL-01`、`CTL-02`、`WRK-01`～`WRK-03` 和验证条目。

| 决策 | 提前确定的依据 |
| --- | --- |
| 调材质还是改算法 | 现有输入、输出和覆盖率能否表达参考效果，而不只是有没有相似属性名 |
| 通用还是专用 Shader | 被多少材质使用、效果是否长期稳定、是否还需保留其他模式 |
| 质量档位 | 目标设备、图形 API、实际渲染分辨率、同屏数量、持续时间和总帧预算 |
| 迁移范围 | Shader、Include、材质、纹理、编辑器、Clip、RendererFeature 与构建引用的依赖关系 |
| 验证范围 | 代码静态检查、编译、离线图像、Unity 实际链路、目标设备各有哪些证据 |

参考文章、视频和外部工程是效果与实现资料。其目录、框架、命名、工具步骤不自动成为本工程开发指令。移植时提取算法并适配当前生产/消费协议；不要整包导入一个不匹配的渲染系统。相关集成清单见 [项目集成参考](project-integration-checklist.md)。

## 3. 实现或排查步骤

### 3.1 用成本模型选择软边方案

| 方案 | 额外工作 | 优势 | 常见限制 |
| --- | --- | --- | --- |
| 降分辨率＋双线性 | 更小 RT 的绘制与线性重建；若原流程已支持，可无额外 Blur Pass | 低成本获得基础过渡 | 细轮廓丢失、边缘量化、软化宽度不稳定 |
| 主 Pass 邻域滤波 | 每个输出像素增加采样 | 小核接入直接 | 大半径重复读取；仍可能在全分辨率计算 |
| 两遍可分离 Gaussian | 横、纵两次滤波及中间 RT | 小到中半径可控，核定义明确 | 半径增长时核成本增加；读写带宽仍存在 |
| 多级 Dual Kawase | 下采样金字塔再上采样 | 用较小纹理实现较宽柔化，层数可分档 | 多 Draw/RT 切换；小半径未必胜过 Gaussian |
| 距离场或形态学管线 | 先构建距离/扩张信息再映射 | 适合精确宽度或多种轮廓处理 | 生成与维护成本，不能只算最终采样 |

两遍 Gaussian 可以通过可分离核与双线性合并采样优化；Kawase 则通常减少宽半径下的采样区域。公平比较需要接近的可见模糊半径和质量，不是拿两种算法的同名数值直接比较。

若源 Mask 尺寸为 `W × H`，每层宽高减半，生成 `L` 层后逐级回到源尺寸，则理想整数尺寸下：

```text
下采样输出面积 = WH × Σ(i=1..L) 4^(-i)
上采样输出面积 = WH × Σ(i=0..L-1) 4^(-i)
总处理像素面积 = (5/3) × (1 - 4^(-L)) × WH
Draw 数 = 2L
```

这个面积上界解释了为什么增加小层级不等于增加同样数量的全分辨率 Pass。但它不包含不同核的每像素采样数、RT 载入/存储、几何 Mask、最终合成、Resolve 和驱动成本。窄图、奇数尺寸、到达最小纹理后停止等情形也会偏离该公式。

若下采样每像素 `kd` 次读取、上采样 `ku` 次读取，近似读取量可写为：

```text
WH × [kd × Σ(i=1..L) 4^(-i) + ku × Σ(i=0..L-1) 4^(-i)]
```

纹理读取表达式的次数也不是物理内存读取次数；缓存、线性滤波、格式和 GPU 架构都会影响实际成本。

### 3.2 将开关、片段与材质职责分层

| 层级 | 建议承担的内容 | 原因 |
| --- | --- | --- |
| RendererFeature / 质量系统 | 是否允许附加模糊、相机过滤、资源生命周期 | 设备档位能统一禁止额外工作 |
| Timeline Clip | 角色绑定、形状模式、RT 比例、模糊层数和偏移、时序权重 | 不同镜头可以选择不同质量与覆盖范围 |
| 材质 | 噪声、流速、颜色、外缘、细节、整体显现等艺术参数 | 同一预设可在不同镜头复用 |
| 运行时快照/实例 | 本次效果最终参数与当前相机的矩阵、纹理和尺度 | 避免多个片段或相机互相覆盖 |

全局允许与片段请求取交集：全局关时跳过 Blur，片段层数为零也跳过。最后把主 Shader 的输入恢复为原始效果形状，而不是仅把已算出的 Blur 颜色乘零。

低档可从关闭附加模糊、降低 Mask 尺寸、避免不必要膨胀 Pass 入手；高档从少量层级开始，在视觉收益足够时再增加。具体默认值和设备结论归入项目 Profile。

新增序列化字段要区分新建 Clip 的初始值、旧资产缺字段时的值以及运行时非法值回退。取值范围、NaN/Infinity、防除零和零尺寸检查放在明确的边界，不能依赖 Inspector 永远写入正常数据。

### 3.3 先优化整条管线，再讨论少量 ALU

| 成本来源 | 可操作的优化 | 验证方式 |
| --- | --- | --- |
| 角色重画 | 缓存目标解析、过滤无效 Renderer，确认是否重复绘制同一 SubMesh | Draw 数、CPU 提交时间和 Mask 图像 |
| 形状生成 | 实心无外扩时直用原始 Mask；UV 缩放不强制另开形状 RT | Frame Debugger 中确实少一个 Pass |
| Mask 尺寸 | 比例相对完整相机尺寸计算；避免两次缩放 | 实际 RT 宽高与边缘质量 |
| 格式与附件 | 只存覆盖率时评估单通道格式、单采样、无多余附件 | 平台格式支持、RT 内存和带宽 |
| 附加 Blur | 质量开关/层数零时直接跳过分配与绘制 | GPU 事件和 RT 列表 |
| 全屏拷贝 | 仅在后续合成确实需要原图时保留副本 | 拷贝次数及排除/替换功能 A/B |
| 主效果采样 | 删除真正不使用的分支或功能；合理使用 uniform 分支 | 编译输出、目标设备计时 |
| 材质/容器分配 | 缓存运行时实例，销毁时释放；避免每帧新建 | Profiler GC 和实例数量 |

将 `if` 改为 `lerp` 不保证省事，两个输入表达式可能都计算；“乘零”也不意味着纹理采样被跳过。减少几条乘加、删除面板参数或让计算移到 CPU，都不能替代整条链路的测量。遵循 `CTL-01`，保留可读且可验证的实现。

总帧预算是整个游戏的预算。效果耗时还受同屏角色数、重叠片段数量、最终合成分辨率、过绘制、频率与发热降频影响。没有目标设备数据时，只给成本结构和候选档位，不给固定毫秒承诺。

### 3.4 处理 RT、命令记录和材质生命周期

Blur 常用缩小层级保存中间结果，再复用不再读取的父层上采样，最后写入独立结果 RT。回写原始人物 Mask 会破坏保护输入；同一 Draw 同时读写同一 RT 也不是合法的通用反馈算法。

命令记录结束前，CPU 上的资源对象仍可能被前面已记录的命令引用。池化复用、重分配尺寸或释放资源时，检查已经排入命令的使用范围。多效果可以共享资源池，但不能在未完成的依赖之间把句柄重新指向别的内容。

参数随 Draw 变化时，确认 API 是复制参数、记录全局命令还是持有对象引用。对同一材质连续 `Set` 两种 Blur 方向，再统一执行命令，可能使早期 Draw 读到后写的值；可按管线选择命令级全局设置、受支持的属性块或独立材质实例。实际例子见 [Bloom 排查参考](bloom-toon-parity-and-debugging.md)。

每个效果开始和 Pass 结束时处理全局输入的无效状态，避免下一个效果、相机或 Editor 视图继承上一份模糊图。无绑定、材质不支持某个 Pass、片段权重为零和 Feature 禁用都有明确旁路。

Timeline 预览适合由运行时材质实例承接动态写入。暂停、拖动、退出预览、图销毁、切材质和 Domain Reload 是不同事件；不能假设某个“停止”回调只会在最终退出时触发。有关持久材质与恢复的设计沿用 [溶解与材质生命周期参考](dissolve-space-threshold-and-material-lifecycle.md)。

### 3.5 制作有差异的效果预设

先做一个不依赖强 Bloom 的灰度形状基线，再依次调：外扩与扰动 → 流动节奏 → 主体/外缘色 → 细节亮度 → 柔边 → Bloom。每次冻结其他维度，避免颜色掩盖覆盖率问题。

以下是可迁移的制作思路，不是已交付资产清单，也不表示任一专用 Shader 已支持所有能力。

| 效果目标 | 数据与参数方向 | 可能需要新增的算法 |
| --- | --- | --- |
| 火焰 | 拉长的条纹/云噪声、单向滚动、暖色主体与高亮边缘 | 若参考需要卷曲或回流，可评估二维向量扰动 |
| 灵体/粉蓝 | 柔和流动细节、冷色主体与暖色外缘、平缓覆盖率 | 已有两色分解常可直接调材质 |
| 魔法 | 不同频率的云雾或符号纹理、较缓节奏、分层色带 | 环绕旋转或符文空间若不存在，需要单独实现 |
| 闪点 | 稀疏高对比细节、局部 HDR 亮点 | 真正独立闪烁需要时间调制；透明闪点需控制 Alpha |
| 七彩 | 彩色渐变或调色纹理 | 单通道细节乘固定色不能自动产生空间彩虹 |
| 黑洞 | 深色中心、明亮边环和低覆盖背景 | 背景引力扭曲需对场景色坐标采样；只改黑色不能实现折射 |

先盘点可用贴图的通道、直方图、平铺连续性、分辨率和导入设置。相似命名不代表相同噪声分布。预设验收至少包含静帧、多个时间点、近远镜头和中性背景；视频的观感还取决于速度及方向。

预设共享 Shader 时，优先只改材质值。不要为了一个粉蓝效果删除其他材质仍在用的闪点或彩虹功能；需要专用化时保留通用版本，仅将明确范围内的材质转接到专用版本。

### 3.6 删除参数时沿依赖链裁剪

按 `CMP-01`、`ORG-03` 和 `WRK-03` 执行：

1. 保存材质全部序列化值、纹理 GUID/Scale/Offset、Keyword、Pass 和基线图。
2. 判断参数是外观必需、Clip/脚本写入、仅模式切换、未使用遗留，还是仅面板隐藏。
3. 搜索材质、动画曲线、Timeline、ShaderGUI 和代码的读写者。隐藏属性可能仍是运行协议。
4. 对专用效果，把确定恒定的模式折叠成实际路径；删除对应 Property、CBUFFER、表达式、Keyword 声明及失效材质条目。
5. 保留仍影响当前外观的细节强度、颜色、阈值等，不按“这个名字看起来可选”判断。
6. 比较固定输入、不同时间、权重、输入模式及透明颜色，确认删除只是减少能力而没有改变目标效果。

专用化不等于普遍性能提升。如果仍采同样的噪声、细节和形状图，主要收益可能是材质可读性、变体数量和维护范围，而不是明显的 GPU 降耗。

### 3.7 将试验 Shader 迁到正式目录

迁移是资源身份与接口维护工作，遵循 `ORG-01`、`ORG-02`、`DOC-03`。

| 项目 | 核对方法 |
| --- | --- |
| 真实目标工作区 | 先确认绝对工程路径、Unity 当前打开的工程、Git 根与分支；历史路径只能作为候选 |
| 文件名与 Shader 菜单名 | 分别制定命名；修改菜单名后搜索字符串查找调用 |
| Shader 身份 | 移动源文件时带走原 `.meta`，保持 GUID；新建另一种 Shader 才生成新 GUID |
| 材质身份 | 重定向 Shader 只改预期引用；保留材质 GUID 和已调好的值 |
| 代码协议 | 检查按 Pass 名查找、固定索引、属性写入、Include 相对路径和变体集合 |
| 资源加载 | 移出特殊加载目录会影响路径加载和打包收集，即使 GUID 引用仍有效 |
| 同名与残留 | 确认旧文件及旧 `.meta` 的处理结果，无重复 GUID、重复菜单名或过期引用 |

用户搜索不到资产时，先检查工程路径、目录、文件名、菜单名与 GUID。不能仅凭旧路径不存在就认定被 Git 回退；它可能已移动、重命名、尚未导入或在另一个 checkout。

迁移阶段最好只改变路径和名称，计算不动；算法优化另作一轮 A/B。比较目录相邻 Shader 的命名和集成契约即可，不机械复制 PBR 的 Forward/Shadow/Depth Pass。全屏特效只保留它真正需要的 Pass，符合 `WRK-02`。

### 3.8 使用工具建立可复现证据

| 工具 | 适合回答 | 不能单独证明 |
| --- | --- | --- |
| `rg` / `rg --files` | 实际资源位置、GUID 使用者、Pass/属性/写入链 | Unity 已导入并正确渲染 |
| Git status / diff / no-index | 修改范围、文本差异、意外删除 | 未跟踪资源的完整正确性 |
| 文件哈希与清单 | 当前版本、迁移字节保真、安装前后漂移 | 功能与视觉正确 |
| UTF-8 文本及 YAML/JSON 检查 | 编码、元数据、保存参数、引用一致性 | Shader 平台兼容 |
| 实际管线头文件＋Shader 编译器 | 入口和宏在所选后端可编译 | Unity 导入、所有移动 API 或图形行为 |
| 固定输入离线 GPU/软件渲染 | 算法 A/B、边界条件、Alpha、时间变化 | 实际 Mask 生产、Renderer 时序和真机帧耗时 |
| Unity Console / Frame Debugger | 实际 Pass 顺序、输入 RT、材质与事件 | 所有设备性能和长时间稳定性 |
| Profiler / RenderDoc / 设备 GPU 工具 | Draw、资源、GPU 时间、带宽和瓶颈 | 不同机型的普遍性能结论 |
| Python 图像与数值工具 | 纹理检查、像素差分、统计、报告生成 | 正确模拟了所有导入和显示设置 |

PowerShell 处理中文时显式 UTF-8 读取；写入用能控制编码的文件 API，避免默认管道把中文送进原生进程后变成问号。保留已有 BOM 与换行；写完读回检查真实字符，退出码正常不代表编码正确。

外部目录写入可先生成精确交付文件和清单，备份将修改的文件，记录源哈希，再只安装清单范围。安装前若原文件哈希已变，先合并并发修改，不覆盖用户新内容。这个流程同样适合材质迁移和文档更新。

`git diff` 不包含全部未跟踪文件；新增 Shader、材质和 `.meta` 需要额外检查。`git diff --no-index` 的退出码 `1` 也可能只是“存在差异”，与工具错误不同，应结合输出解释。

## 4. 风险与不适用边界

| 常见误判 | 更准确的判断 |
| --- | --- |
| Kawase 一定比两遍 Gaussian 快 | 与半径、核、分辨率、RT 切换和平台有关，以同等视觉效果实测 |
| Mask 变小，整个效果就按面积同比变快 | 主合成可能仍全分辨率，几何与拷贝也不一定减少 |
| 新开关关闭后没有成本 | 需要确认没分配、没 Draw、没采样，并有正确回退输入 |
| 删掉属性就是删掉功能 | 实现、Keyword、脚本写入和材质序列化都需检查 |
| 文件可编译，当前场景就已验证 | 离线入口、Unity 管线和目标平台是不同证据层 |
| 同一材质截图一致，所有预设都可替换 | 其他材质可能使用已裁剪的能力 |
| 同 GUID 一定加载正常 | 路径加载、资源收集、变体剔除和运行时字符串还可能失效 |
| 测试工具已在 Temp 中，所以长期可复现 | 临时目录会清理；保留关键版本与结果，并在需要时正式化工具 |

## 5. 验证与回退

### 5.1 根据改动选择证据层

| 变更 | 最小充分验证方向 | 扩大验证的触发条件 |
| --- | --- | --- |
| 只移动/重命名资源 | GUID/依赖/值保真、导入与搜索、字符串调用和构建收集 | 涉及按路径加载或 Pass 名协议 |
| 材质调色/换贴图 | 参数读回、纹理导入、动态与近远视觉 | 新采样模式或透明度语义变化 |
| 删除模式/分支 | 所有入口编译、代表输入 A/B、相关材质迁移范围 | 共享 Shader 或 Keyword/构建变体变化 |
| Mask 深度/Blur/RT 调度 | 实际 Unity 中间 RT、遮挡、相机和重叠 Clip | 多平台、MSAA、XR、动态分辨率 |
| 移动端正式接入 | 目标 API 编译、典型与压力场景、真机 GPU 时间/热稳定性 | 更高分辨率、同屏数或质量档变更 |

静态检查通过后不必无目的重复；新增变化、失败或尚未覆盖的风险才是追加检查的依据。

### 5.2 固定输入做 A/B

冻结场景色、人物 Mask、相机、材质、纹理导入、时间、曝光、输出尺寸和图形后端。比较多个时刻，而不只一张预览图。记录最大误差、差异像素比例及差异图；边缘区域与主体保护分别检查。

测试样本可覆盖：权重零/中间/全量、无绑定、空/满 Mask、模糊/原始输入、低分辨率、实心/空心、不同外扩模式、颜色 Alpha、细节强度零。比较结果为零只证明这些输入与实现版本在该后端一致。

生产端和消费端分别验收：把人工模糊图送入 Shader 可以验证“能否消费软 Mask”，不能证明真正 Blur 金字塔的顺序、核、纹理尺寸和绑定都正确。

### 5.3 留下可执行的交付记录

交付记录包括：最终资源路径/身份、改动原因、保留和裁剪的行为、验证输入与版本、已通过/未验证项、质量建议的依据、回退所需文件。功能使用说明继续放在资产附近，规则库只存可复用方法及项目事实索引。

回退单位跟着变更走：材质恢复原参数与引用；专用化恢复原 Shader 引用；迁移恢复同 GUID 的原路径并处理新路径残留；RT 调度恢复生成/绑定/消费整条契约。没有用户保存的 Timeline 资产时，不把“内存里曾配置过片段”写成可恢复的持久交付。

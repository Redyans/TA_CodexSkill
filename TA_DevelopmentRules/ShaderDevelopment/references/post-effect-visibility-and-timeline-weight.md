# 后处理整体显隐与 Timeline 权重参考

> 类型：REFERENCE；适用范围：全屏后处理、描边、光效与 Timeline 材质参数控制；使用前提：以目标项目的合成公式、材质实例、权重写入者和渲染时序重新验证。
>
> 本文提供实现选择和排查方法，不增加 CORE。具体工程的属性名、源码路径、版本和验证状态见 [ProjectACG 后处理 Profile 第 9 节](../../TimelineDevelopment/Profiles/ProjectACG/custom-post-processing-timeline.md#9-整体显隐参数与-timeline-控制2026-10-20)。功能操作说明继续维护在源码旁。

## 1. 适用场景

### 1.1 先定义“出现”的含义

整体淡入淡出通常需要一个连续的视觉权重，但“强度”“透明度”“溶解”和“禁用渲染”对应不同职责。先确定预期，再决定参数位置。

| 制作目标 | 参数控制对象 | 端点与表现 | 适用边界 |
| --- | --- | --- | --- |
| 整体淡入淡出 | 效果对画面的贡献或覆盖率 | 0 恢复输入，1 保持原效果，中间连续过渡 | 保持形状、扰动、宽度和颜色配方 |
| 发光亮度 | HDR 颜色或发光增益 | 0 关闭发光，但基础覆盖可能仍在 | 调亮暗，不能自动替代整体显隐 |
| 噪声溶解 | 空间噪声与阈值比较 | 像素按分布出现，可附带边缘光 | 需单独定义阈值端点和抗锯齿 |
| 从下到上扫描 | 指定坐标空间内的位置阈值 | 空间顺序可见 | 需定义空间、范围、方向与动态对象行为 |
| 停止整段渲染 | CPU 调度、资源生产与消费 | 省掉对应工作 | 需证明没有其他消费者、替换和恢复职责 |

已有效果只缺总控时，优先在已有合成位置引入连续权重。若制作目标还包括溶解或扫描，再为形状分布增加独立参数；将两种语义塞进同一“强度”容易导致端点和曲线难以维护。

### 1.2 可以迁移的经验

- 参数调查要同时回答“有没有”“谁写入”“哪里消费”，仅看材质面板不够。
- 整体显隐通常控制最终效果贡献；只改颜色可能留下黑边，只改输出 alpha 可能完全无效。
- 材质总控与播放系统权重分开，可使静态材质和自动淡入淡出各自有明确所有者。
- 画面消失、Fragment 提前返回、整段 Pass 停止执行，是三个不同的验证结论。

### 2.2 参数调查表

| 检查层 | 读取内容 | 要回答的问题 |
| --- | --- | --- |
| 材质声明 | `Properties`、默认值、Range、隐藏标记、ShaderGUI | 是视觉总控、颜色强度还是系统内部权重？ |
| GPU 声明 | CBUFFER、全局变量、类型与精度 | 声明与读取是否同名同类型？属于材质还是全局？ |
| Fragment 与合成 | 采样、Mask、Blend、返回值、后续 Composite | 参数是否真的影响目标贡献？后续是否覆盖？ |
| CPU 写入 | `SetFloat`、属性 ID、动画、曲线、RendererFeature | 最后一次写入发生在哪里？ |
| 材质实例 | 源资产、运行时副本、共享材质、MPB | 面板正在修改的对象是否是绘制使用的对象？ |

## 3. 实现或排查步骤

### 3.1 先画出数据流与所有权

常见链路如下，实际项目的顺序以源码为准：

```text
源材质 → 运行时材质复制 → 属性曲线覆盖 → 播放权重写入
       → Mask / 形状 / 模糊 → 效果 Fragment → 可选 Composite → 相机目标
```

为每个控制量注明初值、写入者、写入时机、消费位置、退出恢复方式。内部播放权重若每帧由 Feature 写入，就不适合同时交给美术曲线控制；可以新增独立视觉属性，并在 Shader 内组合。若框架已具备等价且可独立控制的属性，则复用现有合同，避免重复总控。

### 3.2 从合成公式确定总控落点

令输入颜色为 `S`，完整效果输出为 `F`，总权重为 `g`。若合成可按线性颜色差表达，常见形式是：

```text
Output = S + g × (F - S) = lerp(S, F, g)
```

它给出可直接检查的端点：`g=0` 时输出 `S`，`g=1` 时输出 `F`。它描述当前合成颜色域内的数值关系，不保证感知亮度线性；颜色空间、曝光与 Bloom 会影响视觉节奏。

对于主体与外缘的覆盖式合成，设它们原始覆盖率为 `a`、`b`，对应颜色为 `C`、`R`：

```text
原结果 = S × (1-a-b) + C × a + R × b
加总控 = S × (1-g×a-g×b) + C × (g×a) + R × (g×b)
```

这样既降低效果贡献，也恢复被覆盖的背景。如果只写 `C *= g`、`R *= g`，背景仍按原覆盖率被扣除，效果会变暗甚至留下黑块。若发光包含在 `C`、`R` 中，它会随覆盖率一起退出，无需再乘一次 `g`；重复相乘会改变过渡曲线。

覆盖式权重和 HDR 颜色分别处理：权重可钳制到 0–1，HDR RGB 保留允许的高亮范围。背景 alpha 若由管线要求保留，就继续返回输入 alpha。对于 `Blend Off` 的全屏 Pass，只降低输出 alpha 不会自动淡出 RGB。

### 3.3 实现一个最小控制单元

下面是覆盖式合成的 HLSL 参考函数，可嵌入已有 HLSL 编译单元；调用方提供已采样的输入、颜色、覆盖率和保护 Mask。它不包含 ShaderLab、纹理绑定或 Pass 定义，也不是项目属性合同。

```hlsl
half4 CompositeCoverage(
    half4 scene,
    half3 coreColor, half3 rimColor,
    half coreCoverage, half rimCoverage,
    half visibility, half playbackWeight,
    half protection)
{
    half gain = saturate(visibility) * saturate(playbackWeight);
    if (gain <= 0.0h)
        return scene;

    gain *= 1.0h - saturate(protection);
    half a = coreCoverage * gain;
    half b = rimCoverage * gain;
    half3 color = scene.rgb * (1.0h - a - b)
        + coreColor * a + rimColor * b;
    return half4(color, scene.a);
}
```

此函数假定调用方的两层覆盖语义有效，例如互斥的主体与外缘满足覆盖率总和不超过 1。任意叠层若不满足该条件，应按原有 Over、加法或其他混合模型重新推导，不能直接复制此公式。

实际接入时，在材质属性区增加独立的 0–1 视觉参数，在原有每材质 CBUFFER 声明，并在最终合成处读取。默认设为 1 通常有利于保持旧表现，但旧材质导入、序列化和 Bundle 加载仍需实测。参数字符串若被脚本消费，沿用项目已有属性 ID 管理方式。

若提前返回能位于噪声、形状和细节采样之前，它可以减少后续 Fragment 工作。上面参考函数只能跳过函数内部计算，不能撤销调用前已完成的纹理采样；实际早退应放到对应工作之前。是否值得增加分支按 `CTL-01` 的目标设备证据判断。

### 3.4 准确计算 Timeline 与材质的组合

不要只凭“Clip 权重”和“属性曲线”的名称猜结果。某类混合器会先把曲线目标与源材质插值，随后 Shader 再乘播放权重。令：

```text
m    = 源材质视觉参数
q(t) = 当前曲线目标；若实现带幅度系数，还需乘该系数
w    = clamp01(Clip 输入权重)
v    = lerp(m, q(t), w)
g    = clamp01(v) × w
局部覆盖权重 = g × (1 - protection)
```

| 输入 | 材质实例中的 v | Shader 总权重 g | 含义 |
| --- | --- | --- | --- |
| `m=1, q=0, w=1` | 0 | 0 | 曲线完全接管后可以关闭 |
| `m=1, q=0, w=0.5` | 0.5 | 0.25 | 半权重时曲线 0 仍有残留 |
| `m=1, q=1, w=0.5` | 1 | 0.5 | 曲线保持完整强度，由播放权重淡入 |
| `m=0, q=1, w=0.5` | 0.5 | 0.25 | 两段权重组合产生非线性过渡 |

这既不能一概简化为 `curve × weight`，也不总是 `weight²`。没有该属性控制器时，`v` 通常来自源材质，但仍应检查每帧复制规则。多个控制器控制同一属性时，继续追查遍历顺序和仲裁，不能承诺自动相加。

制作时可以让材质总控负责静态强度、Clip 淡入淡出负责播放包络；也可以在 Clip 满权重区用属性曲线塑造出现节奏。需要绝对曲线值或禁止重复缓动时，应明确混合器合同再调整，避免为一个 Shader 顺手改动所有轨道的混合语义。

### 3.5 检查材质实例和停帧预览

常见可靠路径是复用运行时材质实例，每次求值先复制源材质，再应用曲线。编辑器数值变化还要触发一次当前时间求值；仅有复制代码、只重绘窗口或只保存资产都不能证明 GPU 使用了新值。

按 [Timeline 后处理参考](../../TimelineDevelopment/references/timeline-custom-post-processing-renderfeature.md) 检查数值刷新和图结构刷新。数值修改若每次重建 PlayableGraph，可能带来相机跳动、动画重采样或状态闪烁；绑定或结构变化则可能确实需要重建。具体刷新 API 随 Timeline 版本核对。

暂停与销毁分开处理：暂停仍可能需要保留预览状态；图销毁负责释放其拥有的实例与注册。共享材质资产、其他 Director 和其他相机的状态不能被一个 Clip 的清理误删。

### 3.6 “参数不生效”的定位矩阵

| 现象 | 优先查证 | 对应处理方向 |
| --- | --- | --- |
| 材质面板没有总控 | 隐藏属性、自定义 ShaderGUI、实际 Shader 引用 | 先判断是否已有等价参数，再增加独立可编辑属性 |
| 参数能选但播放后被复位 | 最后写入者、Feature、Animator、重复控制器 | 明确所有权；内部权重与视觉总控分离 |
| 改源材质无变化 | 当前绘制材质、实例复制、曲线覆盖、是否重新求值 | 沿源资产到 GPU 的顺序逐层检查 |
| 曲线为 0 仍残留 | 混合基值、幅度系数、Clip 权重、后续 Composite | 代入真实公式，分离效果与替换输出 |
| 变成黑色而非消失 | RGB 被乘小但背景扣减未恢复 | 在贡献或覆盖率层加入总控 |
| 输出 alpha 为 0 仍可见 | Blend 状态、目标 RT 是否使用 alpha | 按实际 RGB 合成合同处理 |
| 只剩细节光或外缘 | 部分分支绕开总控，或发光在后续独立叠加 | 列出所有视觉贡献及其最终合成位置 |
| Scene 有效、Game 无效 | 当前 Renderer Data、相机目标、Feature 与 Pass 时序 | 用 Frame Debugger 确认实际执行链 |
| 停帧修改不更新或画面闪动 | 编辑器变更监听、Undo、求值与重建范围 | 核对刷新级别及去重，不以反复 Repaint 掩盖 |
| 0 时 GPU 耗时仍高 | Mask、Blur、RT 分配、全屏复制与 Composite | 区分 Fragment 早退和 CPU 调度优化 |

### 3.7 工具与可复现调查

| 工具 | 适用工作 | 证据边界 |
| --- | --- | --- |
| `rg --files`、`rg -n` | 定位 Shader、全部属性读写者、材质副本和绘制入口 | 查到代码不代表该分支实际执行 |
| `git diff`、`git show`、`git log` | 确认最小修改、旧版本端点与来源 | 已提交改动用提交差异检查，工作区无 diff 不等于没有实现 |
| `git diff --check`、`Get-FileHash` | 空白检查、记录证据快照、发布前后字节核对 | 不证明 Shader 可编译或画面正确 |
| Unity Shader Inspector / Console | 导入错误、目标平台编译、材质当前状态 | 编辑器成功不等于设备所有图形 API 均成功 |
| Timeline、Game/Scene、Undo | 曲线、Seek、停帧、实例与生命周期复现 | 固定时间输入，记录源值、曲线值和 Clip 权重 |
| Frame Debugger | 当前相机、Mask、Pass、RT 与 Composite 顺序 | 帧捕获用于定位；性能由测量工具确认 |
| Unity Profiler / GPU 工具 | CPU、GPU、GC、Draw 和带宽变化 | 同场景同设备比较，记录分辨率和质量档 |
| 显式 UTF-8 文件读写 | 中文参数、Markdown、脚本和检查结果 | 保留原 BOM/换行，回读并看 diff，避免终端编码二次损坏 |

从目标工程根目录先用 `rg --files` 确定真实目录，再检索。Windows 下把 `-g` 用作文件过滤，避免把含通配符的路径当成一个必定存在的文件名。例如：

```powershell
rg --files -g '*.shader' -g '*PostProcessing*.cs' Assets
rg -n -g '*.shader' 'Properties|CBUFFER|Blend|SV_Target' Assets
rg -n -g '*.cs' 'CopyPropertiesFromMaterial|SetFloat|ApplyProperties|GetPropertyNames' Assets
git diff --check
```

锁定真实属性后，再按精确名称搜索 Shader、脚本、材质和动画资产。避免全工程反复输出长文件；先定位行，再读取函数上下文和直接调用者。

## 4. 风险与不适用边界

### 4.1 合成与视觉边界

- 加法、乘法、屏幕扭曲、颜色分级与覆盖式效果的总控落点不同。扭曲还可能通过减少采样偏移淡出；先定义想保留的行为，再比较最终颜色插值与输入插值。
- 多 Pass 串联时，所谓输入是当前 Pass 接收到的画面，不一定是原始场景。逐效果显隐为 0，不等于恢复整个链路之前的画面。
- 角色保护、排除 Mask、替换材质和最终 Composite 属于不同职责。一支效果 Shader 的总控不会自动关闭其他分支。
- 原有采样空间、UV、屏幕边界、动态分辨率、模糊和保护算法属于独立问题。显隐任务先保持这些行为；需要修正时补充可复现证据，避免把推测记录成已修复。

### 4.2 性能与兼容边界

Fragment 在权重 0 时返回输入，仍可能保留颜色采样、全屏 Draw、RT 带宽和此前的 Mask/Blur。只有查明资源依赖与其他输出后，才考虑 CPU 层跳过；不能依据一个材质属性直接取消整个 Feature。

连续数值控制通常不需要新增 Keyword、Pass 或 RT。没有新增变体来源，只能说明此次变体增量没有来自新关键字，不能据此给出最终平台变体总数或零成本承诺。按 `CTL-02` 和验证规则记录实际构建边界。

默认值 1 是兼容设计意图；旧材质、重导入、序列化残留、Shader 迁移及 Bundle 里已保存的值都需要验证。编辑器中能拖动新属性，不代表发布资源已经包含新 Shader。

## 5. 验证与回退

### 5.1 最小充分验证矩阵

| 层级 | 检查输入 | 通过条件 |
| --- | --- | --- |
| 静态 | 声明、CBUFFER、属性写入者、合成公式、最小 diff | 名称/类型一致，权重无漏乘或重复乘，Pass 与资源合同符合预期 |
| Unity 编译 | Shader 重导入、代表材质、目标图形 API | 无编译错误、粉材质和缺失引用 |
| 显隐端点 | 0、0.25、0.5、1；完整播放权重 | 0 恢复该 Pass 输入，1 对齐基线，中间平滑无黑边或孤立发光 |
| 混合组合 | 源值 0/1、曲线 0/1、Clip 权重 0/0.5/1、交叠 Clip | 与实际混合公式一致，重复缓动符合制作意图 |
| 画面保护 | 主体、外缘、细节光、保护/排除区域、HDR、输入 alpha | 总控覆盖预期贡献，保护与 alpha 合同保持 |
| 运行环境 | Game/Scene、多相机、多对象、分辨率变化、屏幕边缘 | 无串材质、串 Mask、异常裁切或意外覆盖 |
| 编辑器生命周期 | 停帧改材质、改曲线、Undo、Seek、Pause、Stop、图销毁和重开 | 最新值可见，实例不泄漏，退出恢复符合所有权 |
| 资源与性能 | 旧材质重导入、实际 Bundle、目标设备 A/B | 新参数实际可用；Pass、RT、CPU/GPU 与 GC 变化有记录 |

对于无引擎自动化条件的局部改动，可以先交付静态证据和待验矩阵；状态写“源码推导”或“未实测”，不能写成已通过视觉验收。HLSL 参考函数同样需要在目标工程编译后才能视为已验证实现。

### 5.2 回退与经验沉淀

先保留源材质、时间点、画面和源码基线。若新增参数默认 1，恢复该值并停用对应属性控制器可作为视觉回退候选；还要确认播放权重、其他动画写入和后续 Composite。代码回退按原提交差异做最小恢复，保留既有 `.meta` 与序列化标识。

交付记录保留“现象 → 根因 → 最小修正 → 源码证据 → Unity/设备验证 → 未验证项 → 回退”。已存在的规则由稳定 ID 引用；项目版本、字段与证据放入 Profile。按 `EVO-01`，有明确复现与验证的经验再考虑升级规范，避免将一次实现写成所有 Shader 的唯一方案。

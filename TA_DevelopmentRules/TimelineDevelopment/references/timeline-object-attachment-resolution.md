# Timeline 目标解析与嵌套挂点跟随参考

> 类型：REFERENCE；适用范围：Timeline 上的对象需要按名称或相对路径解析到场景/模型里的某个节点（挂点、插槽、特效点、音效点），尤其是轨道不绑定对象、需要跨嵌套 Timeline 向上查找、以及同框出现多个同名模型的场景；使用前提：必须以目标 Unity/Timeline 版本的 `PlayableDirector`、`ControlPlayableAsset` 与 `TrackAsset.outputs` 行为重新验证。
>
> 关联规则：`TML-ARC-01`、`TML-ARC-02`、`TML-ARC-03`、`TML-EDT-01`。当前模块入口见 [Timeline 开发规则](../README_Tech_TimelineDevelopmentRules.md)；编辑期刷新与恢复语义见 [Timeline 片段参数预览刷新与运行时数值同步参考](timeline-preview-refresh-and-live-value-sync.md)；解析正确但快速动画下仍有动态偏差时，见 [Timeline 动画后跟随与 Playable 生命周期参考](timeline-post-animation-follow-and-playable-lifecycle.md)。

## 1. 适用场景

- 轨道不绑定对象，但目标要跟随某个对象上的挂点（武器点、拖尾点、特效点、道具插槽）。
- 同一个功能需要"绑定轨道"和"自动解析轨道"两个变体：一个强制绑定指定对象（不限定是角色模型，任意 GameObject 及其子层级都可作为挂点来源），一个完全不绑定、靠自动解析。
- 子 Timeline 里的挂点跟随需要识别主 Timeline 的挂点。
- 同一 Timeline 里有两个相同角色模型，挂点名称完全一致。
- 想让"找不到挂点"从运行时日志提前到编辑器选片段时就报错。

本参考不适用于：固定的、编译期已知的对象引用（直接序列化引用即可）；也不适用于需要在运行时动态创建挂点的流程。

## 2. 前提与依赖

### 2.1 统一解析入口

把解析做成**无状态工具类**，运行时可执行代码与编辑器校验共用同一份实现。推荐签名形态：

```csharp
public static bool TryResolve(
    PlayableDirector director,
    Transform bindingRoot,          // 非空 = 绑定优先；null = 自动解析
    string mountText,               // 名称或相对路径
    out Transform mount,
    out MountResolveFailure failure,
    out string firstHitOwner,       // 歧义提示用的首个候选根
    bool forceRefreshNestedLookup = false);
```

配套的失败原因枚举至少区分：`None` / `NoBinding` / `NotFound` / `Ambiguous`。把原因枚举化，运行时日志与编辑器红字才能说清"是没绑、没找到，还是命中多个"。

### 2.2 查找文本的三种写法

| 写法 | 例子 | 语义 |
| --- | --- | --- |
| 相对路径（含分隔符） | `Bip001/Bip001 Pelvis/R_Hand` | 从候选根的子层级开始逐级精确匹配，**失败不得降级为名字查找** |
| 名称（无分隔符） | `R_Hand` | 在候选根下做深度优先查找（含候选根自身），命中多个算歧义 |
| 候选根自身 | `.`，或直接写候选根的名字 | 解析结果就是候选根本身，用于"整块对象跟随另一个对象" |

路径写法是唯一可靠的消歧手段：另一个模型里通常不存在同一条路径，所以照抄路径就能精确指定。若路径失败后自动退回名字查找，消歧能力会立刻失效。

两个可选的宽松处理，能显著减少美术填错：

- **首段是候选根自己的名字时按根处理**：候选根叫 `Bip001` 时，`Bip001/Bip001 Pelvis/R_Hand` 与 `Bip001 Pelvis/R_Hand` 等价。实现上先按"从子层级开始"走一遍，没命中再判断首段是否等于候选根名，避免与"根下恰好有同名子节点"的正常情况冲突。
- **开头 `./` 只表示"从候选根出发"**，在归一化阶段去掉，`./子节点` 等价于 `子节点`；单独的 `.` 仍表示候选根自身。

把候选根自身纳入可选目标是必要的：让整块模型 / 道具跟随另一个对象时，不应该强迫用户先在模型里补一个空挂点。

### 2.3 候选范围：Director 链

自动解析按"当前 Timeline → 嵌套它的主 Timeline → 更外层"的顺序遍历，每个 Director 上查两处：

1. Director 自身所在的层级（Timeline 直接挂在模型 / 物体根节点的情况）；
2. 该 Timeline 各轨道绑定的对象（一般是动画轨绑定的角色模型）。

### 2.4 父 Director 只能反查

`PlayableDirector` 与 `PlayableGraph` **没有**父指针，子 Timeline 无法直接向上问"谁控制我"。可用两条规则互补：

| 方式 | 做法 | 覆盖情况 | 限制 |
| --- | --- | --- | --- |
| 层级规则 | `GetComponentsInParent<PlayableDirector>(true)` | 子 Timeline 的 Director 与主 Timeline 挂在同一层级树里 | 子 Timeline 不在主 Timeline 层级里时失效 |
| Control Track 反查 | 遍历场景中的 `PlayableDirector`，检查其 Control 轨片段的 `sourceGameObject.Resolve(parent)`、`updateDirector`、`searchHierarchy` 是否指向自己 | 通过 Control Track 嵌入的子 Timeline | 需要全场景扫描；改用脚本手动控制 Director 的嵌套识别不到 |

两种方式要合并成一条链（去重 + 环检测），而不是二选一。

## 3. 实现或排查步骤

### 3.1 绑定优先，有绑定时不兜底

`bindingRoot != null` 时只在该根下解析；找不到就返回 `NotFound`，不继续去父 Timeline 或其它轨道兜底。否则"绑定"这个显式意图会被静默绕过，美术以为自己控制住了范围，实际仍可能跟错模型。

### 3.2 歧义必须显式失败

自动解析命中两个**不同**的目标时，判定为 `Ambiguous`：不跟随、打错误日志、不猜。

- 同一个 Transform 被多条路径重复命中（例如模型既挂在 Director 层级上、又绑在动画轨上）**不算**歧义，按同一目标去重；
- 歧义日志与编辑器红字都要列出**全部**候选，格式建议"模型名（挂点相对路径）"，让用户可以直接把括号里的路径抄进字段。

### 3.3 自动解析命中多候选时的处置路径

按顺序给用户三条出路，面板提示里写清楚：

1. 两个候选路径不同 → 把字段从名称改成其中一条相对路径；
2. 两个候选路径完全相同（同一模型复制出的多个实例）→ 改用绑定轨，把目标模型显式拖到轨道 Binding 上；
3. 某个候选本不该被搜到（多余的绑定）→ 清掉那条绑定，让自动解析回到单选。

### 3.4 候选根自身作为目标的注意事项

- 绑定轨上 `.` 的含义唯一（就是轨道绑定对象），可以直接用；
- 不绑定轨上 `.` 会落到"当前候选根"上，每个候选根都会命中一次，因此通常判定为歧义——这与"绑定优先"不冲突，属于预期行为，提示里应引导用户改用绑定轨；
- 下拉框要把候选根自身列进候选列表（建议第 0 项，显示成可读文案如 `.（对象自身）`，写入时仍是 `.`），否则用户看不到这个能力；
- 命中结果回显时，候选根自身要显示"自身"而不是留空路径，避免看起来像没解析到。

### 3.5 缓存与限流

反查父 Director 要扫场景，必须加保护：

- 链结果限时缓存（例如 1 秒），避免"一直找不到"时每帧扫场景；
- 缓存条目数上限 + 淘汰，避免长时间运行后无界增长；
- 深度上限（例如 8 层）与环检测，避免异常嵌套造成死循环；
- 编辑器校验传入"忽略缓存"参数，保证面板显示的是本次结果；
- 自动解析命中列表用可复用缓冲，避免每帧重试时分配。

### 3.6 编辑器提前校验

选中片段时立刻用同一份解析实现校验，把错误从"运行时看 log"提前到"选片段就红字"：

- 找到 → 显示匹配到的挂点名与相对路径；
- 挂点为空 / 找不到 → 红字，并区分"绑定模型里找不到"与"自动解析找不到"；
- 绑定轨未绑模型 → 红字提示先绑模型；
- 自动解析歧义 → 红字列出全部候选与处置建议；
- 校验结果按"查找文本 + 绑定对象 + Director"缓存，不要每次重绘都重扫层级；
- 绑定轨的片段面板可以把绑定模型的挂点直接列成下拉框（先扫一遍子层级收集路径），减少手填错误。

### 3.7 运行时失败提示

- 解析失败时目标不跟随，并打一条可定位的 Warning/Error，带**本次实际搜索过的范围**（`子 → 主` 的 Timeline 名列表）；
- 挂点解析成功前可以逐帧重试，但提示只打一次，避免刷屏；
- 挂点文本改变时重置"已记录失败"标记并重新解析，不要沿用上一次状态。

## 4. 风险与不适用边界

| 边界 | 说明 |
| --- | --- |
| 扫描成本 | Control Track 反查依赖场景全量 `PlayableDirector` 查找，属于失败或首次解析路径上的开销；命中后必须靠缓存收敛。 |
| 名称稳定性 | 名字查找要求骨架/层级命名稳定；重定向骨骼、DCC 重命名、同名节点都会让它失准，此时必须走路径或绑定。 |
| 实例复制 | 同一模型复制出的多个实例若路径一致，名称与路径都无法区分，只能改用绑定轨。 |
| 非 Control Track 嵌套 | 脚本手动设置 Director、运行时创建子 Timeline 等场景识别不到父链；诊断输出必须把"搜索范围"打出来，便于判断是"没认出"还是"确实不存在"。 |
| `ExposedReference` 上下文 | 通过 `Resolve(graph.GetResolver())` 解析场景引用时，解析器上下文来自所在图；跨 Director 复用引用要单独验证。 |
| 与混合的关系 | 本参考只管"解析到哪个目标"，不定义多个 Clip 同时跟随时的混合与优先级；那部分按模块 CORE 的混合规则处理。 |
| 与求值时序的关系 | 解析成功只证明“找到了哪个 Transform”，不证明读取的是本帧最终动画姿态；随动作速度变化的偏差应转入动画后跟随时序排查。 |

## 5. 验证与回退

| 层级 | 检查 | 通过条件 |
| --- | --- | --- |
| 绑定优先 | 绑定轨的片段绑到模型 A，场景里同时存在模型 B 的同名挂点 | 只命中 A，不出现歧义 |
| 自身作挂点（绑定轨） | 挂点字段填 `.` | 解析到轨道绑定的那个对象本身，跟随表现为整块对象跟随 |
| 自身作挂点（名字形式） | 挂点字段填绑定对象的名字 | 与填 `.` 结果一致，不出现歧义 |
| 自身作挂点（不绑定轨） | 挂点字段填 `.` | 按候选根逐个命中，多候选时报歧义并提示改用绑定轨 |
| 路径首段是根名 | 候选根 `Bip001`，分别填 `Bip001/Bip001 Pelvis/R_Hand` 与 `Bip001 Pelvis/R_Hand` | 两种写法解析到同一个挂点 |
| 归一新式写法 | 分别填 `./子节点`、`/子节点`、`子节点//下级`、`子节点/`、`子节点\下级` | 都等价于规范的相对路径；`.` 单独出现时仍表示自身 |
| 名称查找 | 单一模型、挂点名唯一 | 用名字即可命中 |
| 路径查找 | 模型内存在重名节点 | 用相对路径命中指定节点；路径不存在时不命中 |
| 嵌套识别 | 子 Timeline 分别用"层级嵌套"和"Control Track 嵌入"两种方式挂到主 Timeline | 两种都能解析到主 Timeline 的挂点；诊断输出包含完整搜索链 |
| 歧义 | 两个同名角色同框，挂点字段填名称 | 报歧义、不跟随、列出全部候选；改填路径或改用绑定轨后恢复单选 |
| 编辑器校验 | 选片段、改挂点文本、清空字段、解绑模型 | 分别给出对应红字/提示，不依赖运行时日志 |
| 性能 | 挂点长期找不到时连续播放 | 不出现每帧场景扫描与日志刷屏（缓存与"只提示一次"生效） |
| 回退 | 解析链无法建立或不稳定 | 回退到显式绑定轨；找不到父链时在提示中说明，不静默不跟随 |

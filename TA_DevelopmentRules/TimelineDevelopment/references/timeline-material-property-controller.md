# Timeline 材质属性控制器与 Shader 开关联动参考

> 类型：REFERENCE；适用范围：通过 Timeline 曲线控制材质 Float/Range、Vector、Color 和 Shader 开关；使用前提：按目标项目的材质合同、混合方式、Unity/Timeline/渲染管线和变体保留策略重新验证。
>
> 关联规则：`TML-CMP-01`、`TML-BLD-01`、`TML-LIF-02`、`TML-EDT-03`、`TML-VAL-01`。本文为实现参考，不新增 CORE 强制规则。
>
> 配套阅读：[自定义后处理与 RendererFeature](timeline-custom-post-processing-renderfeature.md)、[Inspector 与搜索选择器](../../ToolDevelopment/references/progressive-inspector-and-searchable-property-picker.md)、[预览刷新与实时取值](timeline-preview-refresh-and-live-value-sync.md)、[ProjectACG 实现与验证记录](../Profiles/ProjectACG/custom-post-processing-timeline.md)。

## 1. 适用场景

常见需求是“既能画曲线，又能直接改一个数值”。先确认这两者是相乘、相加、覆盖还是互斥模式，不能只凭新增了一个 Float 输入框就认为完成需求。

本参考采用一种常用合同：曲线描述随时间变化的形状，数值描述幅度，结果再与源材质按 Clip 权重混合。Shader 开关沿用同一条数据流；界面的勾选框只是把幅度编辑为 0 或 1，实际开启时机仍取决于曲线和混合后的数值。

不适合直接套用的情况包括：整数枚举、贴图切换、互斥 Keyword 组、材质 RenderQueue/Blend/ZWrite 联动、复杂自定义 MaterialPropertyDrawer。它们需要独立的离散选择和状态合同。

## 2. 前提与依赖

### 2.1 先确定写入权限与属性类型

建立“Shader 声明 → 编辑控件 → 时间求值 → 混合 → 数值/Keyword 写入 → 实际 Pass”的对应关系。

| 声明或能力 | 典型编辑方式 | 运行时检查 |
| --- | --- | --- |
| Float/Range | 曲线 + 标量 | 名称存在、声明类型兼容 |
| Vector | 曲线 + 向量 | 使用 SetVector，不能按同名 Float 写入 |
| Color | 曲线 + 颜色 | 使用 SetColor，确认项目颜色空间合同 |
| 内置 Toggle 家族 | 曲线 + 勾选框 | 解析元数据，并检查是否有可操作的 Keyword |
| 系统独占参数 | 放到专门配置区 | 通用控制器不参与写入，避免一帧内被覆盖 |
| 纹理、整数枚举、自定义 Drawer | 单独设计 | 未支持时明确过滤或诊断 |

Editor 从 Shader 推导类型可减少重复配置；Runtime 仍独立校验。不能假设资产只能从当前 Inspector 产生。

### 2.2 拆清三种状态

源材质保存美术基线，控制器保存动画意图，临时材质保存当前求值结果。预览和运行时都作用于临时副本，源资产只有用户在材质 Inspector 中明确编辑时才变化。

元数据解析最好由 Editor 与 Runtime 共用的轻量组件实现，避免面板识别一种开关、播放器按另一种规则执行。组件只依赖可用的运行时 Shader API；Inspector、搜索和刷新监听留在 Editor 程序集。

## 3. 实现或排查步骤

### 3.1 先写数值公式，再画控件

以下为本参考的数学模型，符号均为示意变量：

`t = clamp01(Clip 局部时间 / Clip 时长)`

`c = curve(t)`

`目标 Float = c × 标量幅度`

`目标 Vector = c × 向量幅度`

`目标 Color = c × 颜色幅度`

`最终值 = lerp(源材质当前值, 目标值, clamp01(Clip 权重))`

例如源 Float 为 0，曲线当前值为 0.4，幅度为 3，权重为 0.5，则目标值为 1.2，最终写入 0.6。曲线恒为 1、权重为 1 时，直接编辑幅度等价于直接编辑最终值。

注意四个容易漏掉的边界：

- 乘数默认 1 是对旧曲线的中性扩展；但旧资产缺少新字段时的反序列化行为仍要在 Unity 内验证。
- 新增数组元素可能复制上一项。明确初始化曲线、幅度、类型和引用，不能只依赖字段初始化器。
- Color 相乘通常包含 Alpha；是否应只改 RGB 由消费者决定。透明度和 HDR 范围单独验收。
- Range 声明通常约束材质输入界面，不自动等价于动画曲线或乘数的合法区间。是否 Clamp 应成为明确合同，避免把强度倍率错误限制到 0～1。

Clip 权重可能还参与最终效果合成。属性的基线混合与画面合成是两个层次；不要为了“统一公式”随意删除其中一个，也不要在不知情时重复叠乘。

### 3.2 识别开关使用元数据，不猜属性名

Shader 中属性仍可能是 Float/Range，但 Drawer 属性表示其编辑语义。读取 `Shader.GetPropertyAttributes`，解析左括号前完整的 Drawer 名称；不要因为名字包含 Enabled、Toggle 或一个子串，就自动当作开关。

| Drawer | 数值语义 | Keyword 语义 |
| --- | --- | --- |
| `ToggleUI` | 勾选编辑 1，取消编辑 0 | 只编辑数值，不自动改 Keyword |
| `Toggle(keyword)` | 同上 | 达到开启条件时启用指定 Keyword |
| `ToggleOff(keyword)` | 同上 | 达到开启条件时关闭指定 Keyword |
| 无显式参数的 `Toggle` | 同上 | 按引擎 Drawer 约定推导名称并验证声明 |
| 无显式参数的 `ToggleOff` | 同上 | 按反向 Drawer 约定推导名称并验证声明 |
| 其他自定义 Drawer | 不自动推断 | 增加 Adapter 或继续用原始数值控件 |

无参数命名规则、属性 API 与 Keyword API 要对照目标 Unity 版本确认；具体推导公式属于项目 Profile。若解析到未声明的 Keyword，可保留数值编辑并提供诊断，不用字符串 API 盲目创建全局关键字。

### 3.3 Keyword 依据最终混合值切换

一种可选离散合同是 `最终值 > 0.5` 为开启，等于 0.5 为关闭；这个阈值是产品语义，不是所有 Shader 的通用规则。

如果采用该合同，顺序为：

`求曲线 × 幅度 → 与源材质混合 → SetFloat → 按最终值计算开关 → ToggleOff 取反 → 写入有效 Keyword`

例如源值为 1，目标值为 0，权重为 0.25，最终值为 0.75。用目标值直接判断会关掉 Keyword，而最终 Float 仍偏向开启，二者不一致。

Float 保留连续值，只把 Keyword 离散化。对于 `ToggleUI`，连续数值可能被 Shader 直接使用，擅自取整会破坏原来的曲线表现。若产品需要硬切换、滞回或独立开关曲线，另定合同，不把这种改变混入勾选框显示优化。

### 3.4 只操作 Shader 已声明且符合合同的 Keyword

使用目标 Shader 的关键字空间解析名称，确认有效性后再对对应材质执行 `SetKeyword`。比“通过字符串无条件启用”更容易限定影响范围。

这只能证明程序操作的是声明过的关键字。局部/可覆盖作用域、互斥组、组合约束和构建裁剪仍需检查。一个有效 Keyword 也不能证明对应变体被打入 Player；运行时不能恢复被构建剥离的变体。

元数据可按 Shader 与属性标识缓存，减少每帧读取属性数组。缓存键相同并不代表 Shader 从未重导入；若项目要求编辑 Shader 后立即生效，需要补充导入版本或显式失效机制。

### 3.5 每次求值从源基线重建当前结果

对同一效果复用临时材质时，推荐顺序是：

```text
当前效果有有效源材质
  → 副本不存在，或源材质/Shader 改变：释放旧副本并创建新副本
  → 复用副本：同步源材质属性与状态
  → 校验并应用当前控制器
  → 应用由控制器决定的 Keyword
  → 提交这一帧的效果请求
```

先同步源，再应用控制器，可让未受控属性跟随材质编辑，让已受控属性保持动画优先。移除控制器后，自然回到源基线；不会沿用上一帧的残留 Keyword。

反向顺序会被源材质同步覆盖。只在创建时拷贝一次，则暂停期间源材质改变不会进入副本。直接使用上一帧结果做基线，会使随机 Seek 和反复 Evaluate 依赖历史顺序。

### 3.6 暂停保留与最终清理分开

Timeline 的暂停、Clip 出界、停止 Director、停止但保留 PlayableGraph、退出预览和图销毁不是同一件事。

对于需要“暂停时仍显示”的效果，可以采用：每次 `ProcessFrame` 替换当前 owner 的帧状态；Clip 出界时提交空帧；图销毁时注销 owner 并释放副本。不要只因为 `OnGraphStop` 被调用就断定应当清空，因为编辑期求值和暂停也可能经过该回调。

多 Director 使用独立 owner。清理一个 owner 不能清空其他 Director 的结果。临时资源在编辑/播放模式采用各自适用的释放方式；回调组合与停止 API 以目标版本的真实行为验证。

曲线 Seek 可重复，不表示 Shader 的 `_Time` 纹理动画也可重复。需要离线逐帧一致或录制可复现相位时，单独引入受控时间参数及 Shader 消费链路。

### 3.7 暂停改材质时补齐“触发求值”这一环

“已经每帧 Copy 源材质，暂停改值还是不刷新”的根因，可能是暂停后根本没有新的 `ProcessFrame`。链路要同时具备：

`相关源资产变化 → 请求当前时间重新求值 → 同步临时副本 → 覆盖控制器值和 Keyword → 刷新画面`

Editor 可监听资产属性变化，过滤为当前预览使用的持久源材质；忽略临时副本，避免“求值修改副本 → 监听再次刷新”的循环。同一批事件合并成一次刷新，没有活动预览图时不主动启动预览。退出或脚本重载时注销事件。

具体刷新策略见 [预览刷新参考](timeline-preview-refresh-and-live-value-sync.md)。判断是否重建图要追踪消费者：建图时复制并缓存的引用可能需要重建；每次求值都会重新读取和解析的引用，可能只需重新 Evaluate。字段类型不是唯一判断标准。

## 4. 风险与不适用边界

| 现象 | 优先排查 | 处理方向 |
| --- | --- | --- |
| 有 Float 输入但改了没变化 | 乘法/覆盖合同未实现、控制器被系统参数覆盖 | 从序列化值追到最终 SetFloat 与 Shader 消费 |
| 勾选却没有溶解等效果 | 只改数值、没改 Keyword，或变体被裁剪 | 查 Drawer 参数、最终值、材质 Keyword、Player 变体 |
| 勾选后到一半时间才开启 | 曲线或 Clip 权重尚未跨阈值 | 核对最终值，这是可能的合同结果 |
| Keyword 一闪又恢复 | 每帧源同步覆盖了刚写入的 Keyword | 改为先同步源，再写当前动画状态 |
| 停帧改材质要重播才更新 | 没有触发当前时间求值 | 仅对相关源材质请求轻量刷新 |
| 拖参数时相机跳动 | 轻量修改触发整图重建 | 核对刷新原因与实际缓存依赖 |
| 暂停效果消失 | 把图暂停当作最终清理 | 分开帧替换、空帧与销毁 |
| 停止一个 Director 影响另一个 | 全局清空代替 owner 隔离 | owner 级注销与资源释放 |
| 勾选框打开就改掉旧小数 | 重绘时回写 0/1 | 仅显式用户操作修改 |
| Editor 有效、Player 无效 | Editor API 泄漏、变体缺失、平台差异 | Player 边界编译、构建与目标设备验收 |

## 5. 验证与回退

验证可以按成本分层，但结论分开记录：

| 层级 | 建议用例 | 证明范围 |
| --- | --- | --- |
| 静态 | 元数据解析、类型检查、Editor/Runtime 依赖、源资产写入点 | 发现明显错误，不能证明宿主行为 |
| 子集编译 | Runtime、Editor、测试代码分别覆盖；Runtime 去掉 Editor define | API/语法层面的补充证据 |
| EditMode 回归 | 真实 Director：暂停、Seek、出界、Stop、多 owner | 运行测试后才可声称这些路径通过 |
| 控制器数值 | 恒 1、变化曲线、幅度 0/1/负数、部分权重 | 符合公式、源基线与类型合同 |
| 开关 | 正向、反向、数值型、阈值上下与等于阈值 | Float 与 Keyword 一致，无全局污染 |
| Inspector | 搜索、勾选、Undo/Redo、多选、无操作重绘 | 数据写入可控，旧配置不被自动归一化 |
| 生命周期 | 改源、删控制器、换 Shader、重导入、退出预览 | 无残留状态或副本泄漏 |
| 渲染与构建 | Frame Debugger、构建变体、目标设备 | 实际 Pass 和最终画面符合预期 |

离线编译组织与局限见 [Unity Editor 脚本离线编译校验](../../ToolDevelopment/references/unity-editor-script-offline-compile-verification.md)。测试源文件编译成功只证明测试能参与编译，不证明 NUnit 已执行。

回退按层进行：先把面板切回完整数值编辑，保留曲线与幅度数据；再单独回退开关 Adapter、刷新监听或条件显示。暂不支持的自定义 Drawer 可退回数值控件并提示边界。恢复旧运行时代码前，检查新增幅度字段和已保存资产，避免旧代码忽略幅度导致结果改变。

# Timeline 重复生成、手工内容保护与收尾镜头参考

> 类型：`REFERENCE`；适用范围：由 Editor 工具生成、随后交由美术手工编辑的 Timeline、Prefab 和演出资源。使用前以目标工程代码、资产和包版本重新验证。
>
> 本文提供实现、排查与验收方法，不新增 CORE 强制规则。规则入口：[Timeline 开发模块](../README_Tech_TimelineDevelopmentRules.md) 的 `TML-DOC-01`、`TML-CMP-01`、`TML-ARC-03`、`TML-VAL-01`，以及 [工具开发模块](../../ToolDevelopment/README_Tech_TAToolDevelopmentRules.md) 的 `TOOL-CMP-01`、`TOOL-OPS-01`、`TOOL-OPS-02`、`TOOL-VAL-02`。

## 1. 适用场景

当工具需要“再次生成，但保留别人手调的内容”，或者需要在演出结尾补一个返回相机片段时，先明确三个对象：**生成器拥有的数据、作者拥有的数据、播放时注入的数据**。同一个 Timeline 里可能同时存在这三类数据，不能用“文件没删”代替“内容和行为都保留”。

本参考可用于技能演出、剧情、抽卡、相机、特效和道具生成工具。项目名称、固定轨道名、具体相机节点、末尾秒数、验证记录见 [ProjectACG 重复生成与收尾镜头案例](../../ToolDevelopment/Profiles/ProjectACG/ultimate-skill-timeline-regeneration.md)。

## 2. 前提与依赖

### 2.1 先把“保留”拆成可检查的合同

| 层次 | 需要确认 | 单看什么会误判 |
| --- | --- | --- |
| 资源身份 | 路径、GUID、子资产身份、外部引用。 | 只看输出文件名相同。 |
| 结构 | 根轨、分组、子轨、Marker、节点及排序。 | 只看轨道数量相同。 |
| 内容 | Clip 资源、开始时间、时长、参数与曲线。 | 只看 Clip 名称相同。 |
| 绑定 | Track Binding、ExposedReference、目标对象身份。 | 只看引用键还存在。 |
| 播放范围 | 总时长、帧率、时间缩放、外推、停止模式。 | 只看片段仍在资产里。 |
| 表现与恢复 | 镜头输出、FOV、混合、显隐、Stop/Seek/重播。 | 只看静态编译成功。 |

例如：手工片段仍在第 6 秒，但生成器把主 Timeline 缩到 4 秒，资源层面保留了，演出行为却发生了变化。又如：手工轨道对象没变，但绑定的 Prefab 子节点被重建，轨道可能已经不能驱动原对象。

### 2.2 写清更新矩阵

每个按钮或命令都可以用下表描述，生成、校验、摘要和文档共用这份含义。

| 操作 | 读取 | 写入 | 特别检查 |
| --- | --- | --- | --- |
| 生成模块资源 | 源模型、动画、模块参数。 | 该模块派生资源。 | 是否意外写主 Timeline。 |
| 组装单模块 | 已有主资源及该模块产物。 | 指定轨道、容器、相关绑定。 | 缺结构时是否扩大为完整组装。 |
| 完整组装 | 全部输入及已有主资源。 | 所有工具拥有的轨道和节点。 | 手工轨道、节点覆盖、总时长。 |
| 保存嵌套资源 | 嵌套实例的当前编辑结果。 | 选定源 Prefab。 | 是否误存外层 owner 或其它脏资产。 |
| 配置预览 | 场景角色、相机、Director。 | 当前场景实例或临时会话。 | 是否把场景引用写回 Prefab 资产。 |

“局部操作”只是入口名称。最终写入集由实际调用链决定，尤其要检查“找不到目标就调用完整组装”的分支。

### 2.3 建立证据基线

记录工作区、分支、提交、未提交差异、Unity/包版本、输入资源、操作 Scope 和生成前资产快照。历史聊天、README、旧截图、缓存编译响应文件都可能早于当前源码。

迁移时可以保留本文的方法；节点名、轨道类型、私有序列化字段、默认 FOV、时间常量和运行时绑定契约则重新核对。没有实际调用点的辅助方法不能作为功能已接入的证据。

## 3. 实现或排查步骤

### 3.1 从完整链路确定最小修改点

建议沿以下顺序阅读代码：

```text
按钮/命令 → 操作 Scope → 输入校验 → 收集有效资源
          → 计算时间区间 → 更新 Timeline → 更新 Prefab
          → 持久对象重绑 → 保存后回读 → 按 Scope 自检
```

新增收尾镜头时，至少涉及时间计算、两种组装入口、去重、相机绑定和生成后验证。只在“完整生成”循环后追加片段，容易遗漏“镜头组装”；只创建 Clip 而不写 Director 引用，则会留下一个目标为 `None` 的片段。

可以把 UI、预设、生成数据、序列化写入、验证分开维护，继续使用小的职责方法。扩展现有工具时按真实职责拆分，不为了这一项功能引入新运行时管理器或另一套资源管线。

### 3.2 选择适合的所有权识别方式

| 方式 | 适用情况 | 局限与补偿 |
| --- | --- | --- |
| 类型 + 精确名称 | 现有工具改动小，生成规则稳定。 | 作者可误用同名轨；同名副本可能被清理。预检列出冲突。 |
| 类型 + 明确历史前缀 | 清理已知旧版产物。 | 前缀过宽会误伤手工轨；保留迁移白名单。 |
| 独占 Group/容器 | 自动内容和手工内容可以分区。 | 被引用子节点重建仍会影响容器外对象。 |
| 持久 owner ID + 稳定条目 ID | 长期多人混合编辑、频繁重排。 | 需要兼容旧资产、迁移和版本管理，不能宣称现有命名方案已经具备。 |

索引式 ID 能保证相同输入的重复运行，却不一定保证重排后的语义身份。例如第 2 个镜头移到第 1 位，按序号命名的引用键可能仍存在，但对应内容已经变化。设计时区分“列表位置”和“资产身份”。

未知轨道通常保留原对象；已知工具轨道按合同更新；有歧义的所有权冲突先给出诊断。Marker、轨道级属性和子资产也单独纳入检查，不能假设遍历 `GetClips()` 已经覆盖全部作者数据。

### 3.3 更新原对象与快照重建的取舍

优先按稳定身份更新工具 Clip，保留未接管对象。若现有结构必须清空后重建，可为允许保留的人工片段建立快照，但快照范围要明确。

| 快照内容 | 可支持的承诺 | 仍不能承诺 |
| --- | --- | --- |
| 引用键、显示名、目标名、开始时间、时长 | 基础片段位置和部分绑定可恢复。 | 所有混合和编辑参数完整不变。 |
| 再加 clipIn、timeScale、ease、blend、外推及自定义曲线 | 能更接近完整 Clip 恢复。 | 新包版本新增字段自动兼容。 |
| 原 Clip/PlayableAsset 对象直接保留 | 减少字段遗漏与子资产身份变化。 | 指向重建节点的外部绑定自动修复。 |

对不同 Clip 类型，序列化字段和运行时语义不同，不能只反射复制已知字段就视为完全保真。精确保留目标时优先记录可解析的稳定身份或相对路径；按名称恢复时按 `TML-ARC-03` 处理歧义，不默默选择第一个同名对象。

### 3.4 将末尾片段表达为时间合同

先明确末尾相对于角色动作、镜头动画还是整个 Timeline；是占用已有结尾还是延长播放；是硬切还是交叠混合；短动画怎样处理；手工回归镜头怎样迁移。

以下为可移植的 C# 时间计算示例，可放入普通工具类。它只计算区间，不创建 Unity 资产；参数是有限正数，不能把非法长度静默当作正常输入。

```csharp
using System;

public static class TailInterval
{
    public static (double Start, double Duration) Calculate(
        double totalDuration, double requestedDuration)
    {
        if (double.IsNaN(totalDuration) || double.IsInfinity(totalDuration) ||
            totalDuration <= 0d)
            throw new ArgumentOutOfRangeException(nameof(totalDuration));
        if (double.IsNaN(requestedDuration) || double.IsInfinity(requestedDuration) ||
            requestedDuration <= 0d)
            throw new ArgumentOutOfRangeException(nameof(requestedDuration));

        double duration = Math.Min(totalDuration, requestedDuration);
        return (totalDuration - duration, duration);
    }
}
```

例如总长 4 秒、末尾占 0.3 秒，则新区间为 `[3.7, 4.0]`；总长 0.2 秒时，新区间为 `[0, 0.2]`。如果工程使用帧对齐，另行定义秒到帧的舍入策略，避免两条轨道分别舍入而错帧。

两个片段的实际交叠长度为：

```text
overlap = max(0, min(previousEnd, tailEnd) - max(previousStart, tailStart))
```

只有在目标 Clip 支持混合且时间关系符合设计时，才将交叠映射到上一片段的 blend-out 和收尾片段的 blend-in。需要同时检查：结尾窗口是否跨多个镜头、最后一镜是否晚于窗口起点、是否有空档、窗口是否覆盖了所有需要退出的镜头。

单纯设置两段 blend duration 不等于任意镜头序列都能平滑返回。若结尾很碎，可选择禁止跨多镜头窗口、缩短混合或实现更完整的镜头接管策略，并将选择写进项目合同。

### 3.5 让生成和迁移具有幂等性

推荐顺序：识别已有自动片段 → 捕获合同内人工内容 → 更新工具片段 → 迁移已知旧片段 → 恢复人工内容 → 验证自动片段数量与身份。

新收尾片段使用稳定引用键。迁移同名手工镜头前先确认其目标和用途；“显示名相同”只能作为候选依据，不能普遍代表同一内容。项目如果决定接管这类手工镜头，应写清被替换的参数和恢复方式。

重复执行后除了数量不增加，还比较资源引用、时间区间、人工曲线、目标身份和其它模块变更。输入减少、清空、重排、模式切换和旧资源迁移都是不同用例。

### 3.6 将绑定保存做成可回读的闭环

详细 API 与两遍保存流程见 [资产生成与 Prefab 绑定](timeline-asset-generation-and-prefab-binding.md)。这里重点检查数据经过的边界：

| 边界 | 操作要点 | 验证证据 |
| --- | --- | --- |
| Timeline 子资产 | 先创建并保存 Track/Clip，再绑定 Director。 | 重新加载后仍能找到目标 Clip 和纯引用键。 |
| Prefab 临时内容 | 保存层级，卸载后重新加载并重新解析目标。 | 绑定不依赖已失效的临时对象引用。 |
| Director 引用表 | Track 用 Generic Binding；Clip 用 ExposedReference。 | `GetReferenceValue` 有效，且返回正确类型和目标。 |
| 落盘状态 | 保存后重开资产，必要时检查文本序列化。 | 不仅键存在，对象也属于预期 Prefab。 |
| 播放图 | 资产保存与图刷新分开处理。 | 不靠反复赋值 playableAsset/RebuildGraph 掩盖引用丢失。 |

读取 exposedName 时使用目标版本支持的序列化路径或创建时保留的原始键；`PropertyName.ToString()` 是显示形式，不适合作为稳定原始键。字符串键、目标路径和绑定职责集中定义，避免创建、自检、修复各拼一套。

### 3.7 区分源 Prefab 与主 Prefab 实例

已有 FX 源 Prefab 被保留，并不代表主 Prefab 中 FX 实例上的 override 会保留。工具清空容器再实例化时，源资源会重新进入，但只存在于旧实例的编辑可能消失。

保存嵌套源资源时，按 [嵌套 Prefab 保存参考](timeline-nested-prefab-save-and-generated-binding.md) 校验 owner/target，快照后写指定源，再同步活动实例。这里的实例回退只适用于明确“把当前实例编辑全部写回源”的操作，不能推广成所有保存后都无条件 Revert。

多资产写入也不天然具备事务性。预检、暂存输出、备份、失败报告和精确回退各有作用；`finally` 释放 PrefabContents 能避免泄漏，但不会自动撤销已经保存的资源。

### 3.8 工具界面与预设保持职责清楚

界面按作者工作流提供资源列表、作用域、生成/组装按钮和结果摘要；预检把冲突路径、将重建的区域和缺失输入说清楚。局部组装发生完整组装回退时，结果摘要体现实际写入范围。

预设保存参数与可解析资源身份，不保存临时对象或生成结果。资源移动和 FBX 子资源场景可考虑 GUID + localFileId；带 schema 版本，并报告缺失资源。本机缓存会被清理，若团队需要共享预设，应另外设计版本化资产格式，不依赖本机缓存充当唯一备份。

## 4. 风险与不适用边界

### 4.1 常见问题排查表

| 现象 | 优先查证 | 解决方向 |
| --- | --- | --- |
| 自定义轨道被删 | 名称、类型、前缀、重复 Group 清理。 | 收窄所有权匹配，给同名冲突诊断。 |
| 轨道还在但效果不播 | 总时长、mute、绑定目标、运行时重绑。 | 分别验证内容存活和播放行为。 |
| 手工相机曲线变了 | 快照是否只保存 start/duration。 | 保留原对象或补齐经验证的 Clip 状态。 |
| 返回镜头重复 | 自动引用键是否稳定，旧手工片段是否迁移。 | 按身份去重，迁移后验证恰好一个自动片段。 |
| 旧返回镜头消失且没新镜头 | 旧片段被识别为工具内容，但创建路径已移除。 | 核对清理、创建、绑定、验证是否为同一版本合同。 |
| 返回镜头跳切、空档 | 总时长来源、最后镜头边界、实际 overlap。 | 先修时间合同，再检查 Cinemachine 混合和相机位姿。 |
| Virtual Camera/Parent Object 为 None | 纯引用键、临时对象、保存顺序、目标类型。 | 两遍保存并重开回读。 |
| 只组装镜头却改了 FX | 缺 Timeline/Group/Prefab 或模式分支回退。 | 根据实际调用链报告范围，设计更窄的回退。 |
| 编译报缺 assets.json | 是否跳过了 restore，输出目录是否新建。 | 使用正常 restore/build；不要修改业务代码绕过构建环境错误。 |
| 缓存响应文件引用已删除源码 | 响应文件与当前工作树是否同版本。 | 刷新 Unity 项目文件或用当前 csproj，不把陈旧缓存当回归证据。 |
| 文档说完成、源码找不到调用 | 分支、提交、工作区、历史回退。 | 固定当前证据，避免把历史测试结果归给当前代码。 |

### 4.2 建议能力与已有能力分开

持久 owner ID、完整 Clip 快照、自定义引用自动重绑、预览变更清单、备份/事务化生成、失败后自动恢复和集成回归测试都是可选增强方向。采用前评估维护成本和迁移代价，未实现时写入项目待改进区。

本文不承诺所有自定义 Track、所有 Cinemachine 版本、所有 Marker 或混合曲线都可通用恢复；也不能用一次镜头样本推导整个项目都无损。

## 5. 验证与回退

### 5.1 最小验证矩阵

| 维度 | 用例 | 通过条件 |
| --- | --- | --- |
| 新建 | 首次生成、短时长、无镜头输入但有合法总时长。 | 结构、时间、目标绑定符合当前合同。 |
| 重复 | 相同输入连续两次。 | 自动内容不堆积，手工内容按合同保留。 |
| 人工编辑 | 独立轨、工具轨内 Clip、同名冲突、Marker、曲线。 | 分项比较，不只检查数量。 |
| 外部引用 | 手工轨绑定到被重建节点。 | 正确重绑或明确报出未支持，不能静默成功。 |
| 时长 | 角色/镜头/道具长度不一致；人工 Clip 超出末尾。 | 总时长规则与播放截断均可解释。 |
| 镜头边界 | 尾窗起点前后、最后一帧、跨镜头、空档。 | 接管和混合符合设计，FOV/位姿无非预期跳变。 |
| 作用域 | 完整组装、单模块、缺结构回退、模式切换。 | 实际改动集与合同一致。 |
| 持久化 | 保存、重开 Prefab、重新载入场景。 | 引用和参数仍有效。 |
| 生命周期 | Play、Pause、Seek、Stop、重复播放、销毁。 | 预览与运行时状态各自正确恢复。 |
| 失败 | 只读目标、缺资源、中途异常。 | 报出已写与失败项，能按精确文件集回退。 |

测试使用隔离输出或复制资源，记录生成前后语义差异。Unity 文本 diff 很有用，但 fileID 顺序变化不一定代表行为变化；结合加载结果比较轨道、片段和目标对象。

### 5.2 工具与证据用途

| 工具 | 适合证明 | 不能单独证明 |
| --- | --- | --- |
| `rg`、源码阅读 | 调用、清理范围、命名、当前分支是否有实现。 | Unity 内实际播放。 |

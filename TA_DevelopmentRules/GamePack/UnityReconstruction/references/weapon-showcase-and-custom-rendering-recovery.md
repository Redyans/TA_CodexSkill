# 独立武器展示与定制渲染恢复参考

> 类型：REFERENCE；适用范围：从原工程的大厅、检视、图标和测试场景中恢复独立道具展示。
> 使用前以目标项目源码、资源及实际 GPU 路径验证。参数与已实现边界见 [AlphaAce Profile](../Profiles/AlphaAce/project-and-weapon-showcase-recovery.md)。

## 1. 适用场景

适用于模型已可导入，但出现全紫、发白、曝光异常、光照不对、皮肤不显示、构图偏移、预览与运行不一致等问题。恢复目标先写成具体用户画面，例如“大厅独立检视”，再界定环境、相机、道具、皮肤、动作和 UI。

规范来源为 [模块入口](../README_Tech_UnityCaptureReconstructionRules.md) 的 `UCR-EVD-02`、`UCR-AST-02`、`UCR-ISO-01`、`UCR-VAL-01`、`UCR-VAL-02` 与 `UCR-VAL-03`。Scene/Game 适配另见 [编辑态预览与自由相机](editor-preview-and-camera-adaptation.md)。

## 2. 前提与依赖

准备目标入口的调用代码、环境场景、展示 Prefab、相机、管线/Renderer、质量配置、材质和皮肤输入。最好同时具备同版本原游戏截图或抓帧；如果缺少，只能确认工程内部配置与局部运行行为，不能宣称原画面一致。

| 视图 | 常见额外状态 | 误用影响 |
| --- | --- | --- |
| 独立检视 | 专用灯组、对象层、姿态偏移、旋转根、展示背景 | 直接放入普通场景后光照与构图不符 |
| 人物持枪 | 人物骨架挂点、第三人称灯组、遮挡 | 对象层与独立检视不同 |
| 第一人称 | 特殊 FOV、近裁剪、武器相机、专用光 | 近景材质和空间比例不能直接移植 |
| 图标生成 | 固定视图、透明输出、离屏目标、特殊皮肤任务 | 离屏图标配置不能自动作为交互画面 |
| 材质测试 | 压力参数、debug tint、极端发光或参考灯 | 被误当成正式美术基准 |

## 3. 实现或排查步骤

### 3.1 以运行调用链拼出展示入口

先从 UI/管理器的“打开检视”路径反查：资源加载 → 对象层 → 灯组切换 → 模型姿态 → 相机 → 质量/管线 → 全局渲染状态 → 皮肤生成 → 关闭恢复。

最终展示可能跨多个资产组合，未必存在一张“打开就与原游戏一样”的完整场景。推荐将原资源装配到专用恢复场景，记录每个节点来源；原资产保留为输入，临时宿主承担缺失初始化。

### 3.2 全紫时先恢复管线契约

建议依次确认：

1. 实际选中的 Graphics 与 Quality 管线，当前相机的 Renderer index。
2. 包 source、定制 include、Shader 编译日志和目标图形 API。
3. 材质 Shader GUID、SubShader 标签、Pass 名、LightMode 与所需 Keyword。
4. RendererFeature 的脚本、材质、Shader 和依赖纹理。
5. 运行分支是否实际需要某个缺失引用。

全紫通常意味着 Shader 缺失、不支持或编译失败，但仍以日志确认。用统一 Lit 材质替换全部资源可帮助检查几何，却不能作为定制材质已恢复的证据。某条未启用渲染路径的缺引用也不必然导致当前画面失败。

若暂时移除不兼容 Feature，保存原配置并记录损失的效果。不要把“移除报错”描述为“实现效果”。

材质检查按 Renderer 类型和实际启用状态解释槽位。停用的辅助粒子组可以合法没有材质；粒子 API 返回的材质数组还可能包含未启用的拖尾槽。先核对主材质、拖尾模块和实际参与绘制的子对象，再决定是否缺资源；不要全数组任一 null 就拒绝整个模型，也不要据此统一替换成默认 Shader。

### 3.3 处理发白时分解贡献

单张最终截图不足以判定曝光或 Bloom。保持相机、姿态、皮肤输入与颜色域一致，每次只改一个贡献，并保留 A/B 输出。

| 检查项 | 诊断动作 | 可支持的判断 |
| --- | --- | --- |
| BaseColor | 查看实际采样、sRGB 与导入设置 | 纹理本身、颜色域或绑定问题 |
| Normal/Tangent | 使用已知法线输入，检查空间/强度 | 反射方向异常是否源于法线 |
| 打包 Mask | 查 Shader 实际采样通道和默认值 | 金属度/粗糙度/遮罩是否解读错误 |
| Emission | 独立禁用并查看材质/全局 multiplier | 白区是否主要由自发光产生 |
| 直接光 | 按用途灯组逐组启停 | 互斥灯组叠加或受光层错误 |
| 环境反射 | 分开检查场景探针与材质自定义反射 | 白斑/亮边是否来自反射输入 |
| Tone/调色 | 查看曲线、通道与调用顺序 | 参数未初始化或重复映射 |
| Bloom | 对比输入、阈值提取与合成 | 只解释其增量，不解释所有底色 |
| RT/输出 | 查 HDR/LDR、sRGB、截断、最终转换 | 中间阶段溢出或重复 gamma |

“关 Bloom 后仍白”表示还有其他贡献；不是单靠此现象就能确认其中一个根因。优先保留材质表达，避免先把灯、反射、发光全部调低来追一张“看着正常”的图。

### 3.4 光照按用途、层与数量恢复

将场景灯分为检视、人物、第一人称、烘焙等用途，追踪原运行时的互斥条件。恢复模型所有子节点的 layer，并验证 Camera cullingMask、Light cullingMask、Probe cullingMask。

序列化位掩码可以按 `mask & (1 << layer)` 验证；名字只用于解释，数字槽位决定实际行为。不要按业务含义擅自重命名或重排层。

灯光模式等枚举以本地包源码为准，不能用官方版本印象解释定制资产的整数值。实际逐像素灯数量还受每对象限制、光源可见性、排序与着色路径影响；只提高灯数量并不能恢复正确灯组。

阴影检查原资产值与进入检视后的临时值。编辑器中的资产字段不是最终运行状态；为单场景临时改值时采用自己的管线实例，避免持久污染共享配置。

### 3.5 分开理解环境、探针与材质反射

依次确认：

- 环境 ambient/SH、天空与场景 custom reflection。
- 反射探针模式、纹理、强度、作用范围和层。
- 材质专用 cubemap、enable 与强度。
- 平面反射等额外渲染功能。
- roughness/mip 与法线是否匹配该输入。

同一反射纹理可能被多个武器共享，资源名含另一把枪不等于贴错。相反，贴图名字完全匹配也不能证明采样通道、颜色域、旋转和强度正确。

### 3.6 后处理按实际执行顺序恢复

“标准后处理关闭”不能推出“所有后处理关闭”。定制效果可能位于 RendererFeature、材质函数、全局 Shader 参数或独立 UI 相机。

建议建立处理顺序表：

| 阶段 | 记录内容 |
| --- | --- |
| 材质着色 | 光照、反射、自发光、材质内调色先后 |
| 自定义 Pass | 事件位置、相机筛选、全局开关、输入输出 RT |
| 标准后处理 | 相机开关、Volume layer、profile、实际激活组件 |
| 最终输出 | 色域、gamma、UI 合成、内部渲染尺寸、目标格式 |

运行初始化顺序同样关键：Volume 组件尚未启用时读取 stack，可能得到默认值。可在明确的初始化阶段或首个有效更新中重新求值；不靠每帧无条件反复重置全部全局参数掩盖问题。

相机允许 HDR、管线支持 HDR和 RenderTexture 格式分别验证。不要在已有定制 ToneMapping 的链路后再添加默认 ACES，除非原参考证明需要。

### 3.7 姿态、可见几何与构图共同决定观感

独立展示通常需要读取配置中的 angle/scale/offset，采样展示 Idle，并补偿动画根骨。直接使用导入姿势或 Prefab 初始 Transform，可能出现悬空弹匣、枪身偏转、占画面太小。

自动包围盒建议以展示时刻可见几何为输入：

```text
worldVertex = Σ(weight_i × boneLocalToWorld_i × bindpose_i × meshVertex)
```

这是线性蒙皮的概念公式。实际实现需处理权重数、骨骼缺失、矩阵空间、静态 Mesh 和可读性。折叠备用零件可能形成零面积三角形，可按有效三角形参与包围盒；退化阈值随单位和精度验证，不能默认删掉小零件。

编辑态可读不代表 PlayMode 仍保留 CPU 网格数据。读取原顶点/索引前检查可读性；不可读蒙皮可考虑让引擎烘焙到临时可读网格，再及时释放。烘焙输出的空间、是否已含缩放、非激活对象行为随版本验证，避免世界变换重复乘缩放。静态不可读网格可用本地包围盒八角点求保守范围，但该近似不能当作精确可见三角形边界。

配置缺失时先追原逻辑的主键与回退类型。确实没有配置而提供通用预览时，在界面与报告中标注近似；不把猜测角度、缩放写回原配置表。加载失败后销毁本次临时对象，避免没有进入“当前选择”字段的对象成为清理盲区。

透视构图先旋转包围盒角点，再按水平/垂直半视角求容纳距离。以相机向前为正深度、角点相对中心为 `(x,y,z)` 时，可用下界 `d >= max(|x|/tan(hFov/2), |y|/tan(vFov/2)) - z`，再加入边距及近裁剪条件。坐标约定改变时重新推导，不能机械套符号。

屏幕全窗口、原 UI 内嵌 viewport、图标画布具有不同 aspect 和视觉中心。离线居中属于适配；不标成原 UI 构图已一致。随意旋转后若仍使用初始 yaw 的 fit，只能保证初始姿态，需按交互要求追加边界验收。

### 3.8 程序皮肤需要恢复生成链

模型 Prefab 与皮肤是不同层次。皮肤可能依赖 item ID、paint kit、seed、wear、decal、高清映射、二进制表、Shader 和 RenderTexture 任务。

推荐的本地适配流程：

1. 读取原配置，保留逻辑名称到资产路径的映射。
2. 复用现有生成系统，以本地 provider 替换不必要的下载/登录入口。
3. 保存原 sharedMaterials、任务句柄和被接管的系统状态。
4. 明确 `Generating / Succeed / Failed / TimedOut`，编辑态按宿主机制推进任务。
5. 结束或切换时取消/释放旧任务，确认回调仍属于当前选择。
6. 先释放生成资源，再恢复原材质与本任务拥有的状态。
7. 使用 A → B → A 与重复生成验证清理及确定性。

超时只改状态文字并不等于任务取消；过期回调仍可能覆盖后续选择。引入 generation token、取消协议和异常即时清理是可选增强，采用前核实原系统支持方式。

名称匹配先精确命中。历史大小写不一致时，只接受映射到唯一目标路径的候选；存在多个不同目标则报歧义，避免任意取第一项。

### 3.9 批量目录与生命周期

目录保存配置条目，当前选择再加载一个模型；搜索和分页减少预览负担。条目数、独立模型数、皮肤数、已成功生成数与逐帧验收数分别统计。

临时宿主可按“获取 → 使用 → 释放”管理渲染状态：

| 状态 | 推荐记录与恢复 |
| --- | --- |
| Graphics/Quality 管线 | 保存原引用，创建临时实例；当前仍由自己持有时才恢复 |
| Renderer/Material | 明确浅复制仍共享的子对象，必要时独立实例 |
| 全局 Keyword/向量 | 分别保存是否存在、原值、最后所有者 |
| Bloom/质量静态开关 | 作用范围与原值；关闭后防止 Update 再接管 |
| 皮肤单例/纹理尺寸 | 会话结束是否需要恢复、任务是否已清理 |
| Editor 生命周期 | Disable、离开场景、重载、退出、异常路径 |
| Importer | 原设置、临时改动与 finally 恢复 |

临时实例有 `HideAndDontSave` 不代表其引用的 Renderer 或材质自动隔离，也不代表静态变量被自动恢复。

## 4. 风险与不适用边界

离线展示可以绕过业务启动链，但不等于恢复登录、音频、战斗、移动端构建或完整 UI。通过 Editor 的资产数据库加载资源，不能据此宣称 Player 可运行。

固定姿态、少量代表武器和程序皮肤成功，只覆盖那些输入。动态挂件、动画特效、透明材质、BlendShape、GPU 变形、非可读网格、多权重骨骼和全目录长期切换均需独立验证。

恢复与画质增强分开维护。改成线性空间、HDR、更高 MSAA、更多灯、全分辨率、另一套 ToneMapping 可能改善观感，但会改变原始契约；增强配置与原始配置分别命名和验收。

## 5. 验证与回退

建议最小验证矩阵：

| 维度 | 样本/动作 | 观察 |
| --- | --- | --- |
| 材质 | 基础款、金属、发光、程序皮肤 | 实际 Shader、贴图、Keyword 与输出 |
| 相机 | 初始姿态、旋转、缩放、不同 aspect | 裁切、中心、反射与尺寸 |
| 状态 | 开启、禁用、启用、换场景、重载 | 管线与全局状态归还 |
| 选择 | 基础 → 皮肤 → 基础 → 同皮肤 | 材质、生成状态与重复画面 |
| 质量 | 原始配置与增强配置分别测试 | 内部尺寸、颜色域、Pass 差异 |
| 失败 | 缺 Prefab、缺表、生成失败/超时 | 可解释错误、无假成功、资源清理 |

真正比较原效果时，再按 [RenderDoc 验证参考](renderdoc-validation-and-troubleshooting.md) 对齐同版本、镜头、姿态、皮肤参数、分辨率与颜色域，分区查看差异。缺原参考时交付“本地运行验证”，不要计算一个没有基准含义的还原率。

回退优先恢复会话状态、临时实例和本次配置差异；保留原场景和源资源。修改默认背景、调色或灯光后，使用新一轮完整证据覆盖验收，旧截图不能自动证明新配置。

# Unreal 动画与次级运动跨引擎还原参考

> 类型：REFERENCE；适用范围：从已获授权的 Unreal 角色资产、运行时证据和抓帧，恢复 Unity 中可播放的展示动作与次级运动；使用前提：以目标游戏的引擎分支、资产、导出链和目标 Unity 版本重新验证。

## 1. 适用场景

本页用于处理“模型与单帧外观正确，但播放后表情、武器、头发或衣物失真”的问题，也用于在导入之前设计可追溯的动画恢复流程。处理对象包括原动画依赖、Montage 时间线、面部标量曲线、骨架单位、镜像旋转，以及由动画图驱动的次级运动。

规范来源沿用[模块入口](../README_Tech_UnityCaptureReconstructionRules.md)的 `UCR-EVD-01`、`UCR-AST-01`、`UCR-AST-02`、`UCR-VAL-01`、`UCR-VAL-02`、`UCR-VAL-03`。本页提供实现选择与排查方法，不另立强制规则。Unity 资源总体流程见[资源与渲染复刻工作流](unity-asset-and-render-reconstruction-workflow.md)，UE 特有的解析与导出见[UE 解包工具链](unreal-extraction-toolchain.md)，画面分层指标见[验证与故障排查](renderdoc-validation-and-troubleshooting.md)。

此方法从[DragonSwordAwakening 项目 Profile](../Profiles/DragonSwordAwakening/character-rendering-reconstruction.md)的原资产、源码推导、独立数值基准和实际 Unity 验证中提炼。该 Profile 承载具体角色、路径、类与节点、轴向转换、默认值、源版本、误差容限和实测数量；迁移时重新建立这些项目事实，避免将某一次导入链的坐标映射当作 Unreal 到 Unity 的固定公式。

本页不提供通用 Retarget、完整角色玩法状态机或所有物理插件的替代实现。导出了某种玩法附带动作，不代表与它关联的注视、手部锁定、载具或其他运行逻辑已还原。

### 2.1 准备可独立核对的输入

| 输入 | 需要保留的内容 | 支持的判断 |
| --- | --- | --- |

| 原动画包 | 解码前后字节或哈希、压缩格式、骨轨道映射、时长、采样定义、原曲线 key/切线 | 导入器是否改变动画函数或丢失轨道 |
| 展示入口及引用图 | 展示类、衣装/武器变体、AnimBlueprint/LinkedAnimLayer、Montage、通知和分支 | 实际展示状态使用了哪些资产和动作 |
| 原默认值与运行逻辑 | 类默认对象、父类、native 构造、初始化、输入复制、配置覆盖和状态更新 | 缺省字段、动态权重及初始状态的真实值 |
| 导出与导入配置 | 导出器版本、骨轴修正、单位转换、附加根、负缩放、Unity ModelImporter 设置 | 变化发生在源资产、格式转换还是宿主导入阶段 |
| 原画面与捕获 | 时间点、actor/world 变换、骨矩阵或可见几何、相机、画面状态 | 当前可见姿态；不单独提供完整模拟历史 |
| 目标宿主 | Unity/包版本、骨架、实际执行顺序、后台验证入口和持久化资产 | 数值转换能否在真实采样、序列化和播放中成立 |

推荐同时保留原数据、转换清单、已保存资产、验证报告四层。每个生成资产通过清单回到原对象与工具命令；工具安装位置和参数写入项目 Profile。读取数据可选能识别目标 cooked 格式的解析器与动画解码器，FBX/GLB 转换只承担已明确的格式转换，不作为原引擎语义的最终依据。

### 2.2 标注证据性质及验证覆盖

| 标记 | 含义 | 表述边界 |
| --- | --- | --- |
| `[EVIDENCE]` | 可回溯的原包、配置、指令、截图或实际宿主输出 | 写清原始来源、版本、时点与观测范围 |
| `[INFERENCE]` | 由来源推导的分支、坐标关系或算法解释 | 同时给出前提及独立复算方法 |
| `[APPROXIMATION]` | 已声明的重采样、格式或后端替代 | 给出误差指标和受影响状态 |
| `[UNVERIFIED]` | 缺少来源、未支持分支或尚未执行的验证 | 不用代码已写或截图相似替代通过结论 |

证据性质与验证层级分别记录。独立 Python 求值通过、Unity 已保存曲线求值通过、实际 PlayMode 通过、原引擎同步轨迹通过是不同命题。只有把同一转换函数的输出再传回同一函数，并不能独立证明算法正确。

可复用的证据链为：原字段或原函数是 Evidence，错误机制与修正条件是 Finding，`源对象 → 导出清单 → 持久化资产 → 运行组件 → 骨/曲线输出 → 实际相机` 是 Path。具体证据 ID 与当前结果留在项目 Profile 及工程专题报告中，避免在通用参考中复制过期数字。

## 3. 实现或排查步骤

### 3.1 先闭合动作依赖，再统计导出数量

1. 从实际展示入口追踪角色和衣装类，沿 Skeleton、AnimBlueprint、LinkedAnimLayer、Montage、AnimSequence、Socket 和武器资源递归展开。按对象引用确认实际分支，不按角色名前缀猜测依赖。
2. 将“展示菜单项”“不同 Montage”“原动画包”“导出的身体/武器 clip”“含表情曲线的 clip”分开统计。一个 Montage 可复用多个片段，一个片段也可被多个入口复用；这些数量没有天然一一对应关系。
3. 同时导出通知引用的武器动作、默认挂点、挂点切换、独立武器骨架，以及正文 Montage 外的显式展示依赖。若用户要求角色相关全部动作，区分可达展示动作与额外附带动作，不把二者合并成一个“已全部播放”结论。
4. 对重复源对象按完整路径、来源包和内容哈希识别。共用资产可集中保存；角色目录保留清晰引用或角色专属副本的来源映射，避免仅靠同名文件覆盖。
5. 导入后从已保存资产读取曲线、时长、路径和实际采样位移。针对身体、面部、武器分别检查缺失绑定，避免“文件存在”掩盖空曲线或错误骨路径。

依赖清单至少包含：源对象身份、使用它的展示入口、Skeleton 身份、目标资产、转换命令、是否进入实际播放覆盖、未支持引用。保留未知引用有助于继续解包；静默丢弃会使后续完整性统计失去依据。

### 3.2 把 Montage 恢复为时间线，而非单个循环 clip

| 项目 | 恢复方式 | 常见误判 |
| --- | --- | --- |
| Segment | 保存源片段、Montage 起点、片段截取区间、播放速率、重复次数 | 用片段全长或统一采样率替代 Montage 时间 |
| Section | 保存起点、名称及 `next` 查找关系 | 看到字符串含 loop 就补造循环段 |
| 默认值 | 区分显式序列化、父类/CDO/native 默认及运行覆盖 | 字段未导出就当零，或直接使用解析器的默认对象 |
| Blend | 保存入/出时长、曲线/模式、基底 pose、退出条件 | 只恢复最终姿态，忽略进入和动作切换 |
| Notify | 保存时间、类型、目标武器、挂点、动作、执行上下文 | 将所有通知转换为不区分主体的 Unity AnimationEvent |
| 独立武器 | 保留自己的 Skeleton、clip、时间相位和启停 | 将武器所有骨曲线并入身体，丢失挂接或独立播放 |

对于单个正向 segment，设原片段区间为 `[a,b]`、Montage 起点为 `s`、播放倍率为 `r>0`、重复次数为 `n`，则该 segment 的占用时长为 `n(b-a)/r`。先计算 Montage 时间落在哪个 segment，再求片段局部时间；精确结束点单独处理，避免取模后跳回首帧。负播放率、重叠 segment、多个 slot 或 additive 行为需要各自的源语义，不能从此正向例子推定支持。

Section 跳转依据原名称查找及失败行为。若源引用了不存在的下一段，先验证原引擎如何终止或回退，保留该行为；自动补段会改变原动作。较大 `deltaTime` 可能跨过多个 section，推进时分段消费时间，记录循环次数及有界保护，防止零长度环路。

通知可按每个实际推进区间 `(t_old,t_new]` 派发，并单独处理进入动作、循环回跳时的起点；具体开闭区间仍与源代码核对。动作切换时明确退出动作是否仍派发通知、暂停/寻址是否重放、武器默认挂点何时恢复。验证至少覆盖精确边界、跨边界、跨多个 section 和重新播放，检查既不漏发也不重复。

缺省值追溯顺序可按“实例显式字段 → 父类/CDO → native 构造与结构默认 → 初始化/运行覆盖”展开；这是调查路线，不是忽略对象生命周期的固定优先级。缺失 JSON 字段只能说明未显式输出，不能证明实际值。原枚举的整数、名称和分支映射分别保存，避免假设枚举值就是 pose slot 索引。

### 3.3 确认 Reference Pose、混合基底与每帧时序

参考姿态应来自原骨架及 slot/图的输入语义。捕获姿态、当前 Unity Transform、导入器预览姿态和原 Reference Pose 可能不同，不能互相代替。首次播放前和测试重置时，分别恢复骨局部位置/旋转/缩放及面部曲线基值；只有源逻辑明确归零的通道才设零。

恢复混合时同时检查骨与曲线：平移/缩放是否线性、旋转是半球修正归一化线性插值还是球面插值、表情是否参与相同权重、出动作是否继续推进、没有有效出动作时使用哪种基底。若源实现采用归一化线性四元数插值，可用下列形式建立独立预期：

```text
q1' = q1                     if dot(q0, q1) >= 0
q1' = -q1                    otherwise
q(w) = normalize((1-w)q0 + w q1')
```

该表达式只适用于已确认的该种混合，不证明所有 Unreal 混合均应替换为 Unity `Quaternion.Lerp`。位置、缩放、曲线和四元数分量分别验证，避免只检查一个骨端点。

推荐把运行步骤拆为可观察边界：恢复上一帧动画输入 → 采样本帧原时间线/混合 → 保存本帧未加物理的输入 → 按原图顺序推进次级运动 → 写回骨骼 → 渲染。若每帧从上次物理输出继续“叠加动画”，即使单帧正确也可能累积漂移。独立武器动画、通知和挂点更新放在源逻辑规定的阶段；测试记录实际执行顺序，而不只依赖方法名。

### 3.4 保留 RichCurve 函数，避免近时间 key 在 float32 中坍缩

面部异常首先检查源函数与时间精度，再检查形变绑定。权重为负或超出常用显示范围不自动表示错误，原曲线可能故意使用越界形变。

1. 保留原始 key 时间、值、每侧切线、插值模式、切线权重模式、首尾外推和默认值。对已解码的数据核对原包来源，避免用转换后的二次采样结果作为“原生基准”。
2. 在目标存储精度中检查时间严格递增。两个不同的双精度时间可能满足 `float32(t_a) == float32(t_b)`；将原 key 与均匀采样网格合并后再降精度，容易制造这一问题。
3. 原函数可直接表达时，优先转移原 key。线性区间的两侧切线使用同一斜率；三次区间使用前 key 的出切线与后 key 的入切线；阶梯及首尾外推采用已验证的目标表示。不要把全部切线交给自动平滑重建。
4. 若值和时间分别换单位 `v_t=k_v v_s`、`t_t=k_t t_s`，则切线换算为 `m_t=(k_v/k_t)m_s`。按原函数导数定义核对，不能只缩放 key 值。
5. 原曲线存在加权切线、非恒定外推或目标不支持的模式时，另建有误差界的转换。仅验证过未加权 Hermite 的路径，不能默认为支持加权曲线。

未加权三次段可用独立的双精度 Hermite 求值器作预期。令 `u=(t-t0)/h`、`h=t1-t0`、前 key 出切线为 `m0`、后 key 入切线为 `m1`：

```text
f(t) = (2u³-3u²+1)v0 + (u³-2u²+u)h m0
     + (-2u³+3u²)v1 + (u³-u²)h m1
```

如确需重采样，在目标时间精度中构建和去重采样点，记录碰撞点及合并策略，并重新验证整段函数；任意加入小 epsilon、对巨大切线截断或裁剪权重都不能证明原函数已恢复。原曲线本来存在同时间跳变时，保留其源语义并单独处理，不能将“严格递增”强加给尚未支持的格式。

保存并重新读取 Unity `AnimationClip` 后再调用 `AnimationCurve.Evaluate` 验证。比较双方 key 的联合断点、区间内部、首尾外推；在同一多项式区间内，可求两函数之差的导数零点，检测稀疏均匀采样遗漏的尖峰。阶梯跳变附近分别检查左右侧。key 数不同不必然意味着函数错误，key 数相同也不证明插值正确。

修复既有 clip 时，先记录所有非目标标量曲线、对象曲线、事件、clip 设置及 GUID；只替换已证明受损的曲线，并比较这些不变量。恢复动作不应使原材质、武器事件或身体运动发生旁路变化。

### 3.5 分开验证骨架单位、原骨缩放和导入包装

为每一层记录单位与变换：源骨局部坐标、源组件、导出器新增根、模型文件单位、Unity 导入根、actor/展示根和世界。几何看起来大小正确，仍可能是两层缩放互相抵消，不能据此认定偏移已使用正确单位。

骨局部碰撞偏移或 Socket 偏移转换为目标长度单位后，若再次经过带导入单位尺度的 `TransformPoint`，会重复放大。设已确认的导入包装尺度为 `S_import`，该尺度恰好位于当前局部偏移到世界的组合变换中，输入偏移 `o_t` 已完成长度换算，可在正确位置使用 `S_import^-1` 消除这一重复项。均匀标量 `s_import` 的常见情形为：

```text
worldOffsetPoint = bone.TransformPoint(o_t / s_import)
```

这一形式以已证明的层级和单位契约为前提。非均匀尺度与旋转不交换，不能直接逐轴除 `lossyScale` 来推广；应从矩阵链确定补偿项插入的位置。原动画中的缩小、负缩放、actor 变换和真实骨缩放仍参与点变换。把总世界尺度全部消掉会同时破坏源行为。

独立测试从原 ReferenceSkeleton/原 GLB 的局部 TRS 组合计算预期中心，覆盖非零偏移、不同 driving bone、正负 actor 和原骨缩放变化。预期值不调用待验证的 Unity 偏移助手。Socket 同样检查位置、旋转、局部尺度及重挂父骨后的结果。

### 3.6 用原局部旋转链处理镜像，区分 P 与 C

负 actor 缩放可用于正确连接导入模型与捕获世界，但带反射的世界矩阵不属于纯旋转。此时 `inverse(root.rotation) * bone.rotation` 不能自动作为原引擎组件四元数；宿主对世界旋转的提取可能与原局部四元数链不同。只比较骨位置会漏掉这种错误。

在已确认导入的局部四元数保留原骨旋转语义时，可沿祖先到子骨累乘局部旋转，得到组件旋转；写回按同空间父骨逆旋转求局部值：

```text
q_component(b) = q_local(root-child) ... q_local(parent) q_local(b)
q_local_output(b) = inverse(q_component(parent)) q_component_output(b)
```

乘法方向与原宿主约定一起核对，不能把数学记号直接映射成任意 API。位置仍通过包含尺度与反射的完整矩阵转换。读取、求解和写回分别验证；只修 bound bone 而遗漏 collider driving bone、辅助骨修改或父骨写回，仍会出现方向错误。局部骨链有非均匀尺度或剪切时，还需确认原引擎 `FTransform` 组合语义，不能宣称四元数链等于世界仿射矩阵的极分解。

用两个符号明确坐标契约：`P` 表示原世界到目标世界的换基，`C` 表示原组件/骨局部到导入组件的换基。若 `A_s` 是原组件到世界的变换，则在两侧单位已统一的约定下：

```text
A_t = P A_s inverse(C)
```

具体轴交换、符号和单位因子由原顶点、原 actor 矩阵及导入局部 TRS共同确定；`P` 与 `C` 可以不同。使用齐次矩阵处理平移/长度单位，纯方向换基则另行标注。`A_t` 含反射时，不能把它整体塞进四元数。

| 量 | 处理要点 | 独立验证 |
| --- | --- | --- |
| 世界点 | 使用世界点换基及长度换算 | 原 actor × 原骨位置，与正式场景世界位置比较 |
| 原骨组件旋转 | 使用已验证的局部链与组件旋转换基 | 比较四元数等价性及三个基轴 |
| 世界模拟骨旋转 | 在原世界语义中组合 actor 旋转与骨组件旋转，再做目标写回 | 同时比较骨轴、刚体中心、输出局部旋转 |
| 骨局部偏移 | 使用它所属骨的基与单位 | 非零各分量偏移，避免零分量掩盖错误 |
| 重力/风/外力 | 区分方向、速度、加速度及其源空间；一般换基不含平移 | 向量方向、单位与组件/World 投影分别比较 |
| 法线、角动量等 | 确认是法向量、普通向量还是轴向量，按原算法定义转换 | 不能将点的转换助手用于所有物理量 |

正负 actor 配对测试有助于发现组件旋转的镜像依赖，但人为改变 actor 奇偶性的场景不是原捕获。正式 World 点位置验收只对实际捕获对应的 actor 契约进行，避免要求人为正 actor 与原世界坐标相同。

### 3.7 恢复原图执行顺序与动态 PropertyAccess Alpha

静态导出的节点 `Alpha` 可能在每次求值前被编译后的属性访问复制覆盖。读取静态值并启用所有节点，可能让普通、骑乘等互斥状态组同时作用于同一骨骼。

1. 先由实际类引用和 PoseLink 确定选中图及节点顺序，检查衣装替换、LinkedAnimLayer、枚举到 pose 的映射。对象遍历顺序不等于图求值顺序。
2. 解析原编译属性访问结构。例如目标版本中的 `CopyBatchArray → SrcPaths/DestPaths → PathSegments` 可以连接输入和节点目的字段；具体字段布局以版本为准。保存复制批次、索引、目标节点/字段、源路径和引用来源，避免按遍历碰到的首个同名类配对。
3. 将静态序列化值、动态输入来源、当前状态初值分开保存。原图存在 scale/bias/clamp/插值或其他 Alpha 处理时，按实际运算顺序恢复；只有逐节点证明恒等时才省略。
4. 动态输入初值从 native 构造、蓝图/CDO、调用点及输入复制追溯。原始零初始化和某次运行写入零属于不同来源，分别记录。
5. 运行时读取输入并传播到实际 solver 权重，保留可更新入口。缺失、重复、未知或非有限输入形成明确错误，避免无声使用静态 Alpha 回退。

验证时分别改变每个输入，观察依赖它的实际节点权重以及不依赖它的节点是否保持原值，再验证组件总权重和原 Alpha 变换的组合。统计“保留的图阶段数”与“当前状态实际启用数”，不要把前者命名或宣传为全部正在生效。停用节点的内部状态保持、重启和重置也有源语义，不由权重为零自动决定。

### 3.8 先校验刚体初态，再移植惯量和约束求解

对选中的一个节点，在原动画固定时刻记录 bound bone 位置、旋转、三轴、关节偏移、刚体中心、重力方向与碰撞体。若源定义刚体中心为 `p_body=p_joint+R_bone j`，初态就按该式验证，写回则核对相应逆过程；不要用目标代码计算出的中心作为预期。偏移 `R_bone j` 与重力的点积/夹角有助于发现反向，但是否应同向取决于原骨与偏移，不能统一要求“所有偏移向下”。

惯性张量迁移中，存储行列顺序、向量左乘/右乘、四元数作用方向是不同问题。设源代码以行向量计算 `M_s D M_s^T`，并已证明 `M_s` 为目标四元数列向量旋转矩阵的转置，则对应的目标向量作用可写为：

```text
inverse(q) * (D * (q * torque))
```

这里的 `D` 是源算法定义的对角张量或逆张量。此式只适用于上述已验证约定，不是惯量的通用固定写法。测试使用非立方体尺寸、非平凡旋转和多个力矩方向；各向同性的 `D` 与旋转交换，单测球体/立方体可能使错误的共轭顺序完全不可见。预期由源矩阵条目显式组成，避免复用目标 Quaternion 助手。

约束顺序按原实现保存。多次迭代中的平面、球、角度等约束通常非交换；把它们按类型、骨名或导出字段排序会改变结果。原实现的预迭代/后迭代、偏置、累计冲量、阻尼应用时刻、步长上限、初始化与重置同样属于行为。看似反直觉的 locked swing 或角限公式先与源实现核对，不靠直觉“修正”。

从源数据独立构造固定初态和固定时间步的重放：先验证首步，再比较多个步骤的中心、旋转、动量和写回。单节点原算法重放通过，只覆盖这个节点的初态与公式；串联图、碰撞和真实动画驱动另行验证。

### 3.9 用因果隔离区分坐标错误与真实惯性

固定姿态诊断与真实播放回答不同问题。推荐在临时实例中建立下列矩阵，所有组使用同一原动画采样时刻、actor、相机、时间步和原参数。

| 诊断组 | 主要用途 | 不能直接证明 |
| --- | --- | --- |
| 仅动画输入 | 检查原片段、Reference Pose、导入骨链和表情 | 物理结果正确 |
| 固定输入 + 完整原图 | 检查持续翻转、整体漂移、长期形态 | 已达到静止平衡或与源连续历史一致 |
| 固定输入 + 单类 solver | 区分不同次级运动系统的贡献 | 隔离结果等于正式串联图 |
| 固定输入 + 单节点 | 对照原公式、初态和写回 | 所有节点组合正确 |
| 临时取消一种力/约束 | 判断异常对重力、碰撞等的依赖 | 取消该项就是生产修复 |
| 实际 PlayMode | 验证真实 Update/LateUpdate、动作切换、挂点、物理和渲染 | 自动证明每帧与源引擎一致 |

固定输入每步恢复同一动画 pose，再运行原求解器；只冻结时间而不恢复输入，可能把上一帧物理结果再次当输入。对正常播放则保留动画推进、通知、父骨运动与惯性历史，不把手动采样循环称为 PlayMode。

发现关闭重力后头发不再上翻，只能说明重力参与了异常。继续检查原重力配置及覆盖、骨旋转、偏移方向、张量和约束。若根因是偏移或轴被镜像反转，减小重力、总权重、碰撞尺寸或角限只会压低症状，同时改变原效果。诊断用参数副本不写回正式资产；生产修正回到已证明的坐标、语义或执行错误。

在若干时刻保存实际相机截图、骨状态和几何指标，并人工检查头发/衣物的方向、穿插和局部闪烁。最大位移大也可能是原展开披风自然落下，不能脱离初态只以阈值判错。若要声称“已收敛到稳态”，增加连续窗口内的速度或姿态变化阈值；末帧自然下垂只支持末帧形态结论。

### 3.10 常见症状与最短排查路线

| 症状 | 优先核对 | 常见根因 | 合适的验证 |
| --- | --- | --- | --- |
| 文件很多但展示动作缺失 | Montage/notify 到 clip 的引用闭包 | 按名称批量导出遗漏武器或共享片段 | 按入口逐项比对源引用及已保存 clip |
| 入场正确、切换动作时突然回姿态 | blend 默认、基底 pose、出动作推进 | 缺省值当零或拿当前物理 pose 当基底 | 混合区间逐骨/逐曲线与原函数比较 |
| 武器跳错位置或越缩越小 | Socket 单位、导入包装、原骨 scale | 重复单位补偿或去掉真实骨缩放 | 独立原 TRS 下重挂接及缩放组合 |
| 表情尖峰、负值异常大 | 原 key 和目标精度时间集合 | 双精度近时间转 float 后重合 | 原函数对保存后 Evaluate，含区间极值 |
| 静态截图正确、镜像角色头发上翻 | 原局部链与世界 quaternion 差异 | 从带反射世界旋转反推组件旋转 | 正负 actor 的同输入组件旋转与写回 |
| 骨位置正确，碰撞中心远离角色 | 偏移单位与 armature 包装 | 已换长度单位又乘导入尺度 | 原生中心 × actor 奇偶性 × 骨缩放 |
| 某些 World 节点正常、其他反向 | P/C 混用与偏移零分量 | 特例掩盖世界/局部基错误 | 三轴、各非零偏移及正式 actor 世界位置 |
| 普通与骑乘衣物互相拉扯 | 原图分支与动态 Alpha 来源 | 使用静态 Alpha 启用所有节点 | 逐输入扰动实际节点权重 |
| 某个盒子异常，球体测试却通过 | 张量方向与行列约定 | 各向同性样本掩盖错误共轭顺序 | 非均匀盒体、非平凡旋转的显式矩阵基准 |
| 同参数仍有碰撞方向差异 | 原约束构建/迭代顺序 | 导出或运行按类型重新排序 | 单步逐约束状态与多步轨迹 |
| 只有播放时爆发或累积漂移 | 动画/物理时序及历史恢复 | 物理输出污染下帧动画输入 | 记录真实回调顺序、输入和输出状态 |
| 没有 NaN 但画面持续变形 | 初始方向、图顺序与实际相机 | 仅凭 finite 判为通过 | 数值、原语义和图像三者联合检查 |

## 4. 风险与不适用边界

- 单帧抓帧不能恢复捕获前的速度、随机种子、风场历史、通知历史和全部状态转移。原参数齐全也不等于具备源同步轨迹。
- 原引擎/插件版本变化会改变 cooked 字段、PropertyAccess 布局、默认值与 solver 语义。开源参考代码只有与目标版本和实际执行路径核对后，才能支撑该目标的结论。
- 原图中存在已导出但当前关闭的阶段，保留数据不代表实现了其全部其他玩法状态。扩展状态后重新检查输入复制、枚举映射、重置与来源。
- 四元数局部链解决的是已证明的原旋转语义保留问题，不自动处理所有非均匀缩放、剪切、Retarget、骨轴重排和 root motion。无法映射的模式作为独立未支持项记录。
- 原生曲线能被 Hermite 表达，不表示目标引擎序列化会原样保留。float32 精度、自动切线、加权模式和外推仍需保存后实测。
- 修改重力、碰撞、角限、权重或表情范围可能产生更平稳的画面，但这是表现变化，不能用来证明行为还原。范围内若需要有意改动，另记与原行为的差异。
- 固定姿态自然垂落、有限值检查、若干截图无异常、全部菜单项时间线通过，各自具有有限覆盖。没有同初态同输入的源引擎连续帧，不宣称全部物理逐帧等价。
- CPU 几何诊断若只取部分骨权重或不计 Morph，应明确近似边界；实际 GPU 蒙皮、表情及相机输出继续单独检查。

## 5. 验证与回退

### 5.1 按层建立可执行验收矩阵

| 层级 | 输入与检查 | 通过条件写法 | 失败后回到 |
| --- | --- | --- | --- |
| 来源与依赖 | 原包哈希、对象图、Montage/notify/clip/Skeleton 对应 | 指定入口引用均已解析；未支持项显式列出 | 索引、类/衣装选择、解码器 |
| 曲线与持久化 | 原函数对已保存曲线，全部断点/区间/外推 | 在项目容差内，非目标曲线/事件/设置/GUID 不变 | key 精度、插值、绑定与序列化 |
| 参考姿态与坐标 | 原局部 TRS、单位链、actor、中心/轴/旋转 | 各量单独给出单位、最大误差和覆盖集合 | P/C、导入包装、局部链与写回 |
| 动态图输入 | 源分支、输入来源、Alpha 变换、逐输入扰动 | 依赖节点按源公式变化，其他节点不变 | PropertyAccess、默认值与状态复制 |
| 求解器 | 独立原公式初态、首步与多步、约束中间态 | 具体节点/模式在容差内，不泛化范围 | 张量、约束顺序、时间步、初始化 |
| 固定姿态图像 | 原输入冻结、临时分组、若干实际相机输出 | 指定现象未出现，或带速度阈值的稳态通过 | 因果隔离与原参数来源 |
| 实际播放 | 真正 PlayMode、真实回调、菜单切换、武器和面部 | 达到计划实际帧数，日志与输出完成，图像复核通过 | 时序、状态历史、宿主绑定 |
| 工程整合 | 编译、缺失引用、场景重开、目标图形 API | 与报告源码/资产快照一致，依赖可加载 | 导入设置、组件引用、管线入口 |

异步后台验证先等待报告更新时间、完成状态、实际帧数和 worker 退出相应运行状态，再调度下一项。启动成功不等于测试通过；只看旧报告也不能验收新源码。各报告保存工具/宿主版本、输入哈希、测试时点、步数/步长、容差、截图和异常，使用新运行标识保留历史证据。

针对动画与物理的独立基准，尽量直接从原 ReferenceSkeleton、原动画解码 TRS、原 actor 和原矩阵公式计算期望；目标 Unity 负责输出实际输入/状态/写回。对同一问题同时记录数值与相机观察，避免以低误差替代没有覆盖的实际画面。

### 5.2 保留原资产与最小回退路径

生成前保存原导入设置、资产 GUID、源清单、当前可用场景及影响到的运行配置；测试在隔离 worker 或临时实例上进行。临时禁用重力、碰撞或节点类型只改变内存副本，报告写明分组，测试完成恢复原引用、父子关系、姿态、管线和全局状态。

回退针对本轮派生曲线、绑定、坐标适配或 solver 变更，恢复先前资产和配置，并保留失败报告。不要重写原证据、删除未知依赖或降低验收要求来使结果看似通过。重新导入时检查是否无意改写未受影响的身体曲线、事件、设置和 GUID。

迁移到下一项目时，可复用本页的步骤、表格和独立验证结构；重新填写项目 Profile 中的版本、源入口、字段布局、P/C、单位、默认值、原参数、容差与当前状态。[DragonSwordAwakening Profile](../Profiles/DragonSwordAwakening/character-rendering-reconstruction.md)提供已完成案例的证据入口，不作为新项目的固定参数库。

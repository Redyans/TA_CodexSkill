# Unity 还原工具、自动化与证据管理参考

> 类型：REFERENCE；适用范围：旧工程恢复、资源提取、离线展示与真实宿主验证。
> 工具按问题选择。下列工具类型不表示某项目已安装或执行；本次实际使用、历史证据和候选工具见 [AlphaAce Profile](../Profiles/AlphaAce/project-and-weapon-showcase-recovery.md)。

## 1. 适用场景

用于把一次人工排查变成可复用、可检查、可回退的流程。核心产物是输入清单、修复、验证和证据链，而不是工具数量或命令日志长度。

沿用 [模块入口](../README_Tech_UnityCaptureReconstructionRules.md) 的 `UCR-EVD-01`、`UCR-ISO-01`、`UCR-VAL-01` 与 `UCR-VAL-02`。后台工程隔离细节见 [独立 Worker 与交付验证](isolated-unity-worker-and-delivery-validation.md)。

## 2. 前提与依赖

先确认编辑器、脚本解释器和命令行工具的实际位置、版本与工作目录。工具索引、旧聊天命令和历史文档中的路径只是候选来源。跨盘路径用项目 Profile 定义的别名引用，规则库内部链接保持相对路径。

每个工具记录用途、输入、输出、是否会修改资产、失败条件和替代方案。工具不可用时可继续不依赖它的工作；记录实际失败，不把未执行的验证写为通过。

## 3. 实现或排查步骤

### 3.1 选择能回答当前问题的工具

| 工具/能力 | 适合回答的问题 | 局限与交叉验证 |
| --- | --- | --- |
| `rg`、文件清单 | 定义在哪里、哪些路径引用该 GUID/Shader/资源名 | 文本搜索看不到运行时实际分支 |
| PowerShell | 文件哈希、进程身份、启动后台 Editor、读取日志 | 不输出完整命令行中的认证参数 |
| Python | GUID 索引、依赖图、幂等恢复、清单、图像指标 | 脚本可跑不代表 Unity 语义成立 |
| Unity Editor/AssetDatabase | 真实导入、子资产、类型和依赖 | EditMode 访问能力可能大于 PlayMode |
| Unity 自带编译器/程序集元数据 | API、实际引用版本和条件编译 | 不能代替导入、原生插件和 GPU |
| 原生 AssetBundle API | 该 Editor 能否直接读包 | 从首个失败阶段判断，不能推断全部内部格式 |
| UnityPy | 批量解析对象、索引与部分导出 | 版本、type tree、私有包装和格式支持需验证 |
| AssetRipper/AssetStudio | 资产浏览、提取与重建候选项目 | 导出工程不自动具备原脚本行为和正确引用 |
| Frame Debugger | 当前 Unity Pass 顺序、绘制和 RT | 与原游戏的状态一致性仍需参考输入 |
| RenderDoc | 实际 draw、Shader、资源、常量和状态 | 抓帧时点、动态历史及 UI 合成需对齐 |
| 图像检查/指标 | 比较区域、重复性、亮度或像素差异 | 不同镜头/颜色域或拟合后的图不能直接评价原效果 |
| 桌面自动化 | 操作现有 Editor、查看 Game 与 Console | 依赖实际连接；失败时不假装已点击或刷新 |

选择顺序通常是文本与元数据 → 目标宿主 → 必要时 GPU 抓帧。没有相关二进制分析需求时，不为了“完整工具链”额外反编译或安装工具。

### 3.2 从截图进入完整诊断

截图可定位时间、资产名、异常和栈帧；接着读取同一 Editor 的完整日志与源码。区分首个错误与连带异常，例如读取网格失败之后包围盒为空，后者通常是结果。

不根据 Console 的累计计数宣称本次失败次数。建立本次验证日志监听窗口，记录开始/结束、异常类型及具体输入；保留既有错误，不通过清空 Console 来制造“无错误”。

### 3.3 Windows 后台进程与异步验证

启动器返回不等于编辑器完成。用实际子进程句柄、最终退出码、新生成报告和日志一起确认。

典型流程：

1. 确认目标项目没有另一编辑器正在占用；已有编辑器采用受控验证入口，或建立真正独立的 Worker。
2. 保存编辑器绝对路径、project path、图形 API、执行方法和本次输出目录。
3. PowerShell 使用 `Start-Process -PassThru -WindowStyle Hidden` 启动后台任务。
4. 分段轮询进程退出与本轮报告；等待期间处理独立工作，不长时间阻塞进度沟通。
5. 读取真正的 ExitCode，检查失败日志和报告完成标志。
6. 结束后核对场景与全局设置是否归还。

`-executeMethod` 若只注册回调或进入 PlayMode，返回时工作尚未完成；附加 `-quit` 可能提前退出。让异步状态机在成功/失败/超时后主动结束。需要 GPU 证据的任务使用有图形设备的模式；`-nographics` 仅用于适合它的静态工作。

不得按进程名称批量终止其他 Unity 工程。读取进程身份时仅输出必要字段，过滤 Hub 的 token、IPC 秘钥和个人信息。

### 3.4 编写有边界的自动验证入口

验证工具与业务功能分离，显式启动，并报告其真实覆盖范围：

| 验证层 | 推荐断言 |
| --- | --- |
| 配置 | 行数、唯一键、缺失映射、歧义候选 |
| 资产 | 路径、类型、GUID/fileID、材质与 Shader 引用 |
| 几何 | 实际目标状态下的读取权限、骨架、有限数值、可见三角形与包围盒 |
| 运行 | 指定条目加载、生成成功、错误日志、退出/切换 |
| 图形 | 等待真实相机帧、记录 GPU/API/目标格式、输出图像 |
| 生命周期 | 禁用/启用、换场景、重载、释放、异常与超时 |
| 精度 | 同输入对照、数值容差、确定性和独立参考 |

临时测试场景可精确重现非可读网格、缩放、非激活对象等边界，再用真实资源确认。合成测试通过不能覆盖真实材质、皮肤和模型结构；全部 Prefab 路径存在也不能覆盖运行切换。

一次验证若改变当前选择、相机 target、控制 UI 或管线，结束时归还原状态。测试报告中记录恢复结果，避免把“测试结束”当成“清理完成”。

异步截图状态机还要核对“请求选择”和“实际对象”。多个相机回调可能早于延迟换枪动作执行；此时若先递增文件编号，会给旧图贴上新条目标签。用选择中状态阻止采集，等实际 item、皮肤输入和资源绑定符合预期后再累计有效帧。错误的测试器不能靠更多截图提高可信度。

### 3.5 一轮证据使用一个身份

建议每轮新建独立目录，以运行 ID 连接以下内容。这里是字段设计，不是已执行报告：

| 字段组 | 内容 |
| --- | --- |
| 身份 | run ID、开始/结束 UTC、本地时区、运行类型 |
| 输入 | 工程、场景、源码/配置哈希、item/skin/seed/wear |
| 环境 | Editor/包版本、GPU/API、色彩空间、RT 格式与尺寸 |
| 输出 | 日志、报告、图像、退出码、各产物哈希 |
| 覆盖 | 枚举数、唯一模型数、实际加载数、成功生成数、实际渲染数 |
| 结果 | 断言、错误、警告、跳过原因、未验证部分 |
| 恢复 | 原设置、恢复后的引用/哈希、剩余临时产物 |

不要让旧汇总 JSON 指向后来被同名覆盖的新截图。时间戳用于发现疑点，哈希用于确定具体文件；仅靠相近时间不能证明同一轮输入。汇总脚本从显式 run 目录读取，避免硬编码早期日志。

### 3.6 图像和日志指标各自证明什么

- PNG 文件 SHA-256 相同：整个文件字节一致。
- PNG 哈希不同：先解码像素比较，文件元数据或编码差异也可能改变哈希。
- A → B → A 输出一致：支持当前输入的重复选择稳定性；不证明与原游戏一致。
- Shader supported/SetPass 成功：支持变体可使用；不证明每个 Pass 已被相机执行。
- 异步皮肤状态成功：支持任务结束；仍需检查输出是否绑定到当前模型。
- 错误数为零：仅对记录窗口及日志级别成立；不自动等于无警告或全工程无问题。
- 视觉“更清晰”：没有固定基准时只是观察；不改写成还原精度提升。

### 3.7 用证据链记录经验

每个值得复用的问题，按以下结构记录：

| 项目 | 内容要求 |
| --- | --- |
| Evidence | 原始日志、源文件、参数、测试产物以及时点 |
| Finding | 现象、可证实根因、排除项和置信边界 |
| Path | 实际修复位置、复现入口、验证方式与回退方法 |

将建议与已实施分开。比如“可使用解析器继续查包头”与“已经解出背景图”属于不同事实；“准备了全目录验证器”也不等于“全目录验证通过”。

### 3.8 可复用任务说明模板

下列自然语言模板用于新项目启动；填写实际路径与目标后再执行，不能把示例当已授权的外部操作：

> 先确认实际 Unity 工程根、版本和定制包，不升级或批量转换原资产。目标是指定的展示入口。索引原资源、配置、脚本路径和运行生成依赖，保存本次改动基线。缺失能力明确降级并记录。先贯通一个代表样本，再验证不同网格读取权限、模型类别和皮肤分支。修改后在目标 Unity 的实际运行状态验证，输出本轮独立日志、图像、来源与限制。只回退本次拥有的改动。将跨项目方法写入 reference，将具体路径、参数和验证状态写入 Profile。

## 4. 风险与不适用边界

工具版本和解析成功率随项目变化。本文不保证任何解析器支持定制引擎、私有加密、全部动画格式或目标平台纹理。

自动化报告中最容易出现的假完成包括：任务已启动、旧报告仍存在、只测了两个资产、EditMode 测试冒充 PlayMode、截图文件名含“original”却不是原游戏基准。遇到这些情况应缩小结论，并补相应验证。

## 5. 验证与回退

交付前核对：

1. 每个关键结论能回到具体证据，历史路径与当前路径有区分。
2. 运行/静态/文档检查使用不同名称，未执行项明确保留。
3. 命令有实际上下文；示意代码标明用途，不冒充已测试工具。
4. 修改文件有基线与归属，报告不会覆盖其他批次。
5. 已验证输出与本轮源码/设置相符，未将旧截图冒充最新结果。
6. 规则库分层、相对链接、UTF-8、稳定 ID、meta 与 GUID 通过检查。

只验证文档时无需重跑大型 Unity 工程；但新增修复则按风险补实际宿主验证，并将结果补入对应项目 Profile。

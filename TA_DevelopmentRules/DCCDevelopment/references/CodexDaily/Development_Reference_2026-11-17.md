# 3ds Max 矩阵动画批处理与保存后验证参考｜2026-11-17

> 类型：REFERENCE；适用范围：在多个 3ds Max 场景间传递选定骨骼的姿态或动画，并确认保存后的活动控制器仍可播放；使用前提：按目标 Max 版本、Rig、Controller、Animation Layer、坐标空间和最终播放链重新验证。
> 关联既有规则：`DCC-DOC-01`、`DCC-CMP-01`、`DCC-BKE-01`、`DCC-REV-01`、`DCC-OPS-01`、`DCC-VAL-01`；项目事实见 [ProjectACG DCC Profile](../../Profiles/ProjectACG/CodexDaily/Development_Profile_2026-11-17.md) 与 [DCC 模块入口](../../README_Tech_DCCDevelopmentRules.md)。

## 1. 适用场景

- A/B 两组 `.max` 文件需要按文件名配对，且只传递参考 Selection Set 中的骨骼。
- A/B 名称、父级或骨骼轴向可能不同，需要在名称匹配和层级匹配之间切换。
- 日志显示写入成功，但时间轴无键、动作不播放，或保存重载后姿势与源文件不一致。
- 需要评估加密 `.mse` 原工具与独立 `.ms` 批处理实现是否等价。

## 2. 前提与依赖

- 冻结 A/B 配对规则、目标 Selection Set、允许覆盖的 B 副本、采样模式（逐帧或源关键帧）和坐标空间（世界或父级局部）。
- 先使用未被旧脚本覆盖的 B 副本；日志要区分匹配、采样、写键、保存、重载和播放六个阶段。
- MaxScript 的 `TimeValue`、`ticksPerFrame`、`node.transform`、`coordsys parent/world` 和 Controller 子通道语义必须以目标版本的 Autodesk 文档为准。
- 对加密或编译的 `.mse`，只能记录已观察到的运行时行为；另写的 `.ms` 不得声称逐行复刻原实现。

## 3. 实现或排查步骤

1. 按文件基名建立 A/B 配对，先报告缺失、重名和结构不兼容。名称模式应保留重名保护；层级模式可按完整父级路径、节点类型和同类兄弟顺序建立唯一映射，歧义时跳过并记录。
2. 每个 A 文件独立读取动画范围。逐帧模式采样 `0..N` 帧；关键帧模式只采样源轨道的关键时间。采样完成后再写 B，避免目标求值反过来影响源数据。
3. 传递完整 `node.transform` 矩阵时，父级局部模式要把 A 的局部矩阵结合 B 的父级矩阵还原为 B 的世界矩阵，并保留缩放；不要把位置、旋转、缩放拆开后再与 B 起始姿势混合，除非已确认两套骨架的基准姿势与轴向一致。
4. 在 B 的目标时间使用 `with animate on` 写入矩阵，写入前清理旧变换键。将动画范围的帧语义与关键时间的 ticks 语义分开；官方 `TimeValue.frame` 用于取得帧数，不能把转成整数得到的 ticks 再当作帧号。
5. 对复合 Controller 递归清理和检查子通道。`numKeys = -1` 代表当前 Controller 不支持直接计数，不能当成零键；应结合 `getSubAnim`、首末时间和矩阵误差判断。
6. 保存 B 后重新打开同一个文件，记录控制器类型、实际首末帧、矩阵误差和代表帧播放结果。日志只有键数或“处理成功”时，不得将结果标为可播放。
7. 若要对照原工具，先在已授权的 Max 进程中用官方通信方式加载脚本并只读盘点控件/运行时符号；需要行为测试时使用临时对象和副本，完成后删除探针。

## 4. 风险与不适用边界

- 世界空间直接写入不同父级或不同局部轴向的骨骼，会导致同帧姿势不一致；只检查名称、父级名称和 Controller 类型不足以证明轴向兼容。
- Animation Layer、Biped、List、Euler/XYZ 等复合控制器可能在加载时被清理或替换；保存前统计不等同于重载后的活动层。
- 把 ticks 误设成动画帧范围会产生类似 `0–24000` 的错误区间；把 `timeToFrame` 等未核实函数直接写入脚本会在运行时得到 `undefined`。
- 直接覆盖 B 有破坏性；没有干净副本、失败恢复和逐骨骼日志时，不应批量写入。
- 内存字符串或 Max 内置 `copyPasteKeys`、Biped 接口的存在，只能证明宿主能力，不能单独证明加密 `.mse` 调用了它们。

## 5. 验证与回退

- 最低验证链：脚本静态结构检查 → 目标 Max 加载 → A/B 采样与写键 → 保存 → 关闭重开 → Controller/首末帧/矩阵误差 → 代表帧播放。
- 把 A、B 的位置、旋转、缩放或矩阵相对首帧变化分开记录，避免“有旋转键”被误写成“旋转值发生变化”。
- 若重载键数为零、首末帧超出范围、矩阵误差超阈值或播放不动，立即恢复 B 副本并保留日志；修正单位、映射或 Controller 后从干净副本重跑。
- 若原 `.mse` 无法还原源码，交付运行时可确认的控件、接口和行为边界，不把未完成的 Copy/Paste 探针当成验证结果。

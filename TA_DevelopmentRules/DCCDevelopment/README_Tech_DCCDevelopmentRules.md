# TA 通用开发规则｜DCC 工具开发模块（CORE + PROFILE）

## 概览

> **文档模式**：ta-development-rules/dcc/v1
>
> **语言与编码**：中文，UTF-8
>
> **模块入口**：本文件是 DCC 工具开发规则的唯一规范来源；TA 规则总入口见 [../README_Tech_TADevelopmentRules.md](../README_Tech_TADevelopmentRules.md)。

本模块适用于 3ds Max、Maya、Blender、Substance 3D Painter 等 DCC 宿主内运行的脚本、插件、动画辅助、预览、模拟、Bake、导入导出与场景修复工具。Unity Editor 工具仍由 [工具开发模块](../ToolDevelopment/README_Tech_TAToolDevelopmentRules.md) 负责；跨 Unity/DCC 链路必须同时加载两个模块，并分别声明状态所有权、协议和验证入口。

规则分为三层：

- `CORE`：跨 DCC 稳定成立的场景兼容、求值、副作用、恢复和验证要求。
- `REFERENCE`：宿主 API、控制器结构、脚本语法、实现方式和排查方法。
- `PROFILE`：项目路径、DCC 版本、插件、节点命名、工具入口、当前验证状态和团队工作流。

本模块不把某个 DCC 的 Controller、Modifier、Dependency Graph、Operator、Action、Constraint 或 UI 类型当作通用事实。所有宿主专有 API 必须在对应 Reference 或 Profile 中重新确认。

## 工作流程

1. **加载上下文**：执行 `DCC-DOC-01`，读取目标场景、工具源码、紧邻 README、DCC/插件版本、控制器或节点图、导出消费者和验证入口。
2. **分类与冻结契约**：执行 `DCC-CLS-01`、`DCC-CMP-01`，确认工具是只读、预览、临时接管、Bake、场景写入还是导入导出，并记录原始场景状态与可逆边界。
3. **显式化状态**：执行 `DCC-STA-01`，写清 Live、近似预览、暂停/旁路、Baked、Unbaked 等状态及其转换和副作用。
4. **设计求值与 Bake**：执行 `DCC-EVL-01`、`DCC-BKE-01`、`DCC-BKE-02`，区分交互近似与最终精确结果，先顺序采样，再写入输出。
5. **实现恢复与故障隔离**：执行 `DCC-REV-01`、`DCC-OPS-01`，保存原始对象引用，预检外部修改，集中恢复全局偏好和场景状态。
6. **分层验证**：执行 `DCC-VAL-01`，完成脚本加载、目标场景、控制器/节点结构、逐帧 A/B、保存重开、导出消费者和性能验证。

## 通用规则（CORE）

### DCC-DOC｜上下文与事实来源

#### DCC-DOC-01｜先读取宿主版本、场景结构和最终消费者

DCC 工具的正确性取决于宿主版本、插件/控制器类型、当前场景结构、求值方式和最终导出消费者，不能只凭 UI 名称或录屏推断实现。

- **必须（MUST）**：修改前读取工具源码、功能 README、目标场景或可复现场景、DCC/插件版本、直接控制器或节点连接、动画范围、单位/坐标约定和导出目标。
- **应当（SHOULD）**：优先查宿主官方 API、随附 SDK/XML 文档和官方脚本样例；二进制字符串或界面观察只能作为定位证据，不能替代运行时类型检查。
- **禁止（MUST NOT）**：把显示名称相似、参数相似或文件中出现某插件字符串直接等同于已确认的运行时结构。
- **验证**：诊断输出能够定位目标节点、控制器/节点类型、宿主 API 可用性、工具版本和当前状态。
- **例外与回退**：无法启动目标 DCC 时，只能交付静态证据、明确假设和真实 DCC 待验项，不得声明场景行为已通过。

### DCC-CLS｜工具分类与最小实现

#### DCC-CLS-01｜按场景副作用和求值影响选择实现模式

- **必须（MUST）**：区分只读扫描、交互近似、临时预览、控制器旁路、Bake、永久场景写入和导入导出；每类操作声明输入、输出、持久化、Undo/回退与性能影响。
- **应当（SHOULD）**：一次性小工具优先使用宿主可直接运行的最小脚本；只有需要菜单持久化、自动更新、跨会话服务或多人部署时才增加安装器、启动脚本或插件包。
- **禁止（MUST NOT）**：为一个可拖入运行的局部工具默认引入系统级安装、启动时自动执行、全局回调或不可见后台求值。
- **验证**：关闭工具、保存重开场景和重启 DCC 后，持久状态与临时状态符合书面契约。

### DCC-CMP｜场景与控制器兼容性

#### DCC-CMP-01｜把控制器、节点图和层级连接视为公开接口

节点的 Controller、Constraint、Modifier、Parent、List/Layer、权重、活动轨道、关键帧和自定义属性共同构成场景兼容性契约。

- **必须（MUST）**：接管前保存原始对象引用和必要结构；恢复前预检当前引用是否仍是工具创建的临时对象。
- **应当（SHOULD）**：新增功能优先包裹或分层保存原轨道，不直接销毁未知控制器；对不支持的嵌套、锁定或第三方结构应阻断并报告。
- **禁止（MUST NOT）**：仅根据类名、轨道索引或节点名称盲目覆盖当前控制器，也不得在检测到外部修改后强行恢复旧引用。
- **验证**：Live/Baked/Unbake 往返后，原控制器类型、参数、约束、层级和关键帧保持一致；异常中途失败不会留下半切换状态。

### DCC-STA｜状态转换与所有权

#### DCC-STA-01｜显式定义 State、Input、Transition、Effect 和 View

包含预览、旁路和 Bake 的 DCC 工具必须使用显式状态模型，不得让按钮分别修改一组隐式全局变量。

- **必须（MUST）**：为每个状态定义场景控制器所有权、全局偏好、活动轨道、允许操作和用户可见说明；转换前先完成全量预检，再统一执行副作用。
- **应当（SHOULD）**：按钮使用结果导向术语，例如“继续调整”“精确预览”“播放/导出”“恢复原控制器”，而不是只暴露 Live、Bake、Detach 等内部名词。
- **禁止（MUST NOT）**：把“权重为 0”“隐藏 UI”“调低参数”当作求值链已经断开；必须以依赖图实际是否仍会求值为准。
- **验证**：逐个状态检查当前控制器、活动轨道、全局偏好、播放性能和诊断输出；往返转换结果可回放。

### DCC-EVL｜时序求值与交互性能

#### DCC-EVL-01｜交互近似与最终精确结果必须分离

- **必须（MUST）**：明确标记快速编辑、降采样、局部回退、冻结或缓存是否为近似结果；最终预览和 Bake 必须进入书面定义的精确求值路径。
- **应当（SHOULD）**：对有历史依赖的模拟从起始帧或 Warm-up 帧按时间顺序推进，并通过读取最终消费者或宿主规定的求值入口强制完成依赖图计算。
- **禁止（MUST NOT）**：通过随机跳帧采样有状态模拟，也不得把宿主的交互优化模式直接作为最终 Bake 结果。
- **验证**：从同一起始状态重复完整求解两次结果一致；随机拖动时间滑块不会改变随后正式 Bake 的结果。

### DCC-BKE｜Bake 数据边界

#### DCC-BKE-01｜先完整采样，再写关键帧

- **必须（MUST）**：采样阶段只读取求值结果并写入内存快照；全部采样成功后才创建/替换 Bake 控制器和关键帧。
- **应当（SHOULD）**：重新 Bake 使用临时输出轨道，全部写入成功后一次替换旧轨道；失败时保留旧 Bake 或原控制器。
- **禁止（MUST NOT）**：边求值边写目标节点关键帧，因为写入会反向改变后续依赖图和模拟历史。
- **验证**：连续 Bake 两次逐帧一致；任一采样或写键失败后，Live 路径和旧 Bake 仍可用。

#### DCC-BKE-02｜Bake 最终消费者的稳定局部变换

- **必须（MUST）**：明确 Bake 对象是最终蒙皮骨、导出节点或其他消费者，而不是仅在 DCC 内驱动它们的 Helper；明确 Position、Rotation、Scale、约束和单位边界。
- **应当（SHOULD）**：层级动画优先保存相对父节点的局部变换和稳定旋转表示，并在导出目标中验证；世界空间 Bake 仅在消费者契约明确要求时使用。
- **禁止（MUST NOT）**：在未验证非均匀缩放、Shear、负缩放、约束或父级变化时声称 Position/Rotation Bake 完整保真。
- **验证**：Live 精确求解与 Baked 在代表帧逐节点 A/B；导出后在最终引擎或下游 DCC 再验证一次。

### DCC-REV｜非破坏切换与恢复

#### DCC-REV-01｜原始引用和工具状态必须随场景持久化

- **必须（MUST）**：需要跨保存/重开恢复的原控制器、临时控制器、Bake 轨道、范围和状态保存到宿主支持的场景级持久结构，并使用稳定 Schema/ID。
- **应当（SHOULD）**：将 Live/Baked 切换与 Unbake 分离；前者只切活动结果并保留 Bake 数据，后者才删除工具包装并恢复原始结构。
- **禁止（MUST NOT）**：只把原控制器保存在脚本全局变量或窗口实例中，也不得因窗口关闭就丢失场景恢复能力。
- **验证**：保存、关闭、重开后仍能识别当前状态并安全恢复；损坏或缺失引用时阻断而不是覆盖。

#### DCC-REV-02｜全局宿主偏好必须成对捕获和恢复

- **必须（MUST）**：修改 DCC 全局偏好、时间设置、选择、动画开关或求值模式前先捕获原值，在正常关闭、异常、取消和失败路径恢复。
- **应当（SHOULD）**：场景持久状态与进程级偏好分开管理；Baked 等不依赖全局偏好的状态不应长期占用全局设置。
- **禁止（MUST NOT）**：假设脚本结束、窗口关闭或切换场景会自动恢复全局偏好。
- **验证**：从不同初始偏好进入/退出工具，退出后精确回到原值。

### DCC-OPS｜事务、安全和诊断

#### DCC-OPS-01｜先全量预检，再执行原子化切换

- **必须（MUST）**：在修改任一节点前预检整个目标集合；操作失败时恢复已修改节点、时间滑块、活动轨道、全局偏好和进度 UI。
- **应当（SHOULD）**：错误信息包含当前操作、目标节点、期望结构和宿主原始异常；诊断命令输出工具版本、状态、目标集合和控制器类型。
- **禁止（MUST NOT）**：捕获异常后静默继续、只显示泛化错误，或把半完成结果标记为成功。
- **验证**：人为制造缺失节点、外部替换控制器、非法帧范围和中途写键异常，确认不会留下半完成状态。

### DCC-UI｜DCC 脚本 UI

#### DCC-UI-01｜UI 必须适配宿主 DPI、字体和脚本控件差异

- **必须（MUST）**：在目标 DCC、目标语言和实际 DPI 下打开工具，检查标题、Spinner/输入框、列表、按钮和错误文本不截断、不越界。
- **应当（SHOULD）**：原生控件不支持字体或布局时，可局部使用宿主支持的 .NET/Qt 控件，但事件签名、主题、生命周期和异常路径必须在真实宿主验证。
- **禁止（MUST NOT）**：只凭固定像素和英文短标签判断中文 UI 可用，也不得用安装流程解决纯布局问题。
- **验证**：至少覆盖默认缩放和团队常用高 DPI；按钮文字能直接说明结果和下一步。

### DCC-VAL｜验证与交付

#### DCC-VAL-01｜按脚本、场景、求值、恢复和消费者分层验证

- **必须（MUST）**：至少完成脚本编译/加载、真实目标场景操作、状态往返、逐帧 Live/Baked A/B、保存重开和最终导出消费者验证。
- **应当（SHOULD）**：记录交互延迟基线、Bake 帧数/耗时、重复 Bake 一致性、异常恢复和目标节点计数。
- **禁止（MUST NOT）**：用括号检查、文本搜索、SDK 反射、窗口能打开或文件能导出替代动画内容验证。
- **验证**：交付明确列出已完成、未完成、宿主/场景版本、代表性用例、回退方式和剩余风险。

## 项目定制规则（PROFILE）

CORE 不包含固定 DCC 版本、插件类名、场景路径、Rig 命名或团队按钮术语。当前 ProjectACG 的 3ds Max Spring 动画工具事实位于 [Profiles/ProjectACG/spring-animation-baker.md](Profiles/ProjectACG/spring-animation-baker.md)，其中记录：

- 工具与目标场景路径、当前版本和直接运行方式；
- `SpringQuickEditMode`、Spring Controller、胸部 Helper/骨骼命名与扫描规则；
- 四态工作流、可逆 Bake 结构、已解决错误和当前验证边界。

## 资源加载与规则维护

- 开发 DCC 场景扫描或修复工具：读取 `DCC-DOC-01`、`DCC-CMP-01`、`DCC-OPS-01`、目标场景和当前 Profile。
- 开发模拟编辑、精确预览或动画 Bake：额外读取 `DCC-STA-01`、`DCC-EVL-01`、`DCC-BKE-*`、`DCC-REV-*` 和 [3ds Max Spring Controller 动画编辑与可逆 Bake 参考](references/3ds-max-spring-controller-edit-and-reversible-bake.md)。
- 涉及 Unity/DCC 双向预览、贴图或材质同步：同时读取 [Unity 与 DCC 本地预览链路参考](../ToolDevelopment/references/local-dcc-preview-link.md) 和对应 Unity 工具 Profile。
- 涉及 FBX 或下游引擎：读取实际导出设置、单位/轴向、骨架消费者和目标引擎验证入口；DCC 内 A/B 不能替代导出结果。
- 新增宿主或插件专有技巧时写入 `references/`；项目路径、版本、类型和当前验证写入 `Profiles/<Project>/`；只有跨宿主稳定且证据充分的要求才修订本 CORE。

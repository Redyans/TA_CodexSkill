## 11. Codex

时间：2026-11-17T03:38:50.576Z

这个工具主要做两件事：压缩 FBX 的动画导入数据，或精简已经导出的独立 `.anim` 曲线。它不会把原始 `.fbx` 文件重新编码变小；独立 `.anim` 减帧则可能减少动画资源的数据量。

- **FBX 导入**：扫描你选中的 FBX 或动作目录，设置 Unity 的动画压缩方式、误差、重新采样和循环参数。手动执行时会修改 FBX 的导入设置（`.meta`）；如果启用了“同步已找到的 standalone `.anim`”，还会尝试更新匹配的现有 `.anim`。它不会自动创建缺失的 `.anim`，也会检查时长、帧率、Rig 和绑定等兼容条件。详情见[使用手册的 FBX 说明](D:/work2025U3D/Valkyria/ProjectACGMain2/ProjectACG/docs/ai-coding/performance/animation-optimization-user-guide.md:65)。

- **独立 `.anim` 减帧**：针对已经导出的 `.anim`，在位置、缩放和旋转误差范围内删去不必要的关键帧。它会先生成候选供你预览；确认角色播放和混合效果后，才应用到原件。应用前会备份，保留原路径、GUID、帧率和绑定；不支持的曲线会保持原样。详情见[减帧适用范围和流程](D:/work2025U3D/Valkyria/ProjectACGMain2/ProjectACG/docs/ai-coding/performance/animation-optimization-user-guide.md:18)。

你刚才要求关闭的自动导入处理和 `.anim` 自动队列目前都已关闭；手动扫描、压缩和候选应用仍可使用。若 Unity Editor 当时已打开，重启后可确保它载入关闭后的设置。

## 30. Codex

时间：2026-11-17T06:29:35.083Z

可以同时处理，但要分成两层：

| 设置 | 处理位置 | 作用 |
|---|---|---|
| Animation Compression | FBX Importer | Unity 原生动画压缩 |
| Rotation / Position / Scale Error | FBX Importer | 原生压缩误差 |
| Resample Curves | FBX Importer | 是否重新采样曲线 |
| 降低曲线精度 | 导入后的 `AnimationClip` 曲线处理 | 把数值和切线四舍五入到 3 位小数 |
| 精简恒值曲线关键帧 | 导入后的曲线处理 | 保留曲线，只保留首尾关键帧 |
| 排除 Scale 曲线 | 导入后的曲线处理 | 按条件删除 `m_LocalScale.x/y/z` |
| `weapon_l / weapon_r` 保护 | 导入后的曲线处理 | 防止武器节点及其子节点被删 Scale |

推荐的导入流程是：

1. `OnPreprocessModel` / `OnPreprocessAnimation` 设置 FBX 原生参数。
2. Unity 完成采样、重采样和原生压缩。
3. 用 `OnPostprocessAnimation(GameObject root, AnimationClip clip)` 处理每个导入出来的动画 Clip。
4. 按以下顺序处理自定义规则：
   - 先判断恒值曲线；
   - 恒值曲线启用“精简”时保留绑定并减少关键帧；
   - 再处理符合条件且未被保护的 Scale 曲线；
   - 最后做 3 位小数精度处理；
   - 完成后校验曲线和 Clip 元数据。

有两个关键冲突需要处理：

- 如果同时开启 Unity 原生 `Remove Constant Scale Curves`，它可能先把 Scale 曲线删除，后面的 `weapon_l / weapon_r` 保护就无法恢复。因此使用截图里的自定义 Scale 删除规则时，原生这个选项建议关闭。
- 原生压缩、重新采样和 3 位小数处理会叠加误差。若要保持截图工具的行为，应使用较保守的原生压缩参数，并对导入结果做实际角色播放验证。

当前项目还不能直接把旧的 `AnimationClipOptimizationService` 原样用于 FBX 导入，因为它要求处理 standalone `.anim` 主资源，而 FBX 动画是嵌入式子资源。需要增加一套专门给 `OnPostprocessAnimation` 使用的导入处理入口，不写 `AssetDatabase.SaveAssetIfDirty`，由 Unity 的导入事务保存结果。

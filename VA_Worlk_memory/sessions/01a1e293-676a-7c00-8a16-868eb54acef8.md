建议做成“只对当前选中据点渲染屏幕空间描边”。描边目标是模型的 `Renderer`，不包括点击碰撞体、定位点或 UI 标签；这样线宽在星球旋转、镜头缩放时仍比较稳定，也不会改动一整套建筑共用的材质。

工程里拾取链路已经具备：点击建筑会通过碰撞体得到据点逻辑 ID，[MainlineExplorationMapInput.cs](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/GameScripts/HotFix/GameLogic/MainlineExploration/MainlineExplorationMapInput.cs:144) 再交给地图绑定查找目标，[MainlineExplorationMapBindings.cs](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/GameScripts/AOT/Common/MainlineExplorationMapBindings.cs:276) 保存了对应的模型根节点。当前 `_selectedOutpostId` 已驱动 UI 选中态；需要留意它使用的是配置行 ID，而模型绑定使用 `OutpostId`，实现时要通过配置把两者对应起来。[MainlineExplorationPlanetUI.cs](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/GameScripts/HotFix/GameLogic/MainlineExploration/MainlineExplorationPlanetUI.cs:427)

渲染侧不能直接依赖现有的 `Outline` 特征：主线探索建筑材质使用 `BattleSceneBaseLit`，[该 Shader](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/Shader/Scene/New/PackedMaskPBR/BattleSceneBaseLit.shader:85) 没有 `LightMode=Outline` pass；虽然 Lobby 的各质量档已有名为 `Outline` 的 Renderer Feature，例如 [Low 档](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/AssetRaw/Settings/URP-Lobby-Low-Renderer.asset:56)，建筑当前仍不会因此自动描边。`CharacterDistortedOutlineRendererFeature` 有渲染器遮罩和深度判断的实现思路，但它接在角色 Timeline 效果上，不适合直接当作据点选中组件使用。

建议的落地路径：

1. 点击据点后，从现有绑定拿到该建筑根节点下的全部可见 `Renderer`，只把这一组交给选中描边通道；宝箱是否参与可以单独决定。
2. 在 URP 中绘制所选模型的遮罩，再做深度感知的边缘扩张与合成。默认只描可见轮廓，让星球表面和其他建筑正常遮挡。可以先用稳定的细线和一套选中色，再根据美术效果调整。
3. 选中变化时替换目标；点空白、关闭详情、切换区域或星球、隐藏地图时清除目标。当前代码已有这些状态切换点，能沿用现有生命周期。
4. UI 标签的选中效果继续独立处理，避免模型描边和标签选中状态互相耦合。

另一种做法是在 `BattleSceneBaseLit` 上增加几何外扩的 `Outline` pass，再用选中状态开关。它初期可能更省事，但线宽容易随镜头变化，建筑锐利或分件多时也更容易出现粗细不匀和接缝问题；不建议直接修改共用材质来试效果。

验收时重点看主线探索的实际画面：切换选中模型、点空白和关闭详情后的清理，模型被星球遮挡时轮廓是否仍正确，以及 Lobby 的 Low、Mid、High、Ultra 档表现是否一致。工程当前已有大量未提交改动；本轮只读分析，没有修改文件或运行测试。

## 61. Codex

时间：2026-11-16T11:51:05.140Z

有，当前 Shader 已经有阴影逻辑：

- 接收主光阴影：`GetMainLight(input.shadowCoord)`，并使用 `mainLight.shadowAttenuation`。
- 接收附加光阴影：`additionalLight.shadowAttenuation`。
- 投射阴影：`UsePass "Universal Render Pipeline/Lit/ShadowCaster"`。

看起来阴影不明显的原因是：

```hlsl
color = albedo * (directLighting + ambient);
```

阴影只衰减 `directLighting`，自定义环境光 `ambient` 仍然存在，所以阴影区域不会完全变黑。这是标准做法。

如果要让阴影更明显，最简单就是让环境光也受阴影影响：

```hlsl
half shadowAmbient = mainLight.shadowAttenuation;
half3 color = albedo * (directLighting + ambient * shadowAmbient);
```

但这会让环境光在主光阴影里一起变暗。当前 Shader 并不是没有阴影，而是自定义环境光把阴影托亮了。

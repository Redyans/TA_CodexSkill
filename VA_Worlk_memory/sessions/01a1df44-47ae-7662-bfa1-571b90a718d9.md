## 8. Codex

时间：2026-11-15T12:58:18.482Z

我按“高处看见云层铺满山谷、一直延伸到地平线”的背景型云海来分析。针对 Android/iOS，建议优先做**网格云面 + 轻量 Shader**，再用高度雾柔化远景；不建议一开始上体积云光线步进。

| 方案 | 画面与性能特点 | 适用场景 |
|---|---|---|
| 天空盒全景贴图 | 成本最低，但没有视差，镜头移动时容易像背景图 | 固定镜头、远景天空 |
| 云面网格或穹顶 + 云纹理 | 形状、视差和缓慢流动可控；一个网格和材质就能控制绘制量，但透明云面覆盖屏幕较大时仍会吃填充率 | **推荐：高空云海、可活动镜头** |
| Billboard / 粒子云团 | 适合零散云团和近景飘云；大量重叠会增加透明过绘和排序成本 | 云海上的少量前景点缀 |
| 高度雾 | 擅长压远景、柔化云海与地平线交界，本身不能代替云层形状 | 给云面网格做补充 |
| 体积云光线步进 | 空间感和光照最好，但要对大量屏幕像素反复采样，移动端成本高 | 高端设备、特写或离线演出 |
| 预烘焙视频 / 序列帧 | 固定镜头下视觉丰富，交互和视差有限，还要考虑解码与资源体积 | 镜头受控的剧情演出 |

**工程里已有可利用的基础。** 项目有 `CustomSkyCloudSurface` 云层 Shader，默认关闭流动图、细节和法线选项时，主云图路径只采样一次；开启流动图会增加采样。[CustomSkyCloudSurface.shader](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/Shader/Scene/New/CustomSkybox/CustomSkyCloudSurface.shader:62) [CustomSkyForward.hlsl](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/Shader/Scene/New/CustomSkybox/ShaderLibrary/CustomSkyForward.hlsl:76) 项目也有通用云朵网格预制体，可供美术和网格形状参考。[pre_common_cloudA01.prefab](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/AssetRaw/Scene/common/prefab/pre_common_cloudA01.prefab)

有个需要留意的工程差异：Battle Low、High、Ultra Renderer 已挂载自定义天空 Feature，但 Mid Renderer 没有；高度雾则在部分档位接入。[URP-Battle-Low-Renderer.asset](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/AssetRaw/Settings/URP-Battle-Low-Renderer.asset:186) [URP-Battle-Mid-Renderer.asset](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/AssetRaw/Settings/URP-Battle-Mid-Renderer.asset:27) 此外，[CustomSkybox.shader](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/Shader/Scene/New/CustomSkybox/CustomSkybox.shader:406) 即使关闭天空层仍会先采样白天、夜晚天空图，再采样云图，不适合直接当作移动端纯云海的最轻方案。[README](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/Shader/Scene/New/CustomSkybox/README.md:20) 关于 Feature 尚未接入的描述也与当前部分 Battle Renderer 资源不符，选方案时应以目标场景实际使用的 Renderer 为准。

我的建议是做一个**专用、普通 URP 渲染路径的云海网格**：用弯曲的大型网格或穹顶承接云面，单个材质、一张压缩云纹理，Shader 内缓慢滚动 UV；低档保持一次纹理采样，高档再加一层细节。关闭阴影和实时法线，避免多层透明网格互相覆盖，利用现有高度雾淡化地平线。这样不依赖特定档位的 Renderer Feature，性能也更容易控制。关键风险是透明云面的屏幕覆盖率，所以最终要在目标手机上用 GPU Profiler 和 Overdraw 验证，单看 draw call 不够。

这轮是方案分析，没有改动文件，也没有实机性能数据。要确定网格形状和遮挡方式，还需要知道具体落在哪张场景，以及镜头是固定展示还是会围绕角色大幅移动。

**1. “看穿玻璃”来自采样已经绘制好的背景**

三个版本都调用了：

```hlsl
SHADERGRAPH_SAMPLE_SCENE_COLOR(screenUV)
```

在项目的 URP 中，它最终读取 `_CameraOpaqueTexture`，也就是不透明物体渲染完成后的场景颜色。

因此玻璃表面可以直接显示背景；改变采样坐标，就能让背景产生扭曲：

```hlsl
float3 background = SampleSceneColor(screenUV + offset);
```

这种方法需要相机提供 **Opaque Texture**。默认情况下，该纹理不包含随后绘制的透明物体，因此多层玻璃、透明粒子之间的折射会受限制。

**2. 折射：用法线控制背景采样位置**

`SimpleGlass` 和 `Glass` 把法线贴图与网格法线经矩阵变换得到的分量组合起来，生成 UV 偏移。核心可以概括为：

```hlsl
offset = normalOffset.xy * (_Refraction - 1);
background = SampleSceneColor(screenUV + offset);
```

所以：

- `_Refraction = 1` 时，偏移为零。
- 大于或小于 `1`，会向相反方向扭曲。
- `_BumpMap` 和 `_BumpScale` 可以制造凹凸、雨痕、波纹玻璃的背景变形。

`Glass(IOR)` 的计算则是：

```hlsl
offset = (IOR - 1)
       * viewSpaceNormal.xy
       * (1 - dot(worldNormal, viewDirection));
```

斜着看表面时，偏移通常更明显。**这里的 IOR 实际控制的是屏幕偏移强度，没有计算光线穿过玻璃前后表面及厚度的完整折射路径。**

还有一个源码细节：**IOR 版这段偏移使用网格法线，没有使用法线贴图扰动后的法线**；法线贴图仍参与表面光照和自定义 Cubemap 反射。

**3. 反射：按反射方向采样 Cubemap**

它们用视线和法线计算反射方向：

```hlsl
float3 reflectionDir = reflect(-viewDirection, normalWS);
float4 reflection = texCUBElod(
    _CubeMap,
    float4(reflectionDir, _BlurReflection)
);
```

`_ReflectionIntensity` 控制亮度，`_ColorCubemap` 控制颜色，`_BlurReflection` 控制采样的 mip 层级，让环境倒影变模糊。

**这个 Blur 只模糊 Cubemap 反射，不会对玻璃后面的画面进行模糊滤波。** 背景的磨砂观感主要依赖其他参数、法线扰动及背景纹理本身的分辨率。

此外，它们仍调用 `UniversalFragmentPBR`，所以还会获得 URP 的灯光高光和环境反射。

**4. 边缘玻璃感：Fresnel**

核心角度关系是：

```hlsl
fresnel = pow(max(1 - dot(N, V), 0.0001), power);
```

正面看时较弱，擦着表面看时较强。Shader 用它增强边缘反射或边缘颜色，也可以用于透明度的角度渐变。

`_FresnelStrength` 控制强度，`_PowerFresnel` 控制效果集中在多窄的边缘区域。这里属于可调的艺术化效果。

**5. 三个版本的“透明度”并不完全相同**

`SimpleGlass / Glass` 将背景采样和自定义反射放进 **Emission**，避免背景再次受到表面光照影响；随后通过 Alpha 与当前画面混合。关闭渐变等附加选项时，可以简化为：

```hlsl
Emission = reflection + background * (_Opacity * _Intensity);
Alpha = 1 - _Fade;
```

所以这里 `_Opacity` 主要影响背景贡献，`_Fade` 才控制整个材质的淡出。**不能直接按“Opacity 越大越不透明”理解。**

`Glass(IOR)` 则先算表面光照，再自行混入折射背景：

```hlsl
color.rgb = lerp(refractedBackground, litSurface, calculatedAlpha);
color.a = 1;
```

它最终输出的 Alpha 是 `1`，看起来透明是因为背景已经被合成进颜色。

`Glass` 和 `Glass(IOR)` 还用贴花 Alpha 遮罩混合颜色、法线、金属度和光滑度，并压低贴花区域的背景贡献，从而表现玻璃瓶上的标签或印刷图案。

另外，当前三个版本的 **Forward Pass 都写死了 `ZWrite On`**；即使 Glass 和 IOR 的面板暴露了 `_ZWrite`，该 Pass 仍会覆盖它。多层透明物体的遮挡和排序需要特别留意。

## 18. Codex

**可以影响，但 `URP - CS_Glass` 的贴图 A 通道控制的是背景透出，不是整个材质的最终透明度。**

在中文面板的「背景透出与透明遮罩」里：

- 开启 **使用 Albedo Alpha 遮罩**：贴图 A 才参与计算。
- A 越小，背景贡献越多；A 越大，更多保留原本的表面不透明权重。
- **反转 Albedo Alpha** 可以交换黑白作用。

最终混合用的 Alpha 由「整体淡出量」及其视角选项控制。因此，**贴图 A＝0 时，表面颜色和反射仍可能存在，不会完全消失**。

另外，关闭角度变化、背景亮度倍率为 1 时，如果「背景透出量」已设为 1，贴图 A 就不会再产生区别。

如果你需要常规的 **A＝0 完全透明、A＝1 完整显示**，需要把贴图 A 接入最终 Alpha；当前源码没有这样连接。

## Helpful technical semantics in descriptions

- `_Refraction = 1` means zero screen offset, 0 does not disable refraction.
- Glass `_Opacity` controls background contribution, not normal opacity; final Alpha comes from `_Fade`.
- Albedo Alpha only affects background mixing when enabled, does not directly multiply final Alpha.
- `_Intensity` is background multiplier, not decal self-emission.
- `_EmissionColor` & `_EmissiveIntensity` (IOR `_EmissionIntensity`) control decal emission masked by `_DetailAlbedoMap.a * _ColorDecal.a`.
- `_UseCubemap` toggles only Fresnel’s cubemap modulation; doesn’t disable independent reflection.
- `_BlurReflection` only blurs cubemap via mip, not background.
- IOR screen offset uses geometric normal, not normal-map-perturbed normal.
- `_PowerFalloffOpacity` and `_PowerFalloffFade` are amplitude multipliers despite original “Power” names.

### 2. 单点采样问题

- 对于平面来说，使用Matcap得到的颜色总是同一个。例如立方体中每个面内部是没有颜色变化的。

[image](https://pic2.zhimg.com/v2-358d1b03f8e3237adecfdb1a63c0edd9_1440w.jpg)

左侧为视图空间法线采样得到的matcap，立方体面内部没有细节

- **解决办法：**\
  matcap本质上就是一个材质球的正视图，那么我们就想象在视图正前方无限远处有一个虚拟球体，我们要做的工作就是把真实的物体反射结果对应到这个虚拟球上去。我们只需要找到平面对应反射角度与球体相同的位置，就可以直接使用该球体的法线（如下图所示），归一化后作为`matcapUV`。因为是无限远，所以视线方向就可以看成是z轴方向，将z轴单位向量和反射方向相加取模，就可以得到我们需要的虚拟球法线。

[image](https://pic1.zhimg.com/v2-0da21bf2772084807fbb14ada41a2bbe_1440w.jpg)

通过反射方向获得采样位置

-

* 具体实现方式如下：
* 先定义一下相关参数
```c
// URP 
half3 norVS = mul(i.norWS, (float3x3)UNITY_MATRIX_I_V); // 逆转置矩阵 
half3 vDirWS = GetWorldSpaceViewDir(i.posWS);
half3 posVS = TransformWorldToView(i.posWS);
```

-

* 按照上面的思路，先得到反射向量，z方向+1后再归一化得到虚拟球法线。
```c
half3 r = reflect(posVS, norVS); 
r = normalize(r); 
half3 n = r + float3(0, 0, 1); 
n = normalize(n); 
half2 matcapUV = n *0.5 + 0.5;  参考这个修复下在平面上的表现
```

**透视相机下，用在平面玻璃上是合理的。** 这里的“边缘”是指**视线接近平行于表面时的反射增强**，不会自动识别玻璃四周的边框。

| 参数 | 在平面上的作用 |
|---|---|
| 边缘效果使用环境图 | 勾选后，Fresnel 效果乘以 Cubemap 的反射颜色，与 MatCap 独立 |
| 边缘强度＝1 | 控制这部分额外反射的亮度 |
| 边缘集中度＝2 | 越大，越需要斜着看才明显；正视时更弱 |

平面的法线虽然相同，但透视相机到每个像素的视线方向不同，因此仍可能出现渐变。**平面较小或相机较远时，整面接近均匀；斜看时整块增强，这都是正常表现。** 想让窗玻璃四周固定出现一圈亮边，则需要边缘遮罩或模型倒角。


   当前采用透明混合，效果可以近似理解为：

当前代码可以概括为：

```text

         +（模型方向项 + 法线贴图扰动）×（折射偏移 − 1）
         + 毛玻璃噪声偏移
```

**为什么会整体往一边偏：**

- **折射偏移不等于 1 时**，原 Shader 会加入模型法线的方向项。平面上这个方向基本一致，所以整块背景会往同一个方向移动，再叠加法线贴图的局部凹凸。它没有保证围绕原位置对称扰动。
- **折射偏移等于 1 时**，剩下的是毛玻璃噪声。噪声采用 `RG × 2 − 1`，只有 RG 的平均值接近 **0.5**，正负偏移才大致平衡。噪声偏亮、偏暗，都会造成整体偏移。
- **噪声贴图开启 sRGB** 也会造成方向偏差：在线性项目中，贴图里的 0.5 会被转换为约 0.214，映射后约为 −0.572，两轴就容易持续往负方向偏。

## 150. Codex

时间：2026-11-10T03:31:08.274Z

这个功能是**视角相关的整体淡出**，控制玻璃最终 Alpha，也就是玻璃本身显示得多不多、透不透明。

截图中的参数作用：

- **整体淡出量**  
  不启用“淡出随视角变化”时直接生效。  
  公式大致是：

  ```text
  最终 Alpha = (1 - 整体淡出量) × 基础贴图 A
  ```

  你这里是 `1`，所以玻璃整体 Alpha 接近 0，玻璃本体会被完全淡出。

- **淡出随视角变化**  
  开启后，淡出不再是固定值，而是根据：

  ```text
  表面法线 · 视线方向
  ```

  计算 Fresnel 角度。正视和平视时透明度不同，转动相机或改变观察角度就会变化。

- **反转角度淡出**  
  交换正视角和掠射角的淡出方向。  
  开启后，原本正视显示、侧视淡出的关系会反过来。

- **角度淡出范围**  
  控制从哪个视角范围开始出现淡出。截图中的 `0.55` 会改变角度曲线的起始位置。

- **角度淡出系数**  
  控制角度淡出的强弱。值越大，角度变化造成的透明差异越明显。

当前这个 `RainGlassChange.mat` 的关键配置是：

```text
整体淡出量 = 1
淡出随视角变化 = 1
反转角度淡出 = 1
角度淡出范围 = 0.55
角度淡出系数 = 2.17
```

所以它不是固定透明，而是**明显依赖视角**。另外 `整体淡出量 = 1` 会参与角度曲线计算，可能导致玻璃在部分角度几乎消失。

**都用于调色，但作用不同，不算重复。**

| 参数 | 实际作用 | 例子 |
|---|---|---|
| 基础贴图旁的颜色 | 与贴图 RGB 相乘，整体染色 | 白色保留贴图原色，蓝色让贴图偏蓝 |

当前计算顺序是：

**贴图 × 颜色 → 调整饱和度 → 乘表面亮度 → PBR 光照**

颜色选择器里的“饱和度”只改变**染色色值**；“表面饱和度”处理的是**整张贴图与颜色相乘后的结果**，不能完全替代。

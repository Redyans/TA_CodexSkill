## 4. Codex

查了当前工程源码，**`UIBlurBackground_Snapshot` 是运行时截取屏幕、经过模糊处理后生成的 RenderTexture。你看到的 `GammaUIDefault` 材质负责显示这张结果纹理。**

具体流程是：

1. **打开结算界面前，先截屏**

   `Settlement` 配置了 `blurBackground: true`。UI 框架在加载结算预制体之前调用截图，因此结算界面自身不会被截进去。见 [UIWindow.cs:348](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/GameScripts/HotFix/GameLogic/Module/UIModule/UIWindow.cs:348)。

   截图工具等待帧末，然后调用：
   ```csharp
   ScreenCapture.CaptureScreenshotIntoRenderTexture(texture);
   ```
   捕获当时已经渲染完成的屏幕画面，RT 命名为 `UIBlurBackground_Snapshot`。见 [ScreenCaptureUtility.cs:25](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/GameScripts/HotFix/GameLogic/UI/Common/ScreenCaptureUtility.cs:25)。

2. **在 GPU 上做横向、纵向高斯模糊**

   使用的是 [S_UIPopupBackgroundBlur.shader:57](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/AssetRaw/Shaders/S_UIPopupBackgroundBlur.shader:57)，每次对一个方向做 **9 点加权采样**：中心权重大，离中心越远权重越小。

   每轮处理如下：
   ```text
   截图 RT → 横向模糊 → 临时 RT → 纵向模糊 → 写回截图 RT
   ```

   当前结算代码配置为 **3 轮、Radius = 8**，因此一共执行 **6 次模糊 Blit**。单方向采样位置是中心及两侧 `±4、±8、±12、±16` 像素。见 [UIBlurBackground.cs:445](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/GameScripts/HotFix/GameLogic/Module/UIModule/UIBlurBackground.cs:445)。

3. **把已经模糊的纹理放到 UI 最底层**

   代码动态创建你截图里的节点：
   ```text
   m_blur_background
   ├─ m_raw_blur_snapshot   ← 显示模糊 RT
   └─ m_img_blur_tint       ← 可选的遮色层，控制压暗/染色
   ```
   并将 RT 赋给 `RawImage.texture`，材质设为 `GammaUIDefault`。见 [UIBlurBackground.cs:223](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/GameScripts/HotFix/GameLogic/Module/UIModule/UIBlurBackground.cs:223)。

还有几个与这张截图相关的细节：

- **这是静态快照**：正常展示期间复用结果，不会每帧重新截屏和模糊。

## 15. Codex

时间：2026-11-10T08:26:45.324Z

明白，是 **Inspector 里直接预览 RT 就发灰**。前面提到的 UI 遮罩不适用于这个现象。

**现在最可疑的是：截图 RT 的颜色空间声明与截图数据不匹配。**

我核对了项目代码及本机 Unity 2022.3 的实现，截图使用：
```csharp
new RenderTextureDescriptor(width, height, RenderTextureFormat.Default, 0)
```
**这个构造方式默认走 `RenderTextureReadWrite.Linear`，即非 sRGB RT。** 项目没有再覆盖它。位置：[ScreenCaptureUtility.cs:35](/D:/work2025U3D/Valkyria/ProjectACGMain/ProjectACG/Client/Assets/GameScripts/HotFix/GameLogic/UI/Common/ScreenCaptureUtility.cs:35)。

问题可能出在这条链路：

```text
屏幕上已经编码成 sRGB 的颜色
→ 截屏写入非 sRGB RT
→ 预览把这些数值当作 Linear
→ 再做一次 Linear → sRGB
→ 中间调和暗部被抬亮，看起来发灰
```

例如，**如果屏幕数值 `0.2` 被原样写入这个 RT**，再次编码后就会变成约 `0.485`；`0.5` 会变成约 `0.735`。这正是“像蒙了一层灰、颜色变淡”的典型表现。

另外，你看的 `UIBlurBackground_Snapshot` 已经经过模糊。模糊会降低局部对比度，但我核算了 Shader 的采样权重，总和约为 **1**，也没有去色运算，所以它**不会把一整块均匀颜色无缘无故整体提亮**。如果大面积暗色也明显变浅，颜色空间错配更值得优先查。

**修正方向**是明确截图数据的编码，并让截图 RT、模糊临时 RT 保持一致。模糊缓存目前也重新创建了默认 Linear descriptor；若截图改为 sRGB，缓存应同步调整或继承 `texture.descriptor`。

目前已确认“RT 默认采用 Linear”这个事实；**尚未读取实际截图像素做对照，因此颜色空间错配是有明确依据的首要嫌疑，还不能说已经完成根因验证。** 本轮未改代码。

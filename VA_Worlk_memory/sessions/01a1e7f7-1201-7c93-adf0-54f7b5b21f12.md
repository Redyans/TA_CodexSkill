可以。你不需要负责合并所有人的代码，但前提是不要把个人开发直接放在公共 `master` 上。

Git 的限制是这样的：

```text
远端 master：A ─ B ─ C       其他人的提交
本地 master：A ─ X           你的提交
```

如果你要直接把 `X` 推到远端 `master`，远端要求最终历史同时包含 `B、C、X`，所以必须先整合。整合方式可以是：

- merge
- rebase
- 由其他负责人通过 PR 合并

不能直接“只推我的 X、忽略 B 和 C”，除非强制推送覆盖远端历史，这会让别人的提交从 `master` 上消失，不能这么做。

你后面应该使用个人分支：

```text
master
  ├─ 其他人的提交
  └─ feature/lyj-1008716
       └─ 你的提交
```

提交时只提交自己的文件，然后：

```powershell
git push -u origin feature/lyj-1008716
```

之后由负责人或 PR 流程合并到 `master`。这样你不需要自己把所有人的修改 merge 到本地。

git config --local pull.ff only
